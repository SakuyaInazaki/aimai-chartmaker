## 0. 一句话结论

> **⚠️ 2026-09-20：本节用的 `全采 / 半采 / 稀采(空音)` 是旧的 agent 类名。**
> 三词口径（采全音 / 半采音 / 空音）下这条结论**原样成立**，数字见 §10.3：
> 去环硬度低→高，**半采音 22.0%→29.2%、空音 7.7%→9.8%、采全音 59.9%→55.8%，
> coverage 0.698→0.665**。

**官方谱不是"越难的地方踩得越满"，而是"越难的地方踩得越省"。** 去掉循环论证后，配置硬度从低档到高档，`半采` 从 9.6% 升到 **18.8%**、`全采` 从 36.6% **降**到 30.2%、`稀采/空音` 从 5.8% 升到 9.0%，而 coverage（骨架轨的音被踩了多少）几乎不动（0.702 → 0.673）。也就是说：**硬配置是用"同样多的音、更狠的摆位"换来的，不是用"更多的音"换来的**——这一点与知识 031「强度 ≠ 密度」同构，但把它推进到了"强度 ≠ 采音密度"。

同时有三条更硬的分布规律可以直接给 LLM 用：

1. **段落决定硬度档**：ドロップ 0.615 / ラスサビ 0.613 / サビ 0.588 ≫ Bメロ 0.452 / イントロ 0.381（曲内归一硬度均值）；高硬度小节在 ラスサビ 的富集倍数 1.47、ドロップ 1.39、サビ 1.30，在 イントロ 只有 **0.52**。
2. **几何配置和交互配置分居两地**：大宇宙 / 逆楼梯（方向盘）/ 楼梯 / 三角 / 轴交互在 **ドロップ与間奏** 富集（lift 1.8–3.5），在 サビ 一律低于 1.0；サビ 里富集的是 **侧边双押 1.51 / 单双双单 1.38 / 连续双押 1.21 / 错位 1.17**。**纵连（尤其是长纵连）住在イントロ**（长纵连 lift **3.16**）。
3. **采音模式主要由"音轨密度 ÷ 谱面密度"决定，不由强度决定**（以下均为曲内逐小节 Spearman 的 Fisher 均值）：ρ(谱面 note/小节, coverage) = **0.437**，而 ρ(音频强度, coverage) 只有 **0.056**、ρ(硬度, coverage) 只有 **0.099**。低 BPM 曲天然是稀采（BPM<150 的 39 首曲级 coverage 0.614 vs BPM≥190 的 44 首 0.705）。

## 1. 方法与操作化定义

### 1.1 数据与对齐口径

与 `audio-chart-calibration-n160.md` 完全一致，不另起炉灶：

- 官方 note 绝对时间 = `&first + note.time + φ`，φ 为全局相位扫描最优值（`stemhit.best_shift`，扫描 ±45 ms / 步长 2.5 ms），`|φ*| ≤ 10 ms` 时不补偿；
- **官方时间槽**：同刻的 each / 双押算**一个采音事件**（`stemhit.unique_times`，1 ms 合并）；
- 谱面小节 ↔ 音频小节按"起始秒最近且 ≤50 ms"匹配（`chartpair.map_measures_to_bars`）；
- stem onset 用 `tools/audio_analysis/onsets.detect_onsets` 重跑（纯 DSP、与管线同参），四路 + `piano`（知识 032 确认的第二有效踩音轨）。

新增的轻量装载路径 `sampling.load_pair()` **不解码 track.mp3、不重算强度曲线**（这两件事占装载耗时九成，采音分析用不到），160 首全量跑完 **7 秒**。

### 1.2 配置识别器 `tools/chart_analysis/configs.py`

**定义一律取自 `.agent/knowledge/` 017–030**（用户逐条讲授 + 官谱实证），本模块只做"把文字定义变成可执行判据"这一层。⚠️ 这一层（窗口长度、匀拍容差、环形跨度上限、各项权重）**是 agent 的操作化，不是知识条目原文**；参数集中在 `PARAMS` / `CONFIG_WEIGHT`，可整体替换。

覆盖 17 类（含子型）：

| 配置 | 知识 | 操作化判据（要点） |
|---|---|---|
| 错位 | 017 | 星星头与启动拍之间（**开区间**）存在其他时间槽；"双手同刻同任务"（两条滑轨同起 + 间隙音也是双押）按 017 的边界排除 |
| 普通交互 | 018 | 匀拍单点段 ≥6 槽、无同键 ≥3 连、星星槽 ≤1/4（018 的基础形是 tap） |
| 纵连 / 长纵连 | 019 | 同键连续 ≥3（>5 为长）；同键**星星串**不算（纵连的难点是拆着敲同一个键） |
| 三角交互 | 020 | 匀拍**纯 tap** 段按 3 个一组，组内键集 2–3 个、环上跨度 ≤3、**必须转向**（排除单向音阶），相邻组键集不相交，≥2 组；每段只取链最长的切分偏移 |
| 轴交互 | 021 | 轴音**隔位**重复（B,A,B,C,B…）≥5 槽，另一手 ≥2 个不同键——直接用知识 021 给的"识别方法" |
| 楼梯交互 | 022 | 成对推进、每步 ±1、**两手反向**且不构成 180° 对位，≥3 对；折叠"每对重复两次"的写法 |
| 逆楼梯/方向盘 | 023 | 成对推进、每步 ±1、**两手同向**且**每对始终 180° 对位**，≥3 对；另报是否折返 |
| 大宇宙 | 024 | 奇/偶位各落在一对**环上相邻**键、两对不相交、两边都真的在横跳，≥8 槽 |
| 散点 | 025 | 匀拍**纯单点**（无星星/长条，按 025 原文）≥8 槽、用键 ≥5、非零步进幅度 ≥3 种，且不与 019–024 任一命中重叠 |
| 跳拍 | 026 | **粗判**：小节内 ≥5 音、间隔倍数 ≤3 且 ≥2 种、二值化后交替段数 ≥4（反复插空而不是一处留白） |
| 定拍 | 027 | 某键在**等间隔** ≥8 槽上出现；另一手 ≥3 音；且"与定拍手同刻"或"另一手会歇"（027 给的与轴交互的区别点） |
| 子弹 | 028 | 同键相邻两槽（**恰好两次**，≥3 归纵连）间隔 ≤半拍且两槽都无星星；或短双押串 `AB,AB`（≥3 归双押纵） |
| 单双/双单 | 029 | 单(S)/双(D) 串出现周期 2 或 3 的完整循环 ≥2 次 |
| 连续双押 / 双押纵 | 030 | 连续 ≥3 个双押；键集全同 → 双押纵；逐步共享键 → 绕圈 |
| 侧边双押 | 030 铁律 | 双押键集恰为 {2,3} 或 {6,7}；"引导"用**前后 ±4 槽内是否出现同键音**代理 ⚠️（代理沿用 `config-usage-survey.md`，**未经用户确认**） |

### 1.3 配置硬度分（逐小节）

五项加权和，权重与各项口径写在 `bar_hardness()` 的 docstring 里：

```
raw = 0.22·K + 0.22·M + 0.26·V + 0.10·U + 0.20·C
```

- **K（note 种类，知识 003-1）**：小节内 note 平均加权值（tap 1.0 / hold 1.2 / 滑轨 1.5 / touch 0.8；break +0.3；each +0.2），线性压到 [0,1]；命中 `错位` 再 +0.25（003 说错位是同踩音同键位下最强的星星用法）。
- **M（位移，知识 003-2）**：`相邻槽位移` 与 `隔一槽（同一只手）位移` 的均值 ÷ 4（环上最大位移）。⚠️ "同一只手 = 隔一个音"是**交替手序的代理**，不是真实手序。
- **V（速度，知识 015/018）**：`NPS = 时间槽数 / 小节秒长`，除以短爆发红线 22.2 键/秒后截断。BPM 与分音的联动已经含在 NPS 里，所以知识 003-3 的 BPM 因素不再单列。
- **U（无理，知识 008/009/010/011）**：小节内叠键（同键 <33.3 ms）/ 外键（启动后 200 ms 内同侧 tap，环距 ≤1）/ 撞尾（终点键在结束 −50 ~ +200 ms 内）代理事件数 ÷ 3。
- **C（配置，知识 017–030）**：覆盖该小节的配置里 `CONFIG_WEIGHT` 的最大值（大宇宙 1.00 / 错位 0.90 / 双押纵 0.90 / 方向盘 0.85 / 连续双押 0.80 / 散点 0.80 / 长纵连 0.75 / 楼梯 0.70 / 三角 0.70 / 定拍 0.65 / 轴 0.60 / 单双 0.60 / 跳拍 0.50 / 纵连 0.50 / 普通交互 0.45 / 子弹 0.40）。**这组数值是 agent 设定**——知识 003 只给了定性顺序。

`hardness_bar` = 曲内有 note 小节上的 min-max 归一；`hardness_class` = 曲内三分位（低/中/高）。

> ⚠️ **循环论证告警**：C 项把"命中什么配置"喂进了硬度分，所以"某配置在高硬度档富集"会自我实现。本报告凡涉及**配置 × 硬度**与**采音模式 × 硬度**的结论，一律**另给一份去掉 C 项（权重重新归一）的版本**，并以去环版本为准。

### 1.4 采音模式的操作化定义 ⚠️

**官方/社区没有"采全音 / 半采音 / 空音"的成文判据。** 以下是 agent 为了能计算而定的操作化，阈值可调、并在 §7 做了敏感性分析。
**（2026-09-20 修正：原文这里写的是"请用户按 §4.8 的谱例校正术语"——**这条作废**。
采音方式是谱师的定性判断，切点是工具内部的诊断口径，不拿去问用户；见 §10。）**

逐小节，相对**骨架轨**（见下）：

- `pool` = 骨架轨在该小节的 onset，按 2τ = 60 ms 合并去重；
- `hit` = pool 中被官方时间槽 ±30 ms 覆盖的个数；`coverage = hit / |pool|`（= `stemhit` 口径的 precision，"音轨的音被踩了多少"）；
- `extra` = 官方时间槽中**五条轨（drums/bass/other/vocals/piano）都覆盖不到**的个数；`extra_ratio = extra / 官方槽数`；
- `alt_pattern` = 三条判据任一成立：①被踩中的 pool 下标构成等差为 2 的序列（≥3 个，"隔一个"）；②官方槽全落在 0.5 拍整数倍上而 pool 有落在半拍之间的（"只踩强拍"）；③谱面该小节最细分音 = 音频该小节量化分音的一半（"分音减半"）；
- `rest_beats` = 小节内最长的"官方无音但 pool 有音"的区间（拍）；
- `density_ratio` = 官方槽数 / pool 大小。

判定顺序（先判的优先）：

| 模式 | 判据 |
|---|---|
| `静默` | 官方时间槽 ≤ 1 |
| `加花` | `extra_ratio ≥ 0.50` |
| `全采` | `coverage ≥ 0.80` 且 `extra_ratio < 0.30` |
| `半采` | `0.35 ≤ coverage ≤ 0.65` 且 `alt_pattern` 成立 |
| `稀采/空音` | `coverage < 0.35`（且 pool ≥ 2） |
| `混合` | 其余 |

**骨架轨**：逐小节按 `lift` 最高选（与标定报告 §5 的归因口径一致），带两道稳态闸门——①官方槽 <3 或该轨 onset <3 时回落到**该段落的骨架轨**；②最高 lift 需超过段落骨架 lift 的 **1.25 倍**才换轨。没有这两道闸门，逐小节 argmax 会一节一换、纯噪声（实测在 Death Scythe 上会在 drums/bass/piano/vocals 之间每小节乱跳）。结果分布：drums 8 811 / other 1 419 / vocals 1 331 / piano 1 115 / bass 859 小节（drums 占 65.1%，与知识 032「鼓骨架」一致）。另算了一份 **drums 固定**的版本做敏感性。

| 6 | 跳拍把"8 分块接 16 分块"的密度变化当跳拍 | 倍数 `[2,2,2,1,1,2,2,2]` | 要求二值化后**交替段数 ≥4**（反复插空，而不是一处切换） |
| 7 | 普通交互 / 纵连把**星星串**算进去 | `8b-6,8b-3,8b-4,8b` 判为纵连 | 星星槽占比超过 1/4（交互）/ 1/3（纵连）即排除 |

修正后三首的命中量：SPICY 51 段、Death Scythe 101 段、幻想のサテライト 135 段（修正前分别是 59 / 161 / 145）。

### 2.3 检测器的已知薄弱点

- **错位命中率高（全库 18.6% 的小节）**：这是定义本身的后果——只要滑条的一拍启动窗口里有别的音就算。抽 40 首复核：**91.0% 的错位片段间隙里恰好 1 个音、97.3% 的间隙音是单点**，正是知识 017 的典型形态，所以不是检测器松，而是官方谱真的到处在用。但高密度段里"间隙必有音"接近自动成立，**在 16 分以上的密集段应当把错位看成背景而不是特征**。
- **跳拍只做粗判**（知识 026 本身是概念记录、用户明说待补充），本报告的结论不以跳拍为据。
- **侧边双押的"引导"判据是未确认代理**：本轮 40 首抽样里 **95.1%** 的侧边双押前后 ±4 槽内有同键音；`config-usage-survey.md` 用 ±2 槽得到 56%。窗口一换数字就翻倍——**这说明"引导"根本没被这个代理抓住**，需要用户给判据。
- **正三角 / 反三角不判**（知识 020 明说区分依据目前只有手感）。
- **手序是代理**：位移项里"同一只手 = 隔一个音"假设严格交替手序，对定拍 / 纵连这类非交替配置不成立。

## 3. 配置硬度 vs 强度 / 段落 / 位置

### 3.1 硬度与强度的相关只有中等，而且是**段落级**现象

| 口径 | Spearman（曲内，Fisher 均值） | 中位 |
|---|---|---|
| 逐小节 ρ(强度 I_bar, 硬度) | **0.291** | 0.297 |
| 逐小节 ρ(强度, 官方 note/小节) | 0.328 | 0.323 |
| 逐小节 ρ(硬度, 密度) | 0.518 | — |
| 逐小节 ρ(强度, 硬度**去掉配置项**) | 0.233 | 0.261 |
| **逐段落均值** ρ(强度, 硬度) | **0.641** | 0.499 |

160 曲里 **88%** 的曲子 ρ(强度, 硬度) > 0。分层：器乐 0.342 > 人声 0.267（与 n=160 标定的 0.42/0.28 同向）；六曲风 0.169（POPS＆アニメ，n=11）~ 0.372（オンゲキ＆CHUNITHM，n=13）。

硬度五个分项各自与强度的曲内 ρ：速度 0.245 ≈ 配置 0.244 > 无理 0.151 ≈ 位移 0.143 ≫ note 种类 0.084。**音乐强度主要通过"写得更快"和"换更狠的配置"传导，几乎不通过"换 note 种类"传导。**

> **读法**：把硬度往**逐小节**的强度曲线上贴是贴不准的（ρ≈0.29，和密度差不多）；但**段落均值**层面贴得住（ρ≈0.64）。这与知识 031「强度 ≠ 密度、结构决定基线」完全同构——**强度曲线只配用来定"段落的档位"，不配用来定"每一小节写多难"**。

### 4.7 采音度量到底被什么驱动（曲内逐小节 Spearman，Fisher 均值，n=160）

| 被解释量 ↓ / 解释量 → | 配置硬度 | 音频强度 I_bar | 官方 note/小节 |
|---|---:|---:|---:|
| coverage | 0.099 | 0.056 | **0.437** |
| extra_ratio | −0.004 | −0.064 | **0.259** |
| rest_beats（最长留白） | −0.030 | 0.005 | **−0.353** |
| density_ratio（官方槽/pool） | 0.073 | 0.017 | **0.461** |

**四行的结论是同一条**：采音形态几乎完全由"这一小节谱面写了多少音"决定，与音频强度、与配置硬度都基本无关（|ρ| ≤ 0.10）。配合曲级口径 ρ(BPM, pool/小节) = **−0.653**（BPM 越高、每小节的音轨 onset 越少）与 ρ(BPM, 曲级 coverage) = +0.272，可以把采音模式的成因写成一句机械关系：

> **采音模式 ≈ f(谱面密度 ÷ 音轨密度)**，而谱面密度由定数与段落决定、音轨密度由 BPM 与编曲决定。
> 「全采 / 半采 / 空音」与其说是谱师的主动选择，不如说是"定数给的音符预算"除以"音乐给的音符数量"之后**落在哪一档**。
> 谱师真正的主动选择体现在 `alt_pattern`（半采时是隔一个踩还是只踩强拍）与 `extra`（加不加花）上。

## 7. 对照与敏感性

### 7.1 随机平移对照（假骨架）

把**每条 stem 的 onset 整体循环平移**一个随机量（`[0.1·曲长, 0.9·曲长]` 均匀，各轨独立，曲长上回绕）。这样 onset 的**密度与节奏纹理完全保留**，只有"和谱面的对齐关系"被打断。

| | 全采 | 半采 | 稀采/空音 | 加花 | 静默 | 混合 | coverage 均 | coverage 中位 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 实测 | 33.4% | 13.9% | 7.2% | 6.5% | 5.4% | 33.7% | **0.687** | 0.727 |
| 对照 | **7.2%** | 10.5% | 9.8% | **45.8%** | 5.4% | 21.2% | **0.422** | 0.400 |

**对照通过**：`全采` 从 33.4% 塌到 7.2%，`加花` 从 6.5% 爆到 45.8%，coverage 掉 0.265。模式分布不是密度伪影。

⚠️ 但要注意对照的**残余 coverage 0.422 相当高**——纯随机对齐都能"踩中"四成。这来自两点：①鼓 onset 本来就密（每小节 8–14 个），±30 ms 窗口在高密度下容易撞上；②官方槽与 onset 都被量化到同一套拍网格上，随机平移不会破坏"都在网格上"这件事。**所以 coverage 的绝对值不能当作"采音准确度"读，只能做相对比较。**

### 7.2 阈值敏感性

| 变体 | 全采 | 半采 | 稀采/空音 | 加花 | 静默 | 混合 |
|---|---:|---:|---:|---:|---:|---:|

drums 固定 vs 逐小节选骨架：`全采` 21.7% vs 33.4%、`稀采` 15.1% vs 7.2%。**骨架轨一换，绝对占比就换一半**；§4.2–4.5 的各表已用同一口径（逐小节选骨架）做横向比较，结论不受影响，但**不要把 33.4% 这个数当绝对事实**。

## 10. 局限（哪些环节仍不可靠）

1. **"采全音 / 半采音 / 空音"这三个词是用户的，但"哪一小节算哪个词"的切点是 agent 造的**。本报告只能给一套可计算的近似，占比数字对切点敏感（旧口径下"全采"在 19.9%–43.0% 之间漂）。
   （**2026-09-20 修正**：原文后面还有一句"§4.8 的谱例就是请用户校正术语用的"——**作废**。
   切点是**工具内部的诊断口径**，不向用户索取；本报告此前另造的 `近全采 / 随机半采 / 加花 /
   静默 / 混合` 五个类名也已整体删除，见 §10。）
2. **coverage 的绝对值不可读**：随机对照都能拿到 0.422，因为鼓 onset 本身密 + 双方都在同一套拍网格上。只能做相对比较。
3. **骨架轨口径一换，绝对占比就换一半**（drums 固定 vs 逐小节选）。逐小节选骨架虽然加了两道闸门，仍是 lift 驱动的弱判据。
4. **人声侧继续不可信**：知识 002 第三轮修订抓到的失败模式（Demucs vocals 轨混 lead synth）在本报告同样存在——vocals 作骨架的 1 331 个小节里有多少是假的，本报告没有办法判。
5. **`extra`（加花）三义混淆**：自由发挥 / 装饰音 / onset 漏检无法区分。World Vanquisher 的 extra 0.336 很可能主要是合成器持续音的漏检，而不是谱师在加花。
6. **硬度分量不到"读谱与手型"**：这是最大的结构性盲区。散点（知识 025 明说难度来自读谱与预判）、大宇宙、方向盘去环后都落在中低档，与谱师直觉相反。要补这一维需要新的特征（手型切换代价、图形可读性），本轮没做。
7. **硬度分的"手序"是代理**：位移项假设严格交替手序，对定拍/纵连不成立。
8. **循环论证只在硬度分里破掉了，没在配置识别里破**：`CONFIG_WEIGHT` 的排序本身来自知识 003/008 的定性描述，是主观的。
9. **错位在高密度段接近自动成立**（18.6% 小节命中），应当当背景看。
10. **侧边双押的"引导"判据仍然没有**：±2 槽 → 56%（旧扫描）、±4 槽 → 95%，窗口一换数字翻倍，说明代理没抓住用户说的"引导"。
11. **跳拍只有粗判**（知识 026 本身待补充），所有结论都没有以它为据。
12. **`Bメロ`(n=360)、`アウトロ`(n=51)、`ブリッジ`(n=18) 样本太小**，相应行只能当提示。
13. **段落标签本身是管线产物**（三路投票 + 日式词表），没有人工听审复核；段落级结论继承了分段的误差。
14. **本报告只覆盖 ST 谱、定数 13.0–14.5**，不能外推到 DX 谱或其他定数段。

## 10.1 三个词的定义（用户原话 + 主会话的白话解释）

用户原话：「它们都是怎么采的音，是**采全音**、**空音**还是**半采音**等等」。

| 词 | 说的是什么 |
|---|---|
| **采全音** | 把这段音轨的音**基本都踩了** |
| **半采音** | **有选择地只踩一部分**（隔一个、只踩重音之类都算） |
| **空音** | **该有音的地方留白不踩** |
| `—` | 这一小节音轨本来就没发出几个音，**没有依据、不下结论**（不是一类采音方式） |

**删掉的 agent 自造类名**：`近全采`、`随机半采`、`稀采/空音`、`加花`、`静默`、`混合`。
其中：
- `近全采` 是为了绕开"踩七成算不算全采"而造的——现在并入**采全音**；
- `半采` / `随机半采` 的区别（踩的是不是重音）降为 `accent` **诊断标记**，两者都是**半采音**；
- `加花`（谱面写了哪条轨都没有的音）降为 `extra_ratio` 诊断字段，**不再撑起一个类名**；
- `静默`（谱面几乎不写音）本来就是"该有音的地方留白不踩"，并入**空音**；
- `混合` 是残差桶，改成 `—`（不下结论）。

> ⚠️ **工具内部仍然要有一个 coverage 切点**才能把连续量落到三个词上
> （`THRESHOLDS["full_lo"] / ["empty_hi"]`）。那是**诊断口径，不是术语定义**，
> **不向用户索取、不列为待裁定项、不写进知识库**。

> 「官方谱不是"越难的地方踩得越满"，而是"越难的地方踩得越省"。」**

> 硬配置是用"同样多的音、更狠的摆位"换来的，不是用"更多的音"换来的。

**否定结论也复现**：半采音里"踩的是重音"的比例**不随硬度上升**——低 65.1% / 中 65.5% / 高 65.3%。
所以**不能说"难的地方谱师更讲究踩重音"**。

## 10.5 草案 033 的改写版（**仍不写入** `.agent/knowledge/`）

### 草案 033（改写） — 采音方式：采全音 / 半采音 / 空音

- **日期**：2026-09-19 立，**2026-09-20 按用户术语改写**
- **要点**：官方谱对目标音轨的采音，用谱师的三个词说就是**采全音 / 半采音 / 空音**。
  三者在官方谱里的关系是：**默认采全音**（约六成小节），
  **越难的地方越往半采音和空音走**（去环硬度低→高：半采音 22.0%→29.2%、空音 7.7%→9.8%、
  采全音 59.9%→55.8%），**但踩的音总量几乎不变**——省的是"踩满"，不是"踩多少"。
- **详情**：
  - **半采音的成因是机械的**：一只手被星星 / 长条钉住时，另一只手只能挑着踩。
    半采音占比最高的十几类配置全是这种形态（拆弹、同起点拍滑、一笔画、双压连续拍滑、
    出张、连续拍滑、井字星星、定拍、绕圈星星、鼓动段、三叉戟、穿心、错位、挥手段）；
    反过来手型预定的几何配置（三角 / 楼梯 / 散点 / 轴 / 普通交互）几乎全是采全音。
  - **"半采音要挑重音"是真的但幅度小，而且不随难度变化**：半采音小节里踩的是重音的约 65%，
    随机平移对照 58%；低 / 中 / 高硬度档分别是 65.1% / 65.5% / 65.3%——
    **不能说"难的地方更讲究踩重音"**。
  - **采什么方式主要由"音轨密度 ÷ 谱面密度"决定，不由音乐强度决定**（§4.7 的相关系数未变）。
  - **段落**：ドロップ 最爱采全音（70.9%）；サビ 的半采音最高（27.6%）与空音最高（10.1%）；
    間奏 采全音 64.5%；イントロ / Bメロ 判不出的比例最高（14.8% / 14.2%，音轨本身就空）。
- **理由**：160 首官方音频 × 官方谱逐小节实测（13 535 小节 / join 后 13 313 小节）；
  随机平移对照下 coverage 从 0.687 掉到 0.422，分布不是密度伪影。
- **来源**：本报告 §10；工具 `tools/calibration/sampling.py`。
- **置信度**：**经验**（分布与相对趋势，n=160，对照通过）/
  **存疑**（三个词是用户的，但"哪一小节算哪个词"的切点是 agent 的**内部诊断口径**，
  用户未确认；切点一动占比会变，见 §7.2 的敏感性）。
- **关联**：知识 002（切轨）、005（采音要简）、031、032。

> **入库状态（2026-09-20）**：本节草案 033（改写版）的**社区术语版**（§11.4）
> **已入库为知识 068**；三词的社区来源与"空音是反义词"另立为知识 **081**。
> 本节保留作过程记录。见 `.agent/notes/058`。

## 10.6 本节的局限

1. **三个词之间的界线仍由一个 coverage 切点决定**，那是 agent 的内部口径。
   它影响的是"某一小节算哪个词"，**不影响**上面那些**相对趋势**（低→高硬度的方向）。
2. 判不出（`—`）占 8.1%，主要落在音轨本身很空的 イントロ / Bメロ；
   它们**不该被强行塞进三个词里**。
3. 采音侧的其余局限（§1.4 / §8.6 / §9.6）一条未变。

## 11.2 为什么「空音」必须换掉（不只是换个说法）

社区的「**（采/插）空音**」是**反义词**：

- 萌娘百科《音乐游戏/用语》：「指原本音乐中并没有音的地方却在谱面的对应位置塞入了音符的情况」；
- Deemo 谱评（cv1359970）：「只要有一处（一类）明显 **zure/空音**就直接乘以 70%」。

即社区的空音 = 谱面**多**写了音；用户的空音 = 谱面**少**写了音。
本报告若继续用「空音」，社区读者读到的结论会**正好相反**。
（顺带：本工具的 `extra` 字段量的才是社区的采空音。）

## 11.3 「舍音」不是完美对应——三条诚实边界

1. **社区没有把「全踩 / 舍音 / 留白」当成一组互斥分类。**「全踩」描述一段跟定一条轨，
   「舍音」描述一张谱的取舍基调，「留白」描述某几小节。
   **把连续的 `coverage` 切成三档，仍然是本工具的操作化**，不是社区术语定义。
2. **切点没有动**（`THRESHOLDS["full_lo"]=0.65` / `["empty_hi"]=0.35`），
   §7.2 的阈值敏感性一条未变；换词**不**把"踩七成算不算全踩"这种量化问题变成可问的问题。
3. **「舍音」与「留白」在社区里本来就是同一件事的不同程度**（少采一点 vs 干脆不采），
   本工具靠一个切点把它们分开。读 §10.3 的"舍音与留白一起上升"时要记住这一层。

另外，**「全踩」在本轮 47 篇 B 站语料里 0 命中**，只在 MMFC 手册里出现（2 处）——
它是**手册用语**，口头行话程度不确定。详见调研报告 §5。
