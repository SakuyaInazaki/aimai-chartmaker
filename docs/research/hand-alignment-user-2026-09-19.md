## 2. 侧边双押红线的改写草案（可机检）

用户原话把「突然」与「引导」都定义了（知识 030 补充）。拟成规则：

```
对每一组侧边双押 D（两手键集合 == {2,3} 或 {6,7}）：
  guided(D) = A ∨ B ∨ C
    A. 双押带过来：D 之前连续 ≥N 组双押，且把两手带到 D 的两个键上   ← 形态待用户补（见 §4-1）
    B. 共享键行走：与前一组双押共享一个键，另一键环距步进 ±1        ← 用户例 18/87/76/65/54
    C. 规则轮转　：前后各组均为「相邻键对」，且整体按固定步长绕环     ← 用户例 18/23/45/67
  sudden(D) = ① 与谱面临近位置位移较大（阈值待标定）
            ∨ ② 与上一个配置的间隔过小（阈值待标定）
  红线(D) = sudden(D) ∧ ¬guided(D)
```

- 与旧规则的差别：旧规则把「**是不是侧边双押**」当红线主语、引导当例外；用户口径是「**突然**」才是红线主语——**侧边双押本身不是禁区**。
- 用户的 B、C 两个例子里都**包含**侧边双押（B 含 7/6、C 含 2/3 与 6/7），它们是**可以写的**。
- 两个「突然」阈值（位移、间隔）用户未给数 → **agent 操作化**，须先在 388 官谱上跑分布。
- 附带收获（agent 解读，待用户确认）：按 064 的舒适区，`2/3` 与 `6/7` 恰好是**必定产生出张**的两组相邻双押
  （`1/8`、`4/5` 两键都在共享区；`1/2`、`3/4` 等各有一键在共享区）。若成立，**侧边双押红线与出张代价是同一个机制的两层**，
  实现上可以让红线复用 §1 的 `w_chuzhang` 判据。

## 3. 必须重跑的验证

改动横跨分页先验、S/H 两项与纵连拆手判据，**§3 的权重一动，下面全部结论都要重算**：

1. **388 谱基线**（`docs/research/hand-assignment-validation.md` §2）：绝对/硬无理、占用冲突、`scrape` 分类明细。
   ⚠️ 重点盯 §3.5 残留的 136 次占用冲突与 §3.3 的「换手拧巴 18」——S/H 撤销后两手的落点分布会变。
2. **定式复现**（§4 的 017–036 共 18 条 + §4.1 星星篇 9 条）。
   ⚠️ 受影响最大的是 **049/050/053/062**（骨架建立在「拍头手＝划轨手」上）与 **057 一笔画**（免除 S/H 的写法失效）。
   062 在旧模型里本来就「把部分轨道换了手」（§5 判别力对照），新口径下这**不再算偏差**。
3. **出张统计**：新旧口径**并列输出一轮**（旧＝末尾半边冲突数、新＝064 键位定义），给用户看差多少；
   验证报告 §9 草案 B 里「每条 slide 平均 0.431 次出张」这一句**必须替换**。
4. **`configs_hand.py` 与三张表**（note 053 在飞）：采音 × 配置 / 配置画像 / 定数 × BPM——三张表都吃 `hands.assign()` 的输出。
5. **§7.2 各配置的平均手序难度排序**（曲内归一）与 §7.1 的正交性结论（ρ = 0.103 / 0.180）：权重一改必变，
   其中「侧边双押 0.515 最费手序」这一条正好可以拿来对照 §2 的新红线是否还自洽。
6. **§6 起手奇偶实验**：旧结论「两种起手全谱代价差中位数 0.08%」建立在「段边界会被分页先验重新锚定」上，
   改舒适区模型（共享区变大、锚定变弱）后须重测。

## 4. 待用户确认（归类时遇到的疑问）

1. **「像你之前说的双押带过来」指哪一条**——这句引用的是同轮对话里主会话此前的说法，**原话不在本次入库材料内**，
   无法编码成 §2 的 A 型判据。
2. **「稍快」的上界**（知识 019 补充）：长度 ≤3 的纵连可以单手，但「稍快」到什么 BPM / 分音为止没有依据；
   目前只能靠知识 009 的绝对下界（33.3 ms）兜底。
3. **出张代价是不是只有一档**：用户只说「轻易不要写」，没说代价是否随跨得多深（6 vs 7）、多久、多频繁而变化。
4. **「突然」的两个阈值**（位移大 / 间隔小）没有数值。
5. **065 是否意味着知识 007 的「末尾半边」完全作废**，还是仍可作弱偏好（本文按「撤销或极小 tie-breaker」写，取后者为保守）。
6. **067 与 060 的层级关系**：060 说「相反起手能规避出张」（段内奇偶），067 说「先出手＝离上一段结束近的手」（段间连续）；
   若二者冲突（离得近的手起手反而制造出张），用户未给裁定。
7. **纵连的「3 个 tap 或以内」**是否也适用于同键连打里混入 hold / 星星头的情形。
