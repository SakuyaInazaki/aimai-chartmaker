## 2.3 检查器迭代日志

| 轮 | 检查器报了什么 | 怎么修 |
|---|---|---|
| **1** | **4 条错误**：`PLAY-INFEASIBLE` + `PLAY-MULTI` 各 2，`m040` 与 `m074`「同刻 3 个需处理对象」 | 病因是**连续拍滑链跨小节线**：`m039`/`m073` 末尾那根 slide 的头落在小节第 7 槽，启动拍落到**下一小节第 0 槽**，而下一小节第 0 槽我写了 `1/8` 双押 → 划轨 + 两个 tap = 三手。改法：把链的最后一根去掉、只留启动拍 tap（`…,7/2-5[8:1],,2,,`），让整条链在本小节内收完 |
| **2** | 0 错误，但四条提示刺眼：① 配置 **20 类 / 主料 13 类**（官谱 40 类透镜中位 15 / 主料 4，知识 073）；② 几何族被写成主料（073：几何只作点缀）；③ 缺 **跳拍**（官谱 93.8% 有）；④ 密度五段形状 `[0.36, 0.78, 1.00, 0.63, 0.96]` 对 `T_density [0.62,…]` 第一段差 −0.26（前奏太空，违反知识 031 §2 密度地板） | 把 `{12}` 三角交互两小节与 16 分大宇宙一小节**换成已经在用的轴交互 / 楼梯**（知识 071：升档是「加每类时长」不是「加种类」）；`m013`/`m017` 改写成不规则空拍的**跳拍**；`m001–m008` 前奏整体加密（2→5 note/小节起步） |
| **3** | 0 错误。密度形状修好了（`[0.51, 0.87, 0.63, 1.00, 0.76]`，逐段差 ≤ 0.22），但**出张掉到 0、侧边双押掉到 0** | 发现关键事实：**出张不是「写出来」的，是被「逼出来」的**——分配器按代价最小选手序，只要两只手都够得着，它永远不会主动跨界。加了两处：`m042`/`m076` 用用户原话里的 **C 型等距轮转 `18/23/45/67`**（知识 030）写侧边双押（它按 064 的交叉推论必然带出张）；`m049`/`m061` 用长条钉住一只手（知识 087 类 2） |
| **4** | 0 错误，出张只出来 4 处 —— `m049`/`m061` 的长条**没有逼出出张** | 因为我把长条写在了**共享键**（`1h` / `8h`）上，分配器直接把它交给「闲着的那只手」。改写到**专属键**：`3h[8:5]`（右手专属）→ 左手只能去打 2；`6h[8:5]`（左手专属）→ 右手只能去打 7 |
| **5** | **0 错误 / 0 警告 / 37 提示**，出张 6 处（8.3 ‰）、侧边双押 4 处（引导全部判得出：C / F1 / F2 / E 型）、绝对与硬无理均为 0、软级蹭 0 | 定稿 |

> 五轮里检查器真正**拦下错误**只有第 1 轮那一处（跨小节线的拍滑链）。其余四轮全是**提示层**在起作用——
> 提示不判对错，但它把「我以为写到了、其实没写到」的四件事（配置太散 / 缺跳拍 / 前奏太空 / 出张为 0）
> 摆到了台面上。**这是本轮工具侧最有价值的部分。**

| 落ちサビ 43–56 | 0.86 / 0.21 | 0.64 / 0.44 |
| 落ちサビ 57–68 | 0.78 / 0.31 | 0.67 / 0.30 |
| サビ 69–76 | **0.88** / 0.28 | **0.59** / 0.42 |
| 間奏 77–84 | **0.95** / 0.28 | 0.67 / 0.12 |

**我全程踩满鼓轨（79% 的小节判成「全踩」），官谱只有 44%。**
差得最狠的是 **Aメロ 27–34（0.88 vs 0.38）与 サビ 35–42（0.90 vs 0.48）**——
官谱在这两段**大面积舍掉鼓**，改跟别的东西（对应 §3.2 里那些 hold 与 slide）。
这正是知识 068「越难的段落越往舍音和留白走，而踩下去的音总量几乎不变」的样子：
官谱 サビ 的 note 数和我一样（88 vs 89），但它**只用了一半的鼓点**，剩下的 note 花在星星与双押上。

## 4. 认识缺口清单

> 三类：**(A) 知识库回答不了**、**(B) 回答了但我写出来不对**、**(C) 工具报不出来**。

### G1（A+B）「这一段该写星星还是写单点」，知识库没有可执行的回答

- 知识 017–063 给了每一类配置**是什么**、070/071/073/074 给了**什么时候多用一点**，
  但**没有任何一条回答「这一段的 note 里该有多大比例是 slide / hold」**。
- 结果：我写了 6.0% slide + 0.5% hold，官谱是 17.1% + 5.3%。**差了三倍**，
  而检查器的四层都没有任何一条提示指向它（密度层只数 note 总数与 NPS）。
- 知识 070 甚至指向反方向：「升定数时 each / slide 占比**反降**」——这句是**跨谱统计**
  （高定数谱的 slide 占比低于低定数谱），我把它读成了「写谱时少写 slide」。

### G2（A+B）段落标签当处方用会写坏，但知识库没说它是分布

- 知识 074 的 lift 是 160 首**平均**；这一首的 イントロ 是星星族、間奏 是星星族，
  两处都和 074 相反。我按 074 写了纵连前奏与几何间奏。
- 更硬的一处：管线把 43–68 标成 **落ちサビ + `rest ✅`**，我照着写成减压段（6.7 note/小节），
  官谱那里是 **11.1 note/小节**（跟副歌一样）。**「rest」这个字段直接把我带沟里了。**

### G3（A+B）出张 / 侧边双押 / 蹭，写谱时「想写也写不出来」

- **出张不是写出来的，是逼出来的**：分配器按代价最小选手序，两只手都够得着时它绝不跨界。
  我前三轮写的「对称模板 `45,,45,,2,3,2`」（知识 087 §5 的原话）**一个出张都没产生**——
  因为那形状里两只手都够得着。真正生效的只有两招：**长条/星星钉住专属键**、**侧边双押**。
- 知识 087 说「纯单点出张占三成、是最大的一类」，但那三成在**官谱既有手序**下成立；
  **写谱端没有办法「指定」这三成**——除非手序由人钉死，而本项目的手序是分配器算出来的。
- 同理，**「蹭」也写不出来**：我全程 0 次软级蹭，官谱 22 次。知识 048/062 说蹭是设计手段，
  但没有任何一条告诉我**该在什么地方主动制造蹭**。

### G4（B+C）「采音」在写谱端没有抓手

- 我以为自己在做「采音」，实际做的是**按分音铺匀拍**——所以骨架轨 coverage 0.87–0.95，
  79% 的小节被判成「全踩」。官谱在副歌只用一半鼓点。
- 知识 068/069 描述了官谱的**分布**（越难越舍音、音多则不踩满），但**没有回答
  「舍音时舍哪一半」** —— 而 068 自己第 8 条就写着「真正要设计的是『舍音时舍哪一半』」。
  这条缺口是知识库**自己标出来的**，本轮试写把它变成了可复现的失败。
- 工具侧：采音层只能在**写完之后**报 coverage，`song_sheet` 的逐小节网格串
  也只给「候选池」而不给「这一格该不该踩」。**写的时候没有任何东西挡住我铺匀拍。**

### G5（C）配置层的「种类数 / 主料数」量的是检测器，不是我的选择

- 我第 2 轮为了把 20 类压下来，删掉了三角交互与大宇宙两类——结果第 3 轮还是 19 类、
  第 5 轮 20 类。因为 `2+1` / `3+1` / `井字星星` / `二连扫` / `散点` / `鼓动段` / `三叉戟`
  这些都是**我没有主动写、检测器从我的匀拍串里认出来的**。
- 这正是知识 075 的「配置有两层」在写谱端的反面：**我能选的是「两只手各做什么」，
  但检测器报的是它从结果里认出来的名字**，两者不是一回事。
- 结论：**「配置种类数」不适合当写谱时的自检指标**；能自检的是「我主动铺了几种手分工」。

### G6（C）检查器拦不住「写得太浅」

- 终稿 0 错误 0 警告，手序难度 0.069 —— **只有官谱的 41%**。
  检查器没有任何一条提示说「这张谱对不起它的定数」。
- 密度层对照了 note 总数与 NPS（两者都在 13.5 档区间内），但 note 总数落在区间内
  ≠ 难度到位：官谱同样在区间内，却比我难一倍。
- 知识 070 说「升定数靠密度与细分音」，知识 078 说「手序难度不是难度代理」——
  两条合起来**等于没有可用的难度自检**。

### G7（A）结尾形态的判据在这首上给了两边同一个标签，但强度差 20%

- 两边都判「尾杀」，官谱 tail_ratio 1.310、我 1.099。知识 031 §10 的三个阈值
  （1.00 / 0.70 / −0.50）把 1.10 和 1.31 归成同一类，**分辨不出「尾杀得够不够狠」**。

### G8（A）音频侧的「强度」和谱面该有的密度对不上

- 管线给 43–56 的强度 0.51、建议 7.3 note/小节；官谱写 11.1。
- 给 77–84 的强度 0.44、建议 7.0；官谱写 13.6（全曲最密）。
- `song_sheet` 自己标了「逐小节 MAE 2.07–4.69」，但**段落级的偏差在这首上达到 6.6 note/小节**，
  而且**方向一致地偏低**。

## 6. 知识草案（试写暴露的稳定认知，**编号占位、不入库**）

> 三条都只有 **n=1**（一首曲子、一次试写），置信度都只能标 `存疑`。
> 入库前至少要再跑两三首试写，并且第 1 条要与官谱全库对照。

### 草案 088 — 生成端写不出「出张」与「蹭」，只能写出**逼出它们的形状**

- **要点**：出张（知识 064）与软级的蹭（知识 011/048）在**读谱端**是可以数的，
  但在**写谱端**没有直接对应的操作——因为手序是分配器按代价最小算出来的，
  两只手都够得着时它绝不会主动跨界、也不会主动去蹭。生成端能做的只有两件事：
  ① 用长条 / 星星**钉住一只手的专属键**（左手 6/7、右手 2/3），逼另一只手跨界；
  ② 写**侧边双押** `{2,3}` / `{6,7}`（按知识 064 的交叉推论必定产生出张）。
- **本轮证据**：把知识 087 §5 的对称模板 `45,,45,,2,3,2` 原样写进 `m049`，出张 **0 次**；
  把长条从共享键 `1h`/`8h` 换到专属键 `3h`/`6h`，出张立刻出现。
- **置信度**：存疑（n=1；且完全依赖 `hands.py` 的代价模型，换一套代价可能变）。
- **关联**：064 / 079 / 087 / 075 / 076。

### 草案 089 — 「段落 lift」是分布不是处方：单曲可以整段与 074 相反

- **要点**：知识 074 的段落 × 配置 lift 来自 160 首的平均，**单曲整段与它相反是常态**。
  本轮这一首：イントロ 官谱写的是星星族（一笔画 / 三叉戟 / 绕圈星星 / 连续拍滑 / 鼓动段），
  074 说是纵连族；間奏 官谱写的还是星星族且**一类几何都没有**，074 说是几何集中地。
- **推论**：074 只能当**候选清单**（「官谱在这类段落写过这些」），
  不能当处方（「这一段就该写这些」）。段落标签本身也是管线产物（未经听审）。
- **置信度**：存疑（n=1）。
- **关联**：074 / 071 / 073 / 075。

### 草案 090 — 「note 总数落进定数区间」不等于难度到位

- **要点**：知识 004 的 p10–p90 区间很宽（13.5 档 492–967）。本轮试写 761、官谱 946，
  **两者都在区间内**，但官谱的手序难度是试写的 2.4 倍、slide 是 3.5 倍、hold 是 12.5 倍、
  出张是 5.5 倍、软级蹭 22 次 vs 0 次。
- **推论**：定数校准**不能只看 note 总数**；至少还要看 **note 种类构成**（slide / hold / each 占比）
  与**跨界与蹭的用量**。知识 070「两条轴正交」说的就是这件事，但它没有给写谱端的自检清单。
- **置信度**：存疑（n=1；两个"难度"量都是本项目的内部口径）。
- **关联**：004 / 031 / 070 / 078 / 079。

## 8. 局限

1. **n=1**：一首曲、一个谱师（agent）、一次试写。任何比例性的结论都只能当个案。
2. **没有真机、没有听审**：终稿没有在 SimaiSharp / MajdataEdit / MiaCode 里跑过
   （本机没装，见检查器 README），也没有人打过。「0 绝对无理」只说明
   **分配器能找到一套合法手序**（知识 065：合法手序不止一套）。
3. **官方谱是社区转录**（mai-notes 镜像），不是 SEGA 原始数据。
4. **段落标签与强度曲线是管线产物**，未经人工听审；§3.2 里「落ちサビ 不是减压段」
   这条结论本身就说明标签有误。
5. **采音层用的是网格候选池口径**（`song_analysis.json` 的 `patterns`），
   与 `tools/calibration/sampling.py` 的**原始 onset 口径**不同，两套数不可混用；
   §3.6 里的 coverage 只在**两张谱之间**横比有意义。
