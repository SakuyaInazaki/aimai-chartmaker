# 官方音频 × 官方谱：配对标定与切轨验证

> **状态**：v1.0（2026-09-11）。这是 `docs/audio-analysis.md` §4.8 标定协议中一直挂起的
> **(E) 项**——「将来若用户提供官方音频，才能做真正的配对标定」。
> 用户 2026-09-11 提供 **8 首官方 ST 曲包**（官方 mp3 + 官方 maidata，含 `&inote_5` Master 谱），
> 本报告是这 8 首上跑出来的全部结果。
>
> **工具**：`tools/calibration/`（CLI 见该目录 README）；数据 `docs/research/data/audio-chart-calibration-summary.csv`。
> **复现**：
> ```bash
> # 1) 先对每首跑音频管线（详见 §1 表）
> python -m tools.audio_analysis --audio out/calib/<曲名>/track.mp3 --bpm <BPM> --first 0 --level <lv_5> --out out/calib/<曲名>/
> # 2) 再跑标定
> python -m tools.calibration --calib-dir out/calib --csv docs/research/data/audio-chart-calibration-summary.csv
> ```
> **口径警示**：全部结论只建立在 **8 首** 上（定数 13.5–14.5，BPM 128–230，全为 ST MASTER）。
> 凡本报告与 388 谱全量统计（知识 031）冲突处，**以 388 谱为准**；本报告的价值在于
> 它是**唯一一份同时握有音频与官方谱的配对证据**。
> **版权**：`official-mp3/` 与 `out/` 均已 gitignore；本报告不含任何音频、谱面正文片段。

## 0. 一句话结论

1. **官方包 `&first = 0` 被音频侧独立确认**（8/8，相位扫描 |φ\*| ≤ 20 ms）；
   管线 §2.4 的 offset 校验在其中 **2 首上报了 ±半拍的假警报**，是一个应当修掉的真 bug。
2. **音频强度 ↔ 官方密度只有中等相关**：逐小节 Spearman ρ ≈ **0.45**、逐段 ρ ≈ **0.52**。
   够用来定"这一段大概多密"，**不够用来定"高潮在哪一小节"**（峰值位置中位误差 33 小节）。
3. **权重标定没有产出值得替换的默认值**：LOSO 8 折的 CV Spearman 0.515 vs 初值 0.488，
   5/8 折胜出、符号检验 p ≈ 0.36 → **保持初值不变**。但标定暴露了两件事：
   **`voiced` 对密度贡献为 0**、**`flux` 单项就比整条融合式强**。
4. **切轨规则表（`stemplan.py`）被实测推翻**：逐段主踩建议与"官方 note 实际落在哪条 stem 的
   onset 上"只有 **64.7%** 一致，而**"永远答 drums"这个常数基线是 82.4%**——规则表输给了常数基线。
   最要害的是 **MMFC 5.4-4「副歌全踩人声」在 14 个副歌段里只有 2 段成立**。
5. **结尾形态**：388 谱中 **尾杀 65.1% / 渐弱 1.0% / 其他 33.9%**（末 8 小节口径，
   换 6/12 小节结论稳定）。用户讲授的「尾杀为主、渐弱也有」被数据完整支持，
   且"渐弱"确实是**少数派**。
6. **「曲子淡出、谱面不淡出」假说只成立一半**：8 首中 **7 首**谱面末段的相对强度高于音频末段
   （d_tail_ratio > I_tail_ratio），但音频真的淡出时（幻想 / 麒麟）**谱面密度也跟着降**，
   只是降得少。正确表述是 **"谱面的收尾减压幅度系统性小于音频"**，不是"谱面不减压"。

### 1.2 offset 校验：`&first = 0` 被音频侧确认，管线报了 2 次假警报

两条独立证据：

**(a) 管线自带的 offset 反向校验（`grid.check_offset`，只报告不覆盖）**

| 曲名 | `delta_ms` | 管线判词 |
|---|---:|---|
| Back 2 Back | +7.7 | 一致 |
| MYTHOS | +10.8 | 一致 |
| Mare Maris | **+27.9** | >15 ms，建议人工复核 |
| Signature | **−229.0** | >15 ms，建议人工复核 |
| Xevel | +7.2 | 一致（对齐峰较弱，15 个同级峰） |
| 初音ミクの激唱 | +4.1 | 一致 |
| 幻想のサテライト | +7.2 | 一致 |
| 麒麟 | **−129.8** | >15 ms，建议人工复核 |

**(b) 用官方谱反过来校验音频（本报告新增，`stemhit.best_shift`）**

把官方 note 的时间槽整体平移 φ ∈ [−45, +45] ms（步长 2.5 ms），
找"落在任一 stem onset ±30 ms 内"的比例最高的 φ\*。官方包的 `&first` 是 ground truth，
所以 φ\* 偏离 0 只可能来自 mp3 解码/容器偏移。

| 曲名 | φ\* (ms) | 匹配率 @φ=0 | 匹配率 @φ\* | 谱面小节起点 vs 音频网格最大误差 |
|---|---:|---:|---:|---:|
| Back 2 Back | +7.5 | 0.963 | 0.974 | 0.000 ms |
| MYTHOS | +2.5 | 0.781 | 0.788 | 0.000 ms |
| Mare Maris | +20.0 | 0.681 | 0.845 | 0.000 ms |
| Signature | −17.5 | 0.746 | 0.891 | 0.000 ms |
| Xevel | +2.5 | 0.812 | 0.815 | 0.000 ms |
| 初音ミクの激唱 | −5.0 | 0.598 | 0.605 | 0.000 ms |
| 幻想のサテライト | +7.5 | 0.819 | 0.823 | 0.000 ms |
| 麒麟 | +7.5 | 0.808 | 0.810 | 0.000 ms |

**结论**：

- **8/8 曲的 |φ\*| ≤ 20 ms**，中位 +5.0 ms —— 与 MP3 容器 `start_time = 23 ms`
  同量级（设计文档 §2.1 已警示的编码器延迟）。**官方包的 `&first = 0` 成立，
  mp3 与谱面没有对齐问题**；后续分析按 `|φ*| > 10 ms 才补偿` 的规则处理
  （实际补偿了 Mare Maris +20 ms、Signature −17.5 ms 两首）。
- **Signature 的 −229 ms 与麒麟的 −129.8 ms 是假警报。** 原因已定位：
  - Signature BPM 128 → 半拍 = **234.4 ms**，报出的两个并列峰是 **−228.7 / +241.3 ms**；
  - 麒麟 BPM 220 → 半拍 = **136.4 ms**，两个并列峰是 **−127.7 / +142.3 ms**。
  - 即：**搜索窗半径恰好设成 ±半拍，窗口两端正是"反拍"位置，在鼓点规整的曲子上反拍与正拍
    得分并列**；真值 φ=0 附近不是局部极大，于是算法在两个反拍候选里二选一，报出 ±半拍的偏移。
- Mare Maris 的 +27.9 ms 与 φ\* = +20 ms 方向一致、量级一致 → 那是**真实的解码偏移**，
  不是谱面错位；管线"建议人工复核"是对的，但措辞应指向解码延迟而不是"谱面可能错"。

> **对 `grid.check_offset` 的修订建议（§8-R1）**：① 搜索窗**不要等于 ±半拍**，
> 改为 ±(1/4 拍) 或显式排除落在 ±(半拍 ± 20 ms) 上的候选；② 增加"φ\* 必须比 φ=0 的
> 得分高出一个比例阈值（如 1.15×）才报警"的门；③ 把"并列峰数 ≥ 2 且分布对称"
> 直接判为**不可判定**，而不是挑一个报出来。

### 1.3 复现一致性

标定工具不复用管线内存中的中间量，而是从 `stems/*.wav` 重跑 onset、重算五项强度分量。
重算的 `bar_raw` 与管线写进 `song_analysis.json` 的值**最大绝对差 5×10⁻⁵**（8/8）
→ 标定与管线口径一致，不存在"两套实现两套数"的问题。

## 2. 强度 × 密度（§4.8(E) 主体）

### 2.1 逐小节相关

`I_bar`（`intensity.py` 的 smoothed 输出）vs `d_bar`（官方逐小节 note 数）：

| 曲名 | Spearman(raw) | Spearman(smoothed) | Spearman(知识 003 加权密度) | Pearson(smoothed) | 段落级 Spearman |
|---|---:|---:|---:|---:|---:|
| Back 2 Back | 0.320 | **0.215** | 0.214 | 0.142 | 0.357 |
| MYTHOS | 0.243 | **0.196** | 0.220 | 0.325 | 0.033 |
| Mare Maris | 0.371 | **0.362** | 0.343 | 0.427 | 0.346 |
| Signature | 0.616 | **0.652** | 0.660 | 0.665 | 0.667 |
| Xevel | 0.395 | **0.362** | 0.363 | 0.418 | 0.769 |
| 初音ミクの激唱 | 0.553 | **0.602** | 0.612 | 0.630 | 0.578 |
| 幻想のサテライト | 0.482 | **0.537** | 0.535 | 0.553 | 0.604 |
| 麒麟 | 0.593 | **0.583** | 0.570 | 0.618 | 0.600 |
| **8 曲汇总（Fisher z）** | **0.468** | **0.454** | **0.467** | **0.498** | **0.523** |

- **中等相关，不是强相关。** 逐小节 ρ ≈ 0.45，逐段 ρ ≈ 0.52。
  设计文档 §4.8(D) 给"人工听审"定的目标是 ρ ≥ 0.8，**配对数据给出的真实水平只有它的一半多**。
- **平滑没有帮助**：raw 0.468 ≥ smoothed 0.454。中值+高斯平滑抹掉的正是官方谱也会有的
  单小节爆发（知识 031：峰值小节 ≈ 2.06 × 全曲均值）。
- **知识 003 的 note 种类加权对相关性毫无影响**（0.467 vs 0.468）。
  这不是说加权错了，而是说**加权密度与原始密度本身高度共线**（note 种类分布在小节间差异不大），
  所以"音频强度 → 谱面强度"的差异**必须**由配置复杂度这一侧承担（知识 003/031 §8 的原话被再次证实）。
  加权权重为本项目自定（`chartpair.KIND_WEIGHT`：tap 1.0 / hold 1.2 / slide 轨 1.5，
  BREAK +0.3、each +0.2），知识 003 只给了定性顺序，**这组数值没有独立依据，仅作稳健性对照**。
- **最差的两首（MYTHOS 0.196、Back 2 Back 0.215）有共同点**：
  Back 2 Back 是全曲密度最低的一首（5.69 note/小节，远低于同定数官方均值），
  MYTHOS 是钢琴+鼓的器乐曲、密度曲线接近全程高位平台（知识 031 §9 的"全程高密平台型"，占全库 40.7%）。
  **平台型谱面天然与任何音频曲线相关性低**——这不是管线的失败，而是知识 031 §9 已经预告过的现象。

### 2.2 单特征相关：融合式不如它的最强单项

各 Z 特征**单独**与 `d_bar` 的 Spearman（8 曲 Fisher 汇总）：

| 特征 | 单项 ρ | 现行权重 |
|---|---:|---:|
| `flux`（谱通量） | **0.524** | 0.10 |
| `loudness`（逐小节响度） | 0.450 | 0.25 |
| `onset`（去重合并 onset 计数） | 0.403 | 0.30 |
| `drums`（鼓能量 dB） | 0.337 | 0.20 |
| `voiced`（人声活动率） | **0.016** | 0.15 |
| （五项融合，初值权重） | 0.454 | — |

两个硬结论：

1. **`voiced` 对"谱面密度"的预测能力是 0**（ρ = 0.016）。设计文档 §4.5 把它当作
   "J-pop 的情绪主载体"加了 0.15 权重，**在密度这个目标上完全无效**。
   （注意口径：这不否定人声是情绪载体，只否定"人声活动率能预测谱面密度"。）
2. **`flux` 是最强单项，权重却最低（0.10）**。融合式（0.454）**低于 flux 单项（0.524）**
   —— 说明当前权重把预测力最强的项压得最轻，其余四项在稀释信号。

### 2.3 峰值位置：音频峰定位不了谱面峰

"高潮小节"用 4 小节滑动均值 argmax（与 `chart_analysis` 的 `peak_position_smooth` 同口径）：

| 曲名 | 音频峰（相对位置） | 谱面峰（相对位置） | 误差(小节) | 8 小节窗误差 | 音频峰是否落在谱面密度前 20% 小节 | 五票 climax 是否落在前 20% |
|---|---|---|---:|---:|:-:|:-:|
| Back 2 Back | 58 (0.88) | 32 (0.48) | 26 | 16 | ✅ | ✅ |
| MYTHOS | 14 (0.19) | 74 (0.99) | 60 | 30 | ❌ | ❌ |
| Mare Maris | 66 (0.84) | 76 (0.96) | 10 | 6 | ❌ | ✅ |
| Signature | 24 (0.35) | 64 (0.93) | 40 | 38 | ✅ | ❌ |
| Xevel | 94 (0.97) | 94 (0.97) | **0** | 78 | ❌ | ✅ |
| 初音ミクの激唱 | 90 (0.76) | 110 (0.93) | 20 | 6 | ✅ | ✅ |
| 幻想のサテライト | 90 (0.73) | 12 (0.10) | 78 | 92 | ❌ | ✅ |
| 麒麟 | 42 (0.37) | 88 (0.77) | 46 | 46 | ✅ | ❌ |
| **中位** | — | — | **33** | **34** | **4/8** | **5/8** |

- **误差中位 33 小节**，在 67–124 小节的曲子上等于"随机猜"。
- 换 8 小节窗没有改善（中位 34）。
- **更宽容的口径也只到一半**：音频强度峰落在谱面密度前 20% 小节里只有 4/8；
  五票 climax 稍好（5/8），说明**结构票 + 投票机制确实比裸强度峰有用**，但仍不可靠。
- 谱面峰的位置本身符合知识 031（相对位置中位 0.93，明显偏后），
  **是音频强度峰的位置太散**（0.19–0.97）。

> **这条直接推翻了一个隐含设计假设**：`intensity.py` 的 `climax_bar` 不能当作
> "谱面最密小节"的定位器。它顶多是"音乐上最激烈的一段"，而官方谱的最密小节
> 常常在一个能量并不最高的位置（例：麒麟音频峰在 0.37，谱面峰在 0.77）。

### 2.4 结构边界 vs 谱面密度变点

音频段落起始小节 vs 官方密度曲线的 L2 变点（k=5，`min_len_frac=0.10`，共 4 个内部边界）：

| 曲名 | 音频给出的边界数 | ±1 小节命中率 | ±2 小节命中率 |
|---|---:|---:|---:|
| Back 2 Back | 6 | 0.75 | 0.75 |
| MYTHOS | 8 | 0.75 | 1.00 |
| Mare Maris | 10 | 0.75 | 0.75 |
| Signature | 7 | 0.50 | 0.75 |
| Xevel | 11 | 0.25 | 0.75 |
| 初音ミクの激唱 | 13 | 0.50 | 0.50 |
| 幻想のサテライト | 13 | 0.75 | 1.00 |
| 麒麟 | 9 | 0.00 | 0.25 |
| **均值** | 9.6 | **0.53** | **0.72** |

- **±1 小节 53%、±2 小节 72%** —— 这是本次标定里**表现最好的一项**。
  知识 031 结尾提到的"密度曲线可以当结构代理"（SPICY 个案 4/4 命中）在这 8 首上
  降到 53%，但仍显著优于随机。
- ⚠️ 口径不对等：音频侧平均给 9.6 个边界去命中 4 个谱面变点，**召回口径对音频有利**；
  换成精确率口径只有 ~22%。所以正确说法是
  **"音频段落边界是谱面密度变点的超集候选"**，不是"能精确预测变点"。
- 麒麟 0.00 是个例外，值得单独复核（音频侧 9 个边界一个都没命中，
  该曲的音频峰/谱面峰也差 46 小节）。

## 3. 权重标定与留一曲交叉验证

### 3.1 做法

- 特征：`intensity.py` 的五项 Z 特征，逐曲各自 z 标准化；
- 目标：逐曲 z 标准化后的 `d_bar`；
- 拟合：非负最小二乘（岭系数 α=1 的增广 NNLS，保证非负）；
- 评估：**留一曲交叉验证（8 折）**，在留出曲上算 `fuse(X, w)` 与 `d_bar` 的 Spearman。
- 说明：融合式后接的 `robust_unit` 是单调变换，**Spearman 只取决于 w 的方向**，
  所以标定 = 找方向，权重归一到 Σw = 1 不损失信息。

### 3.3 决定：**不更换 `intensity.py` 的默认权重**

依据：

1. CV 均值只提升 **+0.027**、中位 **+0.019**；
2. **5/8 折胜出**，双侧符号检验 **p ≈ 0.36**，不显著；输掉的那一折（Back 2 Back）
   反而输得最多（−0.186）；
3. 样本只有 **8 首**，其中 2 首器乐向、1 首变速、BPM 跨度 128–230 —— 拟合权重把 68%
   的分量压在 `flux` 一项上，**这更像是对"本样本里 flux 恰好最好"的过拟合**，
   而不是一条稳定规律；
4. 任务约定「只有当 CV 指标**明显优于**初值时才替换」——+0.027 不满足"明显"。

**保留初值 `[0.25, 0.30, 0.20, 0.15, 0.10]`。** 同时把两条发现记录在案，
作为下一批音频到手后优先复验的假设：

- **H1**：`voiced` 权重应从 0.15 降到 0（对密度目标无贡献，ρ = 0.016）；
- **H2**：`flux` 权重应从 0.10 提到 0.25 左右（单项 ρ = 0.524，为五项最高）；
- **H1+H2 合起来就是 `voiced_to_flux` 预设**，它在 8 首上的**中位 ρ 最高（0.559）**
  且改动可解释、不含黑箱拟合。**建议在拿到 ≥ 20 首配对数据后优先检验这个预设。**

## 4. 密度地板与定数锚点检验

### 4.1 地板：小节尺度 0.25 站得住，段落尺度 0.60 偏高

模型（设计文档 §4.7(2)）：`density_norm = floor + (1 − floor)·I`。
绝对量级另由"定数 → note/小节"锚定，所以这里只比**形状**：
两边各除以曲内均值后，在 8 首上池化拟合最优 `floor`。

| 尺度 | 池化最优 floor | 最优 SSE | floor = 0.25 的 SSE | floor = 0.60 的 SSE |
|---|---:|---:|---:|---:|
| 小节尺度 | **0.020** | 170.9 | 175.0（+2.4%） | 192.1（+12.4%） |
| 段落尺度 | **0.125** | 12.49 | 12.60（+0.9%） | 13.78（+10.3%） |

- **小节尺度 `floor = 0.25`**：损失只比最优大 2.4% → **可以保留**。
- **段落尺度 `floor = 0.60`**：损失比最优大 10.3%，且**比小节尺度的 0.25 还差**
  → **偏高，建议下调**。知识 031 §2 的 0.62 来自"结构对齐五段的最弱段"，
  那是**谱面自身**段间落差的统计；把它直接当成"音频强度 → 密度"映射的截距是**口径错配**：
  前者已经隐含了"官方谱的段落划分本来就不会把一段写得很空"，后者要回答的是
  "音频弱到什么程度时谱面才可以变稀"。
- 按 I 五分位看实测画像（以曲内均值为 1 的口径，8 曲平均）：

  | I 分位 | Q1(最弱) | Q2 | Q3 | Q4 | Q5(最强) |
  |---|---:|---:|---:|---:|---:|
  | **实测密度 / 曲内均值** | **0.598** | 0.945 | 1.081 | 1.136 | 1.239 |
  | `floor=0.25` 模型预测 | 0.721 | 0.957 | 1.045 | 1.099 | 1.176 |

  实测在**最弱档比模型更低**（0.598 vs 0.721），高档略高 —— 即真实映射比模型**稍陡一点**，
  与"最优 floor 更低"的结论一致。

## 5. 切轨验证（本次最有价值的部分）

### 5.1 方法

- 官方 note 按时间去重成**时间槽**（同刻的 each/双押算一个踩音事件）；
- 对每个时间槽，看 ±30 ms 内是否有 `drums / bass / other / vocals` 的 onset（**量化前的原始秒数**）；
- **命中率 recall** = 该 stem 能解释的官方时间槽比例；
- **精确率 precision** = 该 stem 的 onset 中被官方采用的比例；
- **随机基线 chance** = 把同样数量的 onset 均匀撒在同一区间时的期望命中率
  `1 − exp(−λ·2τ)`；**lift = recall / chance**。
  ⚠️ **必须看 lift**：鼓轨 onset 天然最多（479–631 个 vs 人声 61–333 个），
  只比 recall 的话鼓永远赢。

### 5.5 与 MMFC 5.4 / 知识 002 / `stemplan.py` 规则的冲突清单

> ⚠️ **先说清楚这些结论的边界**（决定它们能推翻到什么程度）：
> ① 这里的 ground truth 不是谱师访谈，而是**"官方 note 是否落在某条 Demucs stem 的 librosa onset 上"**这个代理；
> ② **鼓的 onset 检测远比人声可靠**（设计文档 §9 A.3/A.4 已列为最不可靠环节之一：
> Demucs vocals 轨常混进 lead synth，鼓件分解是频带启发式）；
> ③ 人声 onset 数量本身构成天花板。逐曲"人声 onset 数 / 官方时间槽数"：
>
> | 曲名 | 人声 onset 天花板 | 实测 vocals recall |
> |---|---:|---:|

> | Xevel | 0.179 | 0.109 |
> | 麒麟 | 0.183 | 0.123 |
> | Signature | 0.245 | 0.080 |
> | 初音ミクの激唱 | 0.273 | 0.194 |
> | Mare Maris | 0.440 | 0.311 |
> | 幻想のサテライト | 0.616 | 0.331 |
> | Back 2 Back | 1.089 | 0.221 |
>
> MYTHOS 是钢琴+鼓的器乐曲，人声天花板 0.104 本来就该低 —— **那一栏的低命中是正确的，不是缺陷**。
> 但 Back 2 Back（天花板 1.089、实测 0.221）与幻想（0.616 / 0.331）说明：
> **即使人声 onset 充足，官方 note 也没有主要踩在人声上**。

**C1｜「副歌全踩人声」（MMFC 5.4-4 / `stemplan.py` 规则 4 / 知识 002）— 被推翻为"少数情况"**

- 14 个 `chorus` 段里，**只有 2 段**实测 vocals 命中率最高；12 段是 drums。
- 副歌段整体：drums recall 0.583 vs vocals 0.200；lift 2.51 vs 1.73。
- `final_chorus` 更极端：vocals recall **0.065**、lift **0.97**（= 随机水平）。
- **唯一站得住的反例是 幻想のサテライト**（豚乙女，东方人声 arrange）：
  - chorus 小节 97–112：vocals **0.544** > drums 0.392；
  - chorus 小节 49–62：vocals **0.460** > drums 0.405；
  - verse 小节 11–24：vocals **0.400** > drums 0.343。
  这首**确实是"副歌踩人声"**，而且是 8 首里唯一一首。
- → 正确的规则应该是**条件触发**而不是无条件："副歌踩人声"只在
  **人声主导型曲目**（人声 onset 密度接近或超过鼓、vocals lift > drums lift）上成立；
  其余曲目副歌仍以鼓骨架为主、人声作重音。

**C2｜「哪个最响就一直踩哪个是新手误区」（知识 002）— 部分被数据反转**

- 官方谱在**全部 8 首、几乎全部段落**上都以鼓为最高命中轨（70/85 段）。
- 但这**不等于**谱师在"只踩鼓"：
  - **36.2% 的官方 note 不落在 drums 上**；
  - **18.6% 什么都不落**（自由发挥 / 装饰 / 检测漏掉）；
  - 只落在 drums 上的仅 **28.1%**。
- → 官方谱的真实形态是 **"鼓当骨架 + 大量非鼓的填充与装饰"**，
  而不是"整段切到某一条非鼓轨"。知识 002 的"切轨"在**踩音重心**层面成立，
  在**骨架**层面不成立。`stemplan.py` 把"主踩音轨"做成**单值**（一段一条轨）
  是模型层面的错误——应该是**"骨架轨 + 点缀轨 + 权重"**。

**C3｜`stemplan.py` 规则 1「前奏哪个响踩哪个」— 方向对但轨选错**

- `intro` 段一致率 0.75（8 段里 6 段对）是全部类型中最高的之一，
  但**它对的原因是"最响的恰好也是 drums"**；lift 口径下 intro 的最高 lift 是
  **other（5.08）**而不是 drums（4.39）。→ 规则的**判据（能量占比 `share_s`）选错了**，
  应改用"onset 与谱面的匹配倾向"或至少用 lift 而非能量。

**C4｜规则 5「间奏踩人声采样」— 唯一被正面支持的一条**

- `interlude` 是 vocals **precision 最高（0.715）**、**lift 最高（3.18，超过 drums 3.11）**的段落类型。
- 即：间奏里人声 onset 虽然少，但**一旦出现就几乎必被官方采用**。→ 规则 5 成立，且应加强。

**C5｜规则 6「休息段踩次响轨」— 数据不支持也不反对**

- `quiet_chorus`（落ちサビ）一致率 0.62；vocals lift 2.94 为该类型最高。
- 样本 13 段，结论不稳，**维持现状但标存疑**。

## 6. 结尾形态统计

### 6.1 判据（本项目自定，须连同数字一起引用）

用户 2026-09-11 讲授：「曲子结尾一般会有**尾杀**，当然**渐弱淡出**也是有的，这两个都有。」
讲授只给了定性描述，因此判据由本项目定义（实现见 `tools/calibration/ending.py`）：

```
tail       = 逐小节密度曲线的末 N 小节
tail_ratio = mean(tail) / mean(全曲)
trend      = spearman(0..N-1, tail)          # −1 = 严格下降

尾杀 tail_kill : tail_ratio >= 1.00
渐弱 fade_out  : tail_ratio < 0.70  且  trend <= −0.50
其他 other     : 其余（含"低于均值但不单调下降"与 0.70–1.00 的温和收束）
```

对照口径：`late_ratio = mean(tail) / mean(最后一个高密平台)`，`>= 0.90` 记尾杀。

### 6.2 388 官方谱语料结果（解析成功 387/388）

| 尾窗 N | 尾杀 | 渐弱 | 其他 | tail_ratio 中位 | 对照口径尾杀 |
|---|---:|---:|---:|---:|---:|
| **6 小节** | **62.3%**（241） | **2.3%**（9） | 35.4%（137） | 1.072 | 27.7% |
| **8 小节** | **65.1%**（252） | **1.0%**（4） | 33.9%（131） | 1.082 | 26.1% |
| **12 小节** | **71.6%**（277） | **1.6%**（6） | 26.9%（104） | 1.081 | 23.3% |

**敏感性**：换 6 / 8 / 12 小节，**尾杀比例 62–72%、渐弱 1–2%、其他 27–35%**，
结论定性稳定；尾窗越长尾杀比例越高（长窗把收尾前的高密段也纳进来了）。

**解读**：

- **尾杀是压倒性主流（约 2/3）**，用户讲授的「一般会有尾杀」被 387 谱支持；
- **"渐弱淡出"在严格判据下极其罕见（1–2%）** —— 但用户说的「渐弱淡出也是有的」
  同样成立：它确实存在，只是**少数派**；
- **"其他" 27–35% 是真实的第三类**：末段低于全曲均值但不单调下降
  （常见形态是"最后 1–2 小节收尾、之前仍是高密"）。
  这一类不该被归成"渐弱"，也说明**二分法不够**。
- 对照口径（相对最后一个高密平台 ≥ 90%）只有 23–28% —— 即：
  **绝大多数谱的末段比全曲均值强，但比自己那个最猛的平台弱**。
  这与知识 031 §3「曲末 10% = 1.084 × 全曲均值」完全一致，互为交叉验证。

| Signature | 尾杀/尾杀/尾杀 | +0.60 dB | +0.50 | 1.14 | 1.24 | ✅ |
| Xevel | 尾杀/尾杀/尾杀 | +0.77 dB | −0.05 | 1.05 | 1.32 | ✅ |
| 初音ミクの激唱 | 其他/其他/尾杀 | +2.94 dB | +0.60 | 0.56 | 0.82 | ✅ |
| 幻想のサテライト | 其他/**渐弱**/其他 | **−1.55 dB** | **−0.95** | 0.36 | 0.62 | ✅ |
| 麒麟 | 其他/其他/其他 | **−2.19 dB** | +0.48 | 0.57 | 0.80 | ✅ |

**结论**：

- **7/8 曲的 `d_tail > I_tail`** —— 谱面末段相对全曲的"劲头"**系统性高于音频**。
  唯一例外是 Back 2 Back（1.10 vs 1.18）。
- 但 **"曲子淡出、谱面完全不淡出" 不成立**：真正淡出的两首（幻想 −1.55 dB、麒麟 −2.19 dB）
  谱面密度**也降了**（0.62、0.80），只是降幅远小于音频（0.36、0.57）。
- **正确表述**：**谱面的收尾减压幅度系统性小于音频的减压幅度**（约为音频的 1.4–1.7 倍抬升），
  不是"谱面不减压"。
- 8 首里 **5 首尾杀、1 首渐弱、2 首其他**，比例与 388 谱语料（65% / 1% / 34%）方向一致，
  渐弱那首比例偏高只是 n = 8 的抖动。

## 9. 已知局限

1. **n = 8**，且分布不均：2 首器乐向（MYTHOS / Xevel 偏器乐）、1 首变速、
   BPM 跨 128–230、定数只覆盖 13.5–14.5。任何"每首都成立"的说法都不可靠。
2. **切轨的 ground truth 是代理不是事实**：用的是"官方 note 是否落在某 stem 的
   librosa onset ±30 ms 内"，而设计文档 §9 已把 Demucs vocals 泄漏、
   鼓件频带启发式列为最不可靠环节。人声侧的结论（C1）**尤其需要在装上 basic-pitch
   / RMVPE 拿到真正的人声 note 事件后复验**。
3. **18.6% 的官方 note 什么都不落**，这个残差里混着"谱师自由发挥"与"onset 漏检"，
   本报告无法区分二者。
4. **权重标定的目标是"密度"不是"强度"**。`voiced` 被判为无用，只是说它预测不了密度；
   它可能仍然能预测配置复杂度（知识 003 的另外三个因素），而那一维**本次完全没测**。
5. 结尾形态的判据是本项目自定的阈值，虽做了 6/8/12 小节敏感性，
   但 `kill_ratio=1.0` / `fade_ratio=0.7` / `fade_trend=−0.5` 这三个数没有独立依据。
6. 峰值/边界口径对音频侧的"边界数"不设上限（平均 9.6 个边界去命中 4 个变点），
   召回口径对音频有利；精确率口径只有约 22%。
