# 歌词时间轴对齐与「官方谱跟着唱词句读走」假设检验（LRC 97 首 / 全量 160 首）

> **状态**：v1.0（2026-09-14）。这是 `docs/research/audio-chart-calibration-n160.md` §0-3
> 与 `docs/research/stem-refinement-n40.md` 留下的那条路的执行结果：
> **n=160 证明密度侧已经饱和、瓶颈在人声侧**，分轨细化又排除了"换更细的轨"，
> 于是本轮去验证**「人声曲里官方谱的密度与配置跟着唱词句读（乐句起止、换气）走，
> 而不是跟着响度走」**这个假设。用户批准的路线是
> **用公网 LRC 歌词时间轴的逐行时间戳当乐句边界的 ground truth**。
>
> **工具**：`tools/calibration/lyrics_phrases.py`（抓取/对齐/检验/阴性对照，CLI 四个子命令）、
> `tools/audio_analysis/phrases.py`（纯音频乐句边界探测器）。
> **数据**：`docs/research/data/vocal-phrase-summary.csv`（逐曲 160 行，41 KB）。
> **单测**：`tests/test_lyrics_phrases.py`（32 例，全合成数据）；`pytest tests/` 258 例全绿。
>

> 歌词文本**只在内存里用**。落盘只写 `out/lyrics/`（已在 `/out/` 的 gitignore 下），
> 每行只存**时间戳（起/止）、行序号、字符数、假名/汉字/拉丁/数字的粗计数、音节估计**，
> 以及来源（lrclib / netease）、曲目 id、匹配得分。
> **本报告、CSV、代码、单测里没有任何一句歌词原文。**
>
> ## ⚠️ 引用任何数字前必读
>

## 0. 一句话结论

1. **LRC 不是瓶颈，对齐才是。** 109 首人声曲里 **97 首（89.0%）**在 LRCLIB / 网易云找到了
   带时间轴的歌词（lrclib 51 / netease 46，每首平均 4.0 个候选）。
   但 **maimai 的 `track.mp3` 是游戏剪辑版**：LRC 末行比游戏版结尾晚的中位数是 **70.1 s**
   （游戏版中位 129 s），也就是说游戏版通常只保留了原曲的一半左右，而且是多处剪接。
2. **对齐这一步被阴性对照判死。** 把**别的曲子**的 LRC 拿去对同一首音频，
   对齐得分几乎一模一样：真 LRC 的二项 z 中位 **5.74**、外来 LRC **5.15**，
   "真的比假的高"只占 **56.7%**（随机是 50%）。250 对随机配对里 **36.8% 能过 z≥5 的门槛**。
   四种统计量（人声 onset 命中二项 z / VAD 曲线互相关 / 人声 RMS 对比度 / 小节格点受限扫描）
   **全都分不开真假**；奇偶折半一致率真 **0.05** vs 假 **0.01**。
   → **"对齐成功 67/97"这个数字是假的，不得引用。**
3. **唯一能区分真假 LRC 的统计量是「节拍一致性」**：行首落在小节格上的 Rayleigh 集中度
   `n·R²` 真中位 **7.51** vs 外来 **0.52**，真 > 外来占 **86.6%**。
   它证明"这份 LRC 确实属于这首歌"（顺带确认抓取环节没抓错曲），
   但**不含任何关于偏移在哪里的信息**（全局平移不改变集中度）。
4. **LRC 口径的 T1–T4 在配对对照下全线归零**（§3）：
   T1 句头 lift 真 1.046 / 外来 1.044，配对差 **+0.017 ± 0.021（t = 0.80）**；
   T3 音节密度 ρ 真 0.023 / 外来 0.023；T4 也一样。
   唯一"显著"的 T2b（句前留白）**被分层检查证伪为伪影**——
   它在**对齐置信度最低**的一档最强（t = −3.00），在最高一档反而消失（t = −1.25）。
5. **免对齐口径给出真正的答案（§4）：句读结构对官方谱有效，但只在"逐小节密度"这个粗粒度上，
   且增量很小、集中在人声曲。**
   - **note 级别没有句头效应**：纯音频句头 ±半拍窗的 note lift 中位 **1.021**（人声曲），
     只有 **10%** 的曲子显著（p < 0.05）；slide 起点 1.072、BREAK 0.965；
     **换气留白里也没有系统性空拍**（留白 lift 中位 0.992）。
   - **小节级别有一个小而真的增量**：把 `phrase_start` / `in_gap` 两个句读特征加到音频强度上，
     人声曲的 R² 增量相对**环形平移假特征的自由度基线**是
     **+0.036 ± 0.008（t = 4.60，Wilcoxon p = 4.7e-4，符号检验 66/109，p = 0.035）**；
     **器乐曲上没有（+0.012 ± 0.006，t = 1.87，Wilcoxon p = 0.61）**。
     ⚠️ 但**中位增量只有 +0.005**——均值被少数几首拉起来，**典型曲子几乎没有收益**。
6. **句读特征本身与密度几乎不相关**：ρ(句首数, 密度) 人声曲中位 **−0.045**、
   ρ(留白, 密度) **−0.056**，而同批曲子的 ρ(音频强度, 密度) 是 **0.278**。
   → **句读不是"另一条强度曲线"，它只在与强度联合时贡献一点非线性/互补信息。**
7. **纯音频探测器还不能替代 LRC**：F1(±1 拍) 对真 LRC 边界 **0.217**，
   对**外来** LRC 边界 **0.196** —— 两者差距在噪声内，但这**只说明 ground truth 不可信**，
   不能据此说探测器差。**探测器的有效性只有 §4 的免对齐证据（小节级增量）支持。**
8. **下一步的正确做法不是再找歌词**：要么拿到**原曲完整音频**（有了它，游戏版对原曲的对齐
   是一个信噪比高得多的音频×音频问题，LRC 就能精确落到游戏版时钟上），
   要么按 n=160 报告已经写过的那条——**人工听审 5–10 首**。

### 1.1 命中情况

| 项 | 数值 |

| 其中退到网易云 | 46 |
| 每首保留的候选数（中位） | 4.0（上限 6） |

| 游戏版时长（中位） | 129 s |

**按曲风**（人声曲内部）：

| 曲风 | 命中 / 人声曲数 | 命中率 |
|---|---|---:|
| niconico＆ボーカロイド | 39 / 39 | **1.00** |
| 東方Project | 16 / 17 | 0.94 |

- **VOCALOID 曲 100% 命中**（公网歌词库对 niconico 系覆盖极好），
  而 **POPS＆アニメ 与 ゲーム＆バラエティ 最差**——恰好是 n=160 报告里 ρ 最低、
  最需要人声侧信息的那一档（POPS＆アニメ ρ 0.186）。
- 12 首没找到的，全部是**版权曲的游戏限定曲 / 企划曲 / 体操曲 / 台词曲**，
  公网歌词库里本来就没有。

### 1.2 抓取实现里值得记下来的两件事

1. **曲名单独匹配不可靠。** 第一版按"曲名相似度 + 艺术家 token 命中"取单个最优，
   `ARROW` / `B.M.S.` / `Back 2 Back` 这类通用词**全都撞上了完全无关的曲子**。
   改成**保留最多 6 个候选、把裁决交给音频**（`align_song` 对每个候选跑一遍对齐取最优）。
   ⚠️ 结果是：这个"交给音频裁决"的设计**被 §2 判为无效**——音频裁不了。
   实际起作用的是 §2 末尾的**节拍一致性**（它在 86.6% 的曲子上把真候选排到外来候选前面）。
2. **`&artist` 不是歌手。** 官方 maidata 的 `&artist` 常写成
   `作曲者「アルバム名」` / `キャラ名(CV:声優)` / `サークル feat. 歌手`，
   所以打分前要剥掉括注与书名号（`artist_tokens`），否则 token 命中率极低。

## 2. 对齐方法与为什么它失败（本轮的主结论）

### 2.1 问题有多难

maimai 的 `track.mp3` 是**约 2 分钟的游戏剪辑版**，LRC 对应**完整原曲**。实测：

| 项 | 中位 |
|---|---:|
| LRC 末行时刻 − 游戏版时长 | **+70.1 s** |
| LRC 跨度 ≈ 游戏版时长（差 < 15 s）的曲子 | **15.5%** |
| 对齐器判为**有剪接**（块间偏移不一致）的曲子 | 59 / 97 |

→ **绝大多数游戏版只保留了原曲的一半左右，而且不是掐头去尾，是挑段拼接。**
偏移的搜索空间因此是"全曲范围 × 每个乐句块各一个偏移"。

### 2.2 试过的四种对齐口径

| # | 口径 | 做法 | 结果 |
|---|---|---|---|
| A | **人声 VAD 曲线互相关** | `onsets.vocal_activity` 的 0/1 曲线 × LRC「正在唱」曲线 | **废弃**。Demucs `vocals` 泄漏严重，VAD 的"有人声"占比中位 **0.674**，曲线接近常 1；而且公网 LRC 绝大多数**行首尾相接**（逐行间隙中位 **0.00 s**），"正在唱"曲线也是一整块。真 corr 中位 0.563 / 外来 0.522，**分不开** |
| B | **行首脉冲 × 人声 onset 的二项 z**（主实现） | 行首映射后落在某个人声 onset ±0.10 s 内算命中；零假设命中率 = onset 膨胀后的时间覆盖率（随机平移的期望），打分用二项 z | 真 z 中位 **5.74** / 外来 **5.15**，真>外来仅 **56.7%**；250 对跨曲随机配对**36.8% 过门槛** |
| C | **人声 RMS 对比度** | 映射后的"唱"区与"不唱"区的 dB 差 | 真中位 28.1 dB / 外来 23.2 dB，外来 p95 **40.8 dB**，**分不开** |
| D | **小节格点受限扫描** | 先用行首的小节相位把 delta 锁到格点上（把 12500 个候选偏移压到 ~600），再扫命中 | 真 z 中位 3.66 / 外来 3.30，**仍分不开**；联合"节拍一致性"后可以把 FPR 压到 1%，但 TPR 只剩 **0.28** |

### 2.3 判决性证据

**(a) 跨曲阴性对照**（`cross_song_control`，250 对随机配对）

| 指标 | 值 |
|---|---:|
| 过 `z ≥ 5 ∧ hit_rate ≥ 0.55 ∧ n_in ≥ 10` 门槛的比例 | **36.8%** |
| 外来 LRC 的 z 均值 / p95 / 最大 | 4.84 / 6.98 / **8.86** |
| 真 LRC 的 z 中位 / p95 / 最大 | 5.74 / 8.26 / 8.82 |

→ **真 LRC 的最大 z 甚至没超过外来 LRC 的最大 z。** 门槛无论定在哪里都不成立。

**(b) 奇偶折半一致性**（把行首按奇偶拆成两半各自定偏移，真对齐时两半应当给同一个偏移）

| | 两半偏移差 < 0.2 s 的比例 |
|---|---:|
| 真 LRC | **0.05** |
| 外来 LRC | 0.01 |

→ **95% 的曲子连"真 LRC 的两半自己对不上自己"都做不到。**

**(c) 唯一有效的统计量：节拍一致性**

行首落在小节格（4 拍）上的 Rayleigh 集中度 `R`，统计量取 `n·R²`：

| | 中位 | 真 > 外来 | 真 > 外来 p95 |
|---|---:|---:|---:|
| 真 LRC | **7.51** | **86.6%** | 58.8% |
| 外来 LRC | 0.52 | — | — |

配套事实：**行首到最近"1 拍格"的中位偏差只有 67 ms**（半拍窗宽中位 176 ms，比值 0.39），
**LRC 的时间戳精度本身是够的**。所以失败的原因不是歌词质量差，而是
**"游戏版只留了原曲一半 + 多处剪接"把搜索空间撑爆，而音频侧唯一的锚（Demucs 人声轨）
太脏，撑不起这个搜索**。

> **这条要记进知识库的措辞**：`n·R²` 能回答"这份 LRC 是不是这首歌的"，
> **不能**回答"它对应游戏版的哪一段"——因为全局平移不改变相位集中度。

## 3. T1–T4（LRC 口径，**探索性**，全部配对外来 LRC 对照）

口径：对每首曲子，用同一个对齐器分别处理**真 LRC** 与**外来 LRC**（同一批曲子里按固定规则
取的另一首的 LRC），得到两张乐句表，跑同一套检验，然后做**配对差**。
可配对曲数 **95**。每个 lift 自带**同曲随机循环平移对照**（`interval_lift`，200 次，
区间个数与每段时长完全不变，只换位置）。

| 检验 | 真 LRC（中位 / 均值） | 外来 LRC（中位 / 均值） | 配对差 ± SE（t） |
|---|---|---|---|
| **T1** 句头 ±半拍 note lift | 1.046 / 1.068 | 1.044 / 1.051 | **+0.017 ± 0.021（t = 0.80）** |
| T1 slide 起点 lift | 1.157 / 1.206 | 1.132 / 1.169 | +0.037 ± 0.072（t = 0.51） |
| T1 BREAK lift | 0.913 / 1.231 | 0.889 / 1.120 | +0.112 ± 0.194（t = 0.58） |
| **T2b** 句前窗 `[−1.5拍, −0.5拍]` lift | 0.938 / 0.933 | 0.998 / 1.007 | **−0.074 ± 0.020（t = −3.73）** ⚠️ 见下 |
| T2a 真间隙 lift（n = 35） | 0.998 / 0.982 | 0.986 / 0.997 | −0.015 ± 0.091（t = −0.16） |
| **T3** ρ(音节/小节, 密度) | 0.023 / 0.018 | 0.023 / 0.035 | −0.017 ± 0.023（t = −0.76） |
| T3 ρ(句首数/小节, 密度) | 0.022 / 0.003 | 0.009 / 0.032 | −0.029 ± 0.020（t = −1.48） |
| T3 联合回归增量 R² | 0.012 / 0.034 | 0.011 / 0.029 | +0.005 ± 0.005（t = 1.04） |
| **T4** ρ(句长, 句内 note 数) | 0.755 / 0.720 | 0.775 / 0.727 | −0.007 ± 0.026（t = −0.26） |

**参考**：同批曲子的 ρ(音频强度, 密度) 中位 **0.267**（与 n=160 报告的人声曲 0.28 一致）。

### 3.1 T2b 那个"显著"是伪影

把配对差按三种置信度分层：

| 分层键 | 低档 | 中档 | 高档 |
|---|---|---|---|
| 节拍一致性 `n·R²` | −0.063（t = −1.90） | −0.073（t = −2.11） | −0.085（t = −2.37） |
| **对齐 z** | **−0.099（t = −3.00）** | −0.092（t = −2.15） | **−0.032（t = −1.25）** |
| **命中率** | **−0.082（t = −2.87）** | −0.086（t = −2.60） | **−0.053（t = −1.32）** |

→ **如果它是真的句读信号，就应该在"对得越准"的那一档越强。实际相反。**
更可能的机制：真 LRC 的行距被本曲的拍长量化，所以句前窗**整体共用一个（哪怕是错的）拍相位**，
与官方 note 的拍相位分布产生系统性的边界效应；外来 LRC 的行距不匹配本曲拍长，窗口相位被摊平。
**判定：T2b 不构成对"换气留白"的支持。**

### 3.2 T4 的描述统计（唯一可以直接读的部分）

T4 只做描述统计，而且它量的东西**不依赖偏移的正确性**（句长是 LRC 内部的量）：

| 指标 | 人声曲中位（n = 96） |
|---|---:|
| ρ(句长拍数, 句内 note 数) | **0.752** |
| ρ(音节数, 句内 note 数) | 0.329 |
| ρ(句长, 句内 **NPS**) | 0.004 |
| ρ(音节数, 句内 NPS) | −0.008 |
| ρ(句长, each 占比) | −0.038 |
| ρ(句长, slide 占比) | 0.070 |
| note / 音节（中位） | 1.463 |
| 句长（中位） | 8.51 拍 |

**读法**：`ρ(句长, 句内 note 数) = 0.75` 是**平凡的**（窗口越长装的 note 越多）；
一旦除掉长度换成 **NPS，相关就归零（0.004）**。
**"句长/字数决定句内配置强度"这条没有任何支持**（each / slide 占比与句长都不相关）。
⚠️ 这些数字在对齐错误时仍然部分有效（句长本身是对的，句内 note 的归属是错的），
所以**只能当"连个平凡以外的信号都没有"的负面证据**。

### 3.3 副歌分层

副歌段内的句头 lift 中位 **1.066**（n = 83）vs 非副歌 **1.039**（n = 89）。
差距 0.027，在配对对照（±0.021）的噪声量级上，**不构成结论**。

## 4. 免对齐口径：纯音频句读特征 × 官方谱（**本轮真正可用的部分**）

既然歌词对不上，就把"句读边界"换成**不依赖歌词的纯音频估计**
（`tools/audio_analysis/phrases.py`），对**全部 160 首**（人声 109 / 器乐 51）做同一套
lift + 随机平移对照。这一路没有对齐这个坑，**器乐曲天然是阴性对照组**。

**探测器**（`detect_phrases`，默认 `gap_beats=2.0` / `min_sep_beats=2.0`）：
`onset_gap`（人声 onset 的发音间隔 ≥ 2 拍 → 停顿后重新开口）∪ `vad_rise`（VAD 上升沿），
再按 2 拍合并近邻；留白取 VAD 里 ≥ 1 拍的静音段。
规模：句首数中位 **40**（p10 20 / p90 67），留白段数中位 **9**。

### 4.1 note 级别：句头效应 **不存在**

| 指标 | 人声曲（109） | 器乐曲（51） |
|---|---:|---:|
| 句头 ±半拍 note lift（中位 / 均值） | **1.021 / 1.022** | 1.004 / 1.014 |
| 随机平移对照下显著（p < 0.05）的曲子 | **10%** | 16% |
| lift > 1 的曲子 | 57% | 57% |
| slide 起点 lift（中位） | 1.072 | 0.979 |
| BREAK lift（中位） | 0.965 | 1.148 |
| **留白内 note lift（中位）** | **0.992** | 1.007 |
| 留白 lift < 1 的曲子 | 53% | 48% |

**判定**：
- **T1'（句头效应）不成立**。人声曲 1.021 的中位 lift，配上只有 10% 的显著率
  （随机平移对照下期望就是 5%），基本是噪声。
- **T2'（换气留白）不成立**。留白里的 note 密度与全曲均匀基线没有差别（0.992），
  **官方谱不会因为歌手在换气就留空**。
- slide 起点的 1.072 是全表唯一一个方向一致（人声 1.072 > 器乐 0.979）的数字，
  但**没有过显著性**，只能记作"下一轮可以单独看一眼的线索"。

### 4.2 小节级别：有一个小而真的增量

| 指标（中位） | 人声曲 | 器乐曲 |
|---|---:|---:|
| ρ(音频强度, 官方密度) | **0.278** | **0.437** |
| ρ(句首数/小节, 官方密度) | **−0.045** | 0.021 |
| ρ(留白覆盖/小节, 官方密度) | −0.056 | −0.023 |
| 增量 R²（强度 → 强度+句首数+留白） | 0.0372 | 0.0214 |
| **环形平移假特征的自由度基线** | 0.0287 | 0.0256 |

**必须减掉自由度基线**：多加两个自由参数，在 n ≈ 90 个小节上本来就能白捡约 **0.029** 的 R²。
减掉之后：

| | 配对差（观测 − 平移零） | t | Wilcoxon p | 符号检验 |
|---|---:|---:|---:|---|
| **人声曲（109）** | **+0.0360 ± 0.0078**（中位 +0.0050） | **+4.60** | **4.7e-4** | 66/109（p = 0.035） |
| 器乐曲（51） | +0.0116 ± 0.0062（中位 −0.0024） | +1.87 | 0.61 | 24/51（p = 0.78） |
| 全部（160） | +0.0282 ± 0.0058（中位 +0.0031） | +4.91 | 1.1e-3 | 90/160（p = 0.13） |

**读法（这段是本报告最需要小心引用的地方）**：

1. **方向对、人声专属、统计上站得住**：句读特征在人声曲上确实比"同样自由度的假特征"更能
   解释官方逐小节密度；器乐曲上没有（正是应有的阴性对照行为）。
2. **但量很小，而且分布极偏**：**中位增量只有 +0.005**，均值 +0.036 是被少数几首拉起来的；
   只有 **61%** 的人声曲观测值超过自己的平移零。
   → **"给典型曲子加句读特征，几乎什么也得不到"**，收益集中在一小撮曲子上。
3. **句读特征单独用是废的**：ρ(句首数, 密度) 中位 **−0.045**、ρ(留白, 密度) **−0.056**，
   对比 ρ(强度, 密度) 0.278。**它不是第二条强度曲线**，只在与强度联合时贡献一点互补信息。

**按曲风（人声曲）**：

| 曲风 | n | 句头 lift 中位 | 增量 R² 中位（**未减基线 0.029**） |
|---|---:|---:|---:|
| POPS＆アニメ | 11 | 0.960 | **0.0641** |
| 東方Project | 17 | 1.008 | 0.0544 |
| maimai | 17 | 0.969 | 0.0433 |
| niconico＆ボーカロイド | 39 | 1.022 | 0.0393 |
| ゲーム＆バラエティ | 15 | 1.032 | 0.0263 |
| オンゲキ＆CHUNITHM | 10 | 1.058 | 0.0258 |

- **最值得注意的一行是 POPS＆アニメ**：它在 n=160 报告里是 ρ 最低的一档（0.186），
  这里却是句读增量最大的一档（0.064，减基线后约 +0.035）。
  ⚠️ **n 只有 11，且这一档的 LRC 命中率也最低（0.73）**，只能当线索。

## 5. 探测器评估

`tools/audio_analysis/phrases.py` 的 `detect_phrases` 对 LRC 边界的
**F1（±1 拍容差，一对一贪心匹配）**：

| ground truth | n | F1 中位 | F1 均值 |
|---|---:|---:|---:|
| **真 LRC** 对齐后的行首 | 96 | **0.217** | 0.238 |
| **外来 LRC** 对齐后的行首（对照） | 95 | 0.196 | 0.197 |

**这张表不能用来评价探测器**：真 GT 与外来 GT 的 F1 差距只有 0.02，
而 §2 已经证明这两种 GT 的可信度差不多（都不可信）。
**它能说明的只有一件事：LRC ground truth 不可用，探测器的 F1 没有分母。**

**探测器唯一的有效性证据是 §4.2 的小节级增量**（人声曲 +0.036 ± 0.008 相对自由度基线，
器乐曲无）。按这条证据：

- **探测器可以接进管线，但只能作为"逐小节辅助特征"**，不能作为"乐句边界的可靠标注"；
- **不建议现在就改默认权重或默认行为**——三条换权重的判据
  （LOSO 提升 / 折胜率 / p 值，见 n=160 报告 §3）**本轮一条都没去碰**，
  因为句读特征的收益（中位 +0.005 R²）远在"值得换默认值"的量级之下。

**本轮没有做的事（明确声明）**：没有把 `phrase_start` / `in_gap` 写进
`tools/audio_analysis` 的 song sheet 与 `song_analysis.json`，也**没有在 160 首上重跑 LOSO**。
理由：§4.2 的收益量级（中位 +0.005 R²、只有 61% 的曲子为正）达不到动管线默认行为的门槛，
而 AGENT.md 准则 10 要求不擅自开工。**要不要接，交用户拍板**（§7 的待决项 1）。

### R2 — `docs/audio-analysis.md` §9/§10 的"下一步"要更新

- **纯音频句读特征只在逐小节粗粒度上有很小的增量，note 级别完全没有效应**（§4）。

### R3 — `tools/calibration/README.md` 增加一节

记入两条方法学教训（它们对以后所有"外部时间轴 × 游戏版音频"的任务都成立）：

1. **游戏版是剪辑版**：LRC 末行比游戏版结尾晚的中位数 70.1 s，59/97 判为有剪接。
   任何"拿外部完整曲时间轴对游戏版"的方案，都必须先过跨曲阴性对照。
2. **Demucs `vocals` 轨不能当对齐锚**：VAD 活动占比中位 0.674，
   真假 LRC 的对齐得分分不开（真 z 5.74 / 外来 5.15，真>外来 56.7%）。

### R4 — 建议新增知识 **033**（草案，**交主会话决定是否入库**）

> **033 — 官方谱不跟唱词句读走（note 级别）**
>
> - **要点**：在 160 首官方 ST 谱上，用纯音频估计的乐句边界检验"官方谱在乐句起点加密、
>   在换气间隙留空"这个假设，**两条都不成立**：
>   - 乐句起点 ±半拍窗内的 note 密度相对全曲均匀基线 lift 中位 **1.021**（人声曲），
>     随机平移对照下只有 **10%** 的曲子显著（期望 5%）；
>   - 换气/句间留白里的 note 密度 lift 中位 **0.992** —— **官方谱不会因为歌手换气就留空**。
> - **但小节级别有一点信息**：把"句首数/小节 + 留白覆盖/小节"加到音频强度上，
>   人声曲的 R² 相对**同自由度的环形平移假特征**增加 **+0.036 ± 0.008**
>   （t = 4.60、Wilcoxon p = 4.7e-4、符号检验 66/109），**器乐曲上没有**（阴性对照通过）。
>   ⚠️ **中位增量只有 +0.005，收益集中在少数曲子**。
> - **句读不是第二条强度曲线**：ρ(句首数, 官方密度) 中位 **−0.045**、
>   ρ(留白, 官方密度) **−0.056**，而 ρ(音频强度, 官方密度) 是 **0.278**。
> - **句长不决定句内配置**：ρ(句长, 句内 NPS) = 0.004，
>   ρ(句长, each 占比) = −0.038，ρ(句长, slide 占比) = 0.070（n = 96）。
>   `ρ(句长, 句内 note 数) = 0.75` 是平凡的长度效应，不得引用为"句长决定配置"。
> - **置信度**：**较可信（负面结论，n = 160，全部带随机平移对照与器乐阴性对照）**；
>   ⚠️ 乐句边界是**纯音频代理**，不是真句读——真句读这一层因为对齐失败拿不到（见 §2）。
>   所以正确的表述是 **"用音频能估出来的那种句读，对官方谱的 note 级别没有解释力"**，
>   **不能说成"官方谱与唱词句读无关"**。
> - **来源**：`docs/research/vocal-phrase-alignment.md` §4；工具
>   `tools/audio_analysis/phrases.py`、`tools/calibration/lyrics_phrases.py`。
> - **关联**：知识 001 / 002 / 031 / 032；`docs/research/audio-chart-calibration-n160.md`。
