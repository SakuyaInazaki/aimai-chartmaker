## 0. 一句话结论

**第一轮把"半采"判成了网格现象，这一轮改成音乐现象之后，结论方向没翻，但多了一条能用的分工：**

1. 采音判据里的「隔一个 / 只踩强拍 / 分音减半」三条**全部删掉**（它们只是拍网格的影子）。新判据只问一件事：**被踩的，是不是这一小节音乐里更响的那一半**。换判据之后 `半采` 从 13.9% 变成 **15.3%（真·挑重音）+ 7.8%（随机半采）**，而原先被"分音减半"捞进来的那一批基本落回 `随机半采` 与 `近全采`。
2. **「挑重音」是真的，但只比随机强一点**：半采区里官方谱的挑重音通过率 **66.1%**，随机平移对照 **58.3%**（曲内配对 t = 6.40，96/130 曲为正）。**+7.8 pt 是本报告最脆弱的一个数字**，任何"谱师踩重音"的论断只能按这个幅度说。
3. **配置的"密"和"难"预测的是两件不同的事**（本报告最有用的一条）：
   - **密（小节 NPS）→ 决定这个配置出现在多高定数的谱里**：配置级秩相关 **ρ = 0.80**；
   - **难（note 种类 / 位移 / 无理三项）→ 决定它放在曲内多强的位置**：与高强度富集 **ρ = 0.58**，而密与高强度富集 **ρ = −0.03**。
   - 换句话说：**想让谱更难，加密度（几何配置）；想让谱更"重"，加 note 种类（双押系 / 错位）。这两个旋钮官方谱是分开拧的。**
4. 用户要的三张清单在 §3；「音乐事件密度 × 强度档 → 配置」矩阵在 §4；最有用的一格是 **密 × 高强度 → 逆楼梯/方向盘 4.52×、散点 2.98×、三角 2.91×，采音是 `半采` 24%**。

## 1. 采音判据的修订（任务 1）

### 1.1 删掉了什么

第一轮 `半采` 的三条判据（`sampling.alt_pattern`）：

| # | 旧判据 | 为什么删 |
|---|---|---|
| ① | 被踩中的 pool 下标构成**等差为 2** 的序列（"隔一个"） | 下标等差是**采样网格**的性质，与"这个音重不重"无关 |
| ② | 官方槽全落在 **0.5 拍整数倍**上（"只踩强拍"） | 纯拍网格判据，用户点名的"光根据 bpm" |
| ③ | 谱面最细分音 = 音频量化分音的**一半**（"分音减半"） | 同上，而且量化分音本身是管线产物 |

三条一起删。`bar_metrics()` 的签名里 `chart_div` / `audio_div` 两个参数也一并去掉，`load_pair()` 不再返回它们——**现在整条采音判定链上不存在任何分音 / BPM / 网格量**。`sec_per_beat` 只剩一个用途：把 `rest_beats` 从秒换算成拍（单位换算，不是判据）。

### 1.2 新定义（`tools/calibration/sampling.py`）

逐小节，相对**目标音轨**：

- **pool（音乐事件池）**＝目标轨在该小节的 onset，按 `2τ = 60 ms` 合并去重；**合并簇取强度最大的那个事件**（60 ms 内的一串 onset 在谱面上只能对应一个音，谱师听到的是最响那下）。每个事件带一个 onset 强度（`onsets.detect_onsets` 的 `strengths`，曲内已按包络最大值归一）。
- **hit** ＝ pool 中被官方时间槽 ±30 ms 覆盖的个数；`coverage = hit / |pool|`。
- **extra** ＝ 官方时间槽中五条轨（drums/bass/other/vocals/piano）都覆盖不到的个数；`extra_ratio = extra / 官方槽数`。
- **挑重音 `accent`**（`accent_pick()`，**唯一的新判据**）：两条任一成立
  - **① 重音优先**：命中事件的平均 onset 强度 − 未命中事件的平均 onset 强度 **> 0**（严格大于，打平不算）；
  - **② 分位单调**：把 pool 按强度切成 3 个等频桶，各桶命中率**不下降**且最高桶严格高于最低桶。
  - 两侧有效事件各少于 2 个 → `证据不足`，不下结论（全库 59.3% 的小节属于这一类——因为大多数小节 coverage 很高，根本没几个"未命中"事件可比）。

判定顺序与阈值：

| 模式 | 判据 |
|---|---|
| `静默` | 官方时间槽 ≤ 1 |
| `加花` | `extra_ratio ≥ 0.50` |
| （证据不足） | `pool < 2` 或 coverage 无定义 → `混合` |
| `全采` | `coverage ≥ 0.80` 且 `extra_ratio < 0.30` |
| `近全采` | `0.65 < coverage < 0.80` |
| `半采` | `0.35 ≤ coverage ≤ 0.65` **且挑重音** |
| `随机半采` | 同区间但**不挑重音**（= 任务里说的「随机半采/混合」） |
| `稀采/空音` | `coverage < 0.35` **且 `pool ≥ 4`**（音乐真的在响才算留白） |
| `混合` | 其余（主要是"coverage ≥ 0.8 但加花也多"与"coverage 低但 pool 太小"） |

⚠️ 类别名与阈值**仍是 agent 的操作化**，不是用户讲授的术语；参数集中在 `sampling.THRESHOLDS`，敏感性见 §1.6。

### 1.5 「挑重音」到底有多真

| 口径 | 半采区小节数 | 挑重音通过率（判据①或②） | 均强差 Δ |
|---|---:|---:|---:|
| **实测（bar）** | 3 126 | **66.1%** | **+0.056** |
| **随机平移对照** | 2 441 | **58.3%** | +0.021 |
| drums 固定 | 4 109 | 67.1% | +0.058 |
| melodic | 2 621 | 55.1% | +0.033 |

- **曲内配对检验**（130 首两侧各 ≥5 个半采区小节）：Δ 实测 − Δ 对照 的曲均 **+0.036，t = 6.40，96/130 曲为正**。→ **"官方谱在半采时更倾向踩重音"这件事是真的**。
- **但幅度很小**：+7.8 pt。而且**对照本身就有 +0.021 的正偏**，来源是机械的——60 ms 合并取最大强度，密集区留下的事件天然更强，而密集区也天然更容易被命中。**所以 66.1% 这个绝对值不能读成"三分之二的半采是挑重音的"，只能读成"比随机对齐高 8 个点"。**
- 判据②（分位单调）几乎不独立起作用：半采小节里 `重音优先` 1 328、`重音优先+分位单调` 699、**只有 38 个是靠②单独进来的**。

**读法**：

- **"这个配置该出现在多高定数的谱里" ≈ 看密度**。大宇宙 13.88 / 方向盘 13.88 / 散点 13.87 / 三角 13.85 / 轴 13.84 / 楼梯 13.83 —— 六个几何配置包揽平均定数前六；而 each 最多的侧边双押 13.61 是全表最低。

- 两件事**基本正交**（D 与高强度 lift ρ = −0.03）。所以**"加难"和"加重"是两个独立旋钮**：想提高定数就加密度（几何配置、16 分以上），想跟着音乐情绪走就加 note 种类（双押系、错位）。

**一句话结论**：**BPM 是配置的"放大器"，不是配置本身**——同一个配置 BPM 越高，NPS 与平均定数都上一档（大宇宙 13.69 → 14.03、方向盘 13.65 → 14.04、错位 13.67 → 13.85），但形态不变；而**低 BPM 曲天然是半采/稀采**（<150 的 39 首 coverage 0.616、pool/小节 6.6，vs >180 的 0.711 / 4.8），**不要试图在低 BPM 曲上把鼓踩满**（知识 003 第 4 条"低 BPM ≠ 简单"的另一面）。

## 6. 矛盾案例：内在难度与实际放置对不上的

### 6.1 错位：内在 #1，平均定数只排 #11（秩差 −10）

### 6.5 长纵连：内在 #17（最简单），但平均定数 13.74 排 #9（比连续双押 13.69、单双 13.68、侧边双押 13.61 都高）

## 8. 局限（哪些环节仍不可靠）

1. **配置识别是键位版，没有左右手**。用户已要求「所有配置都按左右手定义」，`hands.py` 正在另一条线上做。本报告 §2–§6 的所有数字**都要在手序版检测器上重跑**；`config_profiles.py` 已经写成可注入的形式，重跑只需换 `detector`/`bar_configs`，但**结论可能改变**——尤其是轴交互、定拍、纵连这些"哪只手在做什么"决定成败的配置。
2. **「挑重音」只比随机强 7.8 pt**。这是本报告最脆弱的数字。`accent_margin = 0`（照任务定义的字面）时对照都能拿到 58.3%；差距在 margin = 0.05 处最大（+10.8 pt）。**任何"官方谱踩重音"的说法都只能按这个幅度说。**
3. **onset 强度是 librosa 能量包络的值，不是"这个音听起来多重"**。鼓的 kick 与 hihat 在这个量上可能反过来（低频能量大），而人耳的重音感知还含频率与音色。本报告没有办法验证这件事——**要验证需要人工听审标注"哪一下是重音"**。
4. **coverage 的绝对值不可读**：随机对照都能拿到 0.422（鼓 onset 密 + 双方都在同一套拍网格上）。只能做相对比较。
5. **目标轨口径一换，绝对占比就换一半**（bar 全采 33.4% vs drums 固定 21.8% vs melodic 22.8%）。三个口径已并排给出，但"哪个是对的"没有裁定依据。
6. **人声侧继续不可信**：知识 002 第三轮修订抓到的失败模式（Demucs vocals 轨混 lead synth）在本报告同样存在；`melodic` 口径里 vocals 占 4 119 个小节，其中有多少是假的判不了。
7. **`extra`（加花）三义混淆**：自由发挥 / 装饰音 / onset 漏检无法区分。
8. **难 H 量不到"读谱与手型"**（§6.6）。本轮用"密 D / 难 H 分列"绕开了它，没有修好它。
9. **错位在高密度段接近自动成立**（20.1% 小节），应当当背景看。
10. **侧边双押的"引导"判据仍然没有**：±2 槽 56% / ±4 槽 95%，窗口一换数字翻倍。
11. **跳拍只有粗判**（知识 026 本身待补充），所有结论都没有以它为据。
12. **小样本**：方向盘（388 谱 161 / 160 首 64）、散点（267 / 97）、长纵连（134 / 69）、定拍（490 / 202）；矩阵的"密 × 低强度"格只有 315 小节；アウトロ 51、Bメロ 360。
