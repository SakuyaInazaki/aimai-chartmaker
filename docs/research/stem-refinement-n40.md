# 分轨细化：六路分离 × 有音高 note × 高频瞬态（n = 40）

> **日期**：2026-09-12 ｜ **样本**：`out/calib/` 已有的 **40 首官方 ST 曲**
> （定数 13.0–14.5、BPM 100–260，与 `docs/research/audio-chart-calibration-n40.md` 完全同一批）
> **触发**：用户 2026-09-12「**采样的话不能只有人声和鼓点两种**」——官方谱大量踩
> 合成器主旋律、钢琴、吉他 riff、采样音效，四路管线把它们全塞在 Demucs 的 `other` 一路里，
> 而能量 onset 抓不到长音 / 分解和弦 / legato 换音。
>
> **口径警示（引用任何数字前必读）**：ground truth 仍然是 n=40 报告用的那个**代理判据**
> ——「官方 note 的时间槽在 ±30 ms 内有没有某条轨的事件」。它**不能**证明谱师"听到了"
> 那条轨，只能证明两条时间序列在 30 ms 尺度上对得上。本轮**没有做人工听审**。

---

## 0. 一句话结论

**三条新轨里只有 `piano` 真正赢了，`melody`（有音高 note）是个陷阱，人声瓶颈没动。**

| 问题 | 答案 |
|---|---|
| basic-pitch 装上了吗 | ✅ **装上了**。走 **uv + 独立 py3.11 venv（`.venv-pitch`）**，主管线子进程调用；ONNX 与 CoreML 后端**数值实测一致**，默认固定 ONNX |
| 六路分离值不值 | **一半值**：`piano` lift **2.44 > `other` 2.30**、precision 0.563 全表最高 → **赢**；`guitar` lift 1.79 < `other` → **不如不拆**；六路模型自己的 `other` 反而变差（1.81 vs 2.30） |
| 有音高 note 值不值 | **❌ 作为候选池不值**：`melody`(lead) recall 0.698 看着漂亮，但 lift 只有 **1.61**、precision **0.338**——高 recall 是**靠撒得密**换来的；人声的有音高 note（lift 1.27）比人声能量 onset（2.16）**还差** |
| `fx`（>4 kHz 瞬态）值不值 | **✅ 值，但只配当稀有点缀**：recall 只有 0.043，lift **1.99**、precision 0.460 —— 和 n=40 说的"间奏人声采样"同一种形态：**稀少但一出现就被采用** |
| 16.8% 收回了多少 | **收回 77.0%**（未解释率 16.8% → **4.0%**），**但 chance-adjusted lift 只有 melody 1.42 / fx 1.14 / pnote_vocals 1.27，guitar 0.84、piano 0.84 低于随机**——大部分"收回"是候选池灌水，不是真的找到了那些音 |
| 人声曲 ρ 前后 | **完全没动**：LOSO 40 折，人声曲 ρ **0.338 → 0.338**（把 `voiced` 换成有音高覆盖率，NNLS 照样给 **0 权重**）；试了 5 种特征组合，**三条换权重判据没有一组通过** |
| 权重换了吗 | **❌ 没换**。`intensity.py` 的 `DEFAULT_FUSION_WEIGHTS` 原样不动 |
| 切轨规划接进去之后 | **骨架持平、点缀明显变好**：骨架 top-1 **0.8522 = 0.8522**（常数基线 0.8443）；第一点缀落在段内 lift 前三 **0.528 → 0.662**（瞎猜 0.500），收益全部来自 **`piano` 进点缀候选**。⚠️ 前提是把 `melody` **踢出排序**、`fx` **单独走稀疏规则**——直接塞进去会让骨架掉到 0.826、点缀掉到 0.356 |

## 1. 方法

### 1.1 三条新轨怎么来的

| 轨 | 做法 | 动机 |
|---|---|---|
| **六路 stem**（`guitar` / `piano`） | Demucs **`htdemucs_6s`**（MIT ✅ 代码+权重），输出写 `out/calib/<曲>/stems_htdemucs_6s/`，**不覆盖已有四路缓存** | 把吉他/钢琴从 `other` 里拆出来 |
| **`melody`**（有音高 note） | **basic-pitch**（Apache-2.0 ✅）跑 `other`/`guitar`/`piano`，取**最高声部**（`lead_mask`）的 note onset 合并去重（30 ms） | 能量 onset 抓不到长音 / 分解和弦 / legato 换音 |
| **`fx`**（点缀音瞬态） | 四路 `other` stem 上只算 **> 4 kHz 频带**的谱通量 + 「该帧高频能量占比 ≥ 0.35」的相对门 | 风铃 / crash / 采样打击 / FX，全带包络里被合成器持续能量压住 |

**为什么 `melody` 必须取最高声部**：basic-pitch 是**复音**转录器，一个和弦吐 3–5 个 note。
🧪 《Signature》的 `other` 单轨吐 **3450** 个 note，而整条 drums 轨的能量 onset 只有 **476** 个。
不筛声部时（`melody_all`）40 首合计 **60003** 个候选，随机基线被抬到 **0.536**——
recall 再高也失去意义。取最高声部后降到 43873 个、基线 0.434。

### 1.2 basic-pitch：这次装上了

`docs/audio-analysis.md` §3.5 记录过两次失败（py3.12 上 `[onnx]` 报 `resolution-too-deep`、
`[tf]` 钉死的 `tensorflow-macos<2.15.1` 无 cp312 wheel）。**本轮换了装法，成功**：

```bash
pip install uv
uv venv .venv-pitch --python 3.11          # uv 自动下载独立 Python，不动系统
uv pip install --python .venv-pitch "basic-pitch[onnx]" "setuptools<81"
```

- ⚠️ **`setuptools<81` 是硬性的**：`resampy` 仍 `import pkg_resources`，setuptools ≥ 81 已删掉它，
  不钉版本会在 `import basic_pitch.inference` 时直接 `ModuleNotFoundError`。这是本轮踩到的唯一坑。
- **主管线怎么用**：新模块 `tools/audio_analysis/pitch_notes.py` **一个文件两种身份**——
  在主 `.venv` 里 `import` 时负责拼子进程命令、跑 `.venv-pitch/bin/python`、读回 JSON；
  在 `.venv-pitch` 里被 `python <file>` 执行时才真正 `import basic_pitch`。避免两边参数漂移。
- **后端**：🧪 实测 **ONNX 与 CoreML 在合成音上 note 事件逐位相同**
  （同 4 个音、onset/offset/pitch/confidence 全一致）→ `docs/audio-analysis.md` §3.5 挂的
  「三后端数值一致性 ❓」**对这两个后端可以结案**（TF/TFLite 未装、未测）。
  但 CoreML 退出时抛 `libc++abi: recursive_mutex lock failed`（coremltools 的 atexit 问题），
  批量子进程调用里这个非零退出码会污染错误处理 → **默认固定 ONNX**。
- **参数**：`onset_threshold = 0.4`（默认 0.5，放宽是因为分离后的 stem 信噪比不如干净独奏）、
  `frame_threshold = 0.3`、`minimum_note_length = 58 ms`。⚠️ **这三个值未标定**（见 §10）。

### 2.1 三条结论

1. **`piano` 是本轮唯一的干净胜利**：lift 2.44 全表第二（仅次于 drums）、precision 0.563 全表第一。
   它在 `intro`（recall 0.374、precision 0.563）与 `outro`（recall 0.325、precision **0.781**，仅 6 段）
   尤其强 —— 和 n=40 §5.5 里「intro 的 `other` 最强」是同一件事的更细分辨版本。
2. **`guitar` 拆出来反而更差**（1.79 < `other` 2.30）。合理解释：Demucs README 自己写明 6 源模型是
   实验性追加训练、**piano 源质量差**（原话 "the piano source is not working great"）——
   但实测是 **piano 好 guitar 差**，与官方说法相反 ⚠️（可能因为本曲库是日系音游曲，
   钢琴/键盘线条比吉他 riff 更贴谱面）。
3. **`fx` 是"稀有高价值"型**：recall 0.043（全表最低）但 precision 0.460、lift 1.99。
   逐段看它在 `final_chorus`（precision 0.596）与 `interlude`（0.548）最准 ——
   和 n=40 §5.5 对间奏人声采样的表述**完全同型**：**稀少，但一旦出现几乎必被采用**。

## 3. 「16.8% 什么都不落」收回了多少

📊 图：`fig1` 下半区的 lift 行是判断这一节的关键。

| 口径 | 数值 |
|---|---:|
| 官方时间槽总数（40 首） | 19883 |
| **四路口径下没被任何 stem 解释**（= n=40 报告的 16.8%） | **3642 个 / 18.3% 池化 / 16.77% 逐曲均值** |
| 新轨（`guitar`/`piano`/`melody`/`fx`/人声 note）至少一条能解释 | **77.0%** |
| **换算成占全部时间槽** | 18.3% → **4.2%**（逐曲均值 16.8% → **4.0%**） |

**逐轨收回贡献**（分母 = 那 3642 个未解释事件；会重叠）

| 新轨 | 收回比例 | **该轨独占**（只有它能解释） | **chance-adjusted lift** |
|---|---:|---:|---:|
| `melody` | **61.6%** | 32.2% | **1.42** |
| 人声有音高 note | 29.9% | 9.9% | **1.27** |
| `guitar` | 9.0% | 1.8% | **0.84** ❌ |
| `piano` | 8.8% | 1.8% | **0.84** ❌ |
| `fx` | 2.9% | 0.7% | **1.14** |

**这一节的真正结论（不要只看 77%）**：

- **`guitar` 与 `piano` 的收回率低于随机撒点**（lift 0.84 < 1）。它们能解释的那部分，
  按它们的 onset 密度本来就该撞上那么多。**六路分离没有把"漏掉的音"找回来。**
- `melody` 的 1.42 是唯一像样的数字，但它是用 **43873 个候选**换来的
  ——相当于给 LLM 的候选池里塞进比鼓轨多一倍的音。
- **所以正确的读法是**：16.8% 里**真正被新轨解释掉的**，扣掉密度红利后大约只有
  **三成上下**（1.42 ≈ 比随机高 42%）。剩下的仍然是 n=40 说的那三件无法区分的事：
  **谱师自由发挥 / 装饰音 / onset 漏检**。
- ⚠️ 逐曲差异极大：最高《ECHO》0.892、《ワールズエンド・ダンスホール》0.889；
  最低《Back 2 Back》**0.286**（它本来就只有 3.7% 未解释，分母小）。

## 4. 人声曲瓶颈：ρ 前后对照

📊 图：`fig2-vocal-rho-before-after.png`

n=40 报告 §9-A.5' 把「强度管线对人声曲几乎不管用」列为**第二个结构性瓶颈**
（逐小节 ρ 器乐 0.399 / 人声 0.146），并判断「下一轮最该补的是更好的人声 ground truth」。
本轮就是去补这个。**结果是干净的否定。**

### 4.1 单特征相关（逐小节 Spearman，Fisher 均值）

| 特征 | 全部 40 首 | **人声曲 (28)** | 器乐曲 (12) |
|---|---:|---:|---:|
| `flux`（谱通量） | **0.393** | **0.365** | **0.456** |
| `loudness` | 0.294 | 0.274 | 0.338 |
| `drums`（鼓能量 dB） | 0.213 | 0.184 | 0.279 |
| `merged6`（六轨去重合并 onset 数） | 0.194 | 0.168 | 0.255 |
| `onset`（四轨去重合并 onset 数） | 0.168 | 0.077 | **0.365** |
| **`melody_density`** | 0.168 | **0.175** | 0.154 |
| **`voiced`（现行能量 VAD）** | 0.088 | 0.099 | 0.060 |
| **`vocal_pnote_density`（人声有音高 note 个数）** | 0.073 | **0.104** | −0.001 |
| `fx_density` | 0.067 | 0.046 | 0.105 |
| **`vocal_pitched_cov`（人声有音高覆盖率）** | **−0.003** | 0.014 | −0.043 |

- **`vocal_pitched_cov` 的单项相关是 −0.003，比它要替换的 `voiced`（0.088）还差。**
  "这一小节有多少时间在唱"和"这一小节谱面多密"**基本无关**。
- `vocal_pnote_density`（唱词句读的直接代理：**音节数**）在人声曲上 0.104，
  只比 `voiced` 的 0.099 高 0.005 —— **也不行**。
- 唯一有点意思的是 **`melody_density` 在人声曲上 0.175，超过 `onset` 的 0.077**。

### 4.2 LOSO 40 折：五种换件方案，三条判据一条没过

换权重的三条判据与 n=40 §3.3 **完全相同，不得放宽**：
① 留一 CV 的 ρ 均值提高 **≥ 0.03**；② **≥ 70%** 的折胜出；③ 精确符号检验 **p < 0.05**。

| 方案 | ρ(全部) | **ρ(人声曲)** | ρ(器乐曲) | Δρ | 胜/40 | p | 判定 |
|---|---:|---:|---:|---:|---:|---:|:-:|
| **v0.4 现行五项**（基线） | 0.380 | **0.338** | 0.472 | — | — | — | — |
| A：`voiced` → 有音高覆盖率 | 0.380 | 0.338 | 0.472 | **+0.0000** | 0/40 | — | ❌ |
| B：`voiced` → 人声 note 密度 | 0.378 | 0.336 | 0.472 | −0.0017 | 13/40 | 0.038 | ❌（**显著变差**） |
| C：六项（+ 人声 note 密度） | 0.378 | 0.336 | 0.472 | −0.0017 | 13/40 | 0.038 | ❌ |
| **D：六项（+ `melody` 密度）** | 0.387 | **0.348** | 0.474 | +0.0071 | 21/40 | 0.87 | ❌ |
| **F：`onset` → `merged6`（六轨合并）** | 0.388 | **0.360** | 0.451 | +0.0083 | 23/40 | 0.43 | ❌ |

- **A 的结果最说明问题**：拟合权重与现行**逐位相同**（`onset 0.191 / drums 0.065 / flux 0.743`）——
  **NNLS 给有音高覆盖率的权重也是 0**，和它给 `voiced` 的一样。换件等于没换。
- **D 和 F 方向对但量不够**：只看人声曲，D 的 Δρ = +0.0098（胜 17/28，p = 0.34），
  F 的 Δρ = **+0.0223**（胜 **19/28**，p = 0.087）—— F 在人声曲上是**本轮唯一接近显著**的改动，
  但它在器乐曲上**倒扣 0.021**，合起来仍不过判据。
- → **`intensity.py` 的 `DEFAULT_FUSION_WEIGHTS` 原样不动。**

### 4.3 这说明人声瓶颈是什么

n=40 的判断是"**人声侧的 ground truth 不够好**，等 basic-pitch 装上再验"。
本轮把真正的人声 note 事件拿到了，结论要改：

> **不是 ground truth 不够好，是"人声活动"这个量本身就预测不了谱面密度。**
> 无论用能量 VAD（0.088）、有音高时间覆盖率（−0.003）还是音节数密度（0.073），
> 单项相关都在 0 附近；融合时被 NNLS 一律归零。

人声曲密度跟唱词句读走 —— 但**句读的"疏密"与谱面的"疏密"不同步**：
副歌唱得密的地方谱面未必密（谱师会留白避免撞词），主歌唱得疏的地方谱面靠器乐填。
**这不是一个更好的人声检测器能解决的问题**，它需要的是"乐句/句读边界"这一层结构信息，
而不是"人声有多活跃"这一个标量。

## 5. 曲目类型分类：有音高 note 也救不了

n=40 §5.3 的结论是「能量 VAD 把 10/12 首器乐曲判成人声曲，不能当分类器，改用 `share_vocals ≥ 0.10`」。
本轮拿有音高覆盖率再试一遍：

| 判据 | 40 首上的表现 |
|---|---|
| `share_vocals ≥ 0.10`（n=40 现行） | 28 人声 / 12 器乐，**已知 1 处错分**（《僕は空気が嫁ない》0.070 是人声曲但器乐极密） |
| 能量 VAD `voiced_ratio ≥ 0.5` | 与 `share_vocals` 交叉：**10 首器乐被判人声**（n=40 结论复现：本轮 3 首方向错 + 2 首另一方向） |
| **有音高覆盖率 `≥ 0.15`** | **37/40 判成人声曲** —— **比 VAD 还差** |

**根因（重要）**：`voiced_ratio` 的失败模式是「相对 dB 阈值 + 底噪」，
有音高 note **修掉了底噪这一条**，但没有修掉**另一条**——
**lead synth 本身就是有音高的**。器乐曲《超絶！Superlative》的 vocals 轨是纯 lead synth 泄漏，
它的 `vocal_pitched_ratio` 拿到 **0.516**（`share_vocals` 只有 0.003）。
《Urban Crusher [Remix]》0.474、《Jack-the-Ripper◆》0.328 同理。

→ **`share_vocals` 维持为曲目类型的判据，不换。**
有音高覆盖率只作交叉验证信号（管线里 `instrumental` 判据写成
`share_vocals < 0.10 ∧ vocal_pitched_ratio < 0.30` 的**合取**，即两者都说器乐才判器乐，
比单用 `share_vocals` 更保守）。

## 6. 人声曲副歌的 melody / vocal 复验（C1 的第二次检验）

n=40 §5.4 的 C1「副歌全踩人声」被降级为条件性+存疑，理由之一是
"器乐曲的 vocals 轨是纯泄漏也能拿 0.339 recall，代理会**制造**假的踩人声"。
本轮把**真的人声 note 事件**加进来复验：

**人声曲（`share_vocals ≥ 0.10`，28 首）的副歌 + 大副歌段，67 段 / 4080 个事件**

| 轨 | recall | precision | lift（段均） | 候选数 |
|---|---:|---:|---:|---:|
| `drums` | **0.667** | 0.589 | **2.77** | 4613 |
| `vocals`（能量 onset） | 0.249 | 0.540 | **2.27** | 1871 |
| `vocal_plus`（能量 ∪ 有音高 note） | 0.566 | 0.423 | 1.84 | 5709 |
| **`pnote_vocals`（纯有音高 note）** | 0.483 | 0.423 | **1.58** | 5785 |
| `melody` | 0.690 | 0.332 | 1.60 | 9100 |

**段内 lift 最高轨的分布（67 段）**：`drums` **45** / `vocals` 15 / 人声有音高 note 4 / `vocal_plus` 2 / `melody` 1。

**对照：器乐曲（12 首）的 22 个副歌段** —— `drums` 19 / `vocals` 2 / `vocal_plus` 1，
人声有音高 note **一次都没赢过**（而在四路代理下器乐曲的 vocals 轨还能靠泄漏拿 0.146 recall）。

**裁定**：

- **C1 维持降级，证据更强了**。即使换成真的人声 note 事件，人声曲的副歌里
  **45/67 段仍然是鼓 lift 最高**；人声家族三条轨加起来只赢 21/67（31%）。
- **但代理的失败模式确实被修掉一部分**：器乐曲的副歌里 `pnote_vocals` 再也赢不了，
  说明 basic-pitch 至少不会把**纯底噪**算成人声（虽然它照样会把 lead synth 算成人声，见 §5）。
- ⚠️ **`pnote_vocals` 的 lift（1.58）比 `vocals` 能量 onset（2.27）低**：
  把人声 note 灌进候选池会**稀释**人声轨的价值。人声侧**不要**用 `vocal_plus` 替换 `vocals`。

## 8. 切轨规划（`stemplan.py`）接新轨之后

复用 40 首的段落划分，只重算逐小节特征表并重跑 `plan_stems`，与逐段实测比一致率。

### 8.1 第一次接法（naive）：**变差了**

把 `melody` / `fx` 直接塞进候选集、沿用原来的排序量
`tendency = onset 密度 × 落格率`：

| 口径（379 段） | v0.4 四轨 | **v0.5 naive** | 常数基线（永远答 drum） |
|---|---:|---:|---:|
| 骨架 top-1 一致率（真值 = recall 最高轨） | **0.852** | **0.826** ❌ | 0.844 |
| 规划出的骨架分布 | drum 364 / hook 10 / vocal 3 / bass 2 | drum 359 / **melody 16** / hook 4 | — |
| 第一点缀轨的分布 | hook 146 / vocal 100 / bass 69 | **melody 276** / vocal 71 / hook 59 / bass 6 / fx 1 | — |

**两个病因**：

1. **`melody` 不该有当骨架的资格**：它的 lift 全表最低（1.61），却在 16 段里顶掉了 drums。
2. **`tendency` 是个纯密度量，系统性高估稠密轨**：`melody` 在 **276/379 段**里被排成第一点缀，
   而它的价值（lift 1.61）低于 `piano` 2.44 / `other` 2.30 / `vocals` 2.16。
   lift 的定义（`recall / (1 − e^{−2λτ})`）本来就是"扣掉密度红利之后还剩多少信号"，
   所以密度排序和价值排序在稠密轨上必然打架。

### 8.2 修法：四条轨、四种角色

第二次尝试（只加 `TRACK_LIFT_PRIOR` 先验）**没修好**：先验把 melody 打了 0.59 折，
但它的密度是 `other` 的 4 倍，`4 × 0.59 = 2.4` 倍，照样霸榜（232/379 段）。
→ **密度排序和价值排序在稠密轨上是打不平的**，必须按角色分名单：

```python
SKELETON_CANDIDATES = ("drums", "bass", "other", "vocals")   # melody 退出骨架候选
ACCENT_RANKED  = ("other", "vocals", "bass", "piano", "guitar")  # 参与密度排序
ACCENT_SPARSE  = ("fx",)          # 不排序，专门规则触发（与 C4「间奏人声采样」同型）
CANDIDATE_ONLY = ("melody",)      # 只进 song sheet 的候选池网格串，不进 accent_stems

tendency = onset密度 × 落格率 × lift_prior(轨)   # 先验仍保留，用于 ACCENT_RANKED 内部排序
TRACK_LIFT_PRIOR = {"drums": 2.73, "piano": 2.44, "other": 2.30, "vocals": 2.16,
                    "fx": 1.99, "bass": 1.93, "guitar": 1.79, "melody": 1.61}
```

⚠️ `TRACK_LIFT_PRIOR` 是**曲库级常数**（40 首 ST 谱、定数 13.0–14.5），**只用于候选排序**，
不进入任何硬判据；换曲库须重标。`fx` 的触发门 `0.5 个/小节` 是**可解释初值，未标定**。

### 8.3 修后结果：骨架不退步，点缀明显变好

**骨架**（真值 = 段内 recall 最高轨，四轨口径，379 段）

| 模型 | top-1 | top-2 |
|---|---:|---:|
| v0.4 四轨 | **0.8522** | 0.9789 |
| **v0.5（修后）** | **0.8522** | 0.9789 |
| v0.5 naive（melody 参选） | 0.8259 ❌ | — |
| 常数基线（永远答 drum） | 0.8443 | — |

→ **完全持平**，没有为了接新轨牺牲骨架判断。

**点缀**（第一条点缀轨落在段内实测榜的前 k，**同一把尺子**：七轨候选去掉骨架剩 6 条，
所以瞎猜的期望是 top1 0.167 / top2 0.333 / top3 0.500）

| 榜 | k | v0.4 | **v0.5** | 瞎猜 |
|---|---:|---:|---:|---:|
| 段内 **lift** 榜 | 1 | 0.2005 | **0.2322** | 0.167 |
| | 2 | 0.3879 | **0.4670** | 0.333 |
| | 3 | 0.5277 | **0.6623** | 0.500 |
| 段内 **recall** 榜 | 1 | 0.0422 | **0.1293** | 0.167 |
| | 2 | 0.3245 | **0.5330** | 0.333 |
| | 3 | 0.5515 | **0.7203** | 0.500 |

→ **v0.5 在全部 6 个口径上都赢 v0.4**，lift-top3 从 0.528（几乎等于瞎猜 0.500）
提到 **0.662**。收益全部来自 **`piano` 进候选**：

| | v0.4 第一点缀分布 | **v0.5 第一点缀分布** |
|---|---|---|
| | hook 139 / vocal 77 / bass 51 | **piano 118** / hook 95 / vocal 55 / bass 28 / guitar 20 |

**`fx` 的落点**：按 `≥0.5 个/小节` 的门，40 首里大量段落被点亮（《Signature》6 段中 4 段），
它写进新字段 `sparse_accents`，**不占 `accent_stems` 的两个名额**，
song sheet 里以 `+fx★稀有高价值` 标注。⚠️ 这条门限未标定。

## 9. 被证实 / 被推翻 / 维持存疑

### ✅ 被证实

1. **basic-pitch 可以装、可以用**（`docs/audio-analysis.md` §9-D.15 结案：uv + py3.11 + `setuptools<81`）。
2. **ONNX 与 CoreML 后端数值一致**（§9-D.15 的后半问，对这两个后端结案）。
3. **官方谱确实踩钢琴/键盘线条**：`piano` lift 2.44、precision 0.563，
   在 `intro` / `verse` / `outro` 尤其明显 —— 用户"不能只有人声和鼓点两种"的判断，
   在**钢琴/键盘**这一支上被数据直接支持。
4. **"点缀音/采样音效"确实存在且被采用**：`fx` precision 0.460、lift 1.99，
   在 `final_chorus` / `interlude` 最准。
5. **n=40 §5.5 的 C3（intro 别默认踩鼓）再获支持**：intro 的 drums recall 0.524 仍全表最低，
   `other` 0.393 与 `piano` 0.374 双双逼近。
6. **「骨架 = drums」这个底盘再次站住**：加了三条新轨之后，379 段的骨架真值分布仍是
   drums 320 / other 43 / vocals 9 / bass 7，规划一致率 0.8522 原地不动。

### ❌ 被推翻

7. **n=40 §9-A.5 的判断「下一轮最该补的是更好的人声 ground truth」被推翻**：
   补到了，ρ **一点没动**（人声曲 0.338 → 0.338，NNLS 权重仍为 0）。
   瓶颈不在检测器，在"人声活动"这个**标量本身**（§4.3）。
8. **"有音高 note ⇒ 更好的候选池"被推翻**：`melody` lift 1.61、precision 0.338，
   `pnote_vocals` lift 1.27 < `vocals` 2.16。**有音高 note 的高 recall 全是密度红利。**
9. **"六路分离能把 16.8% 捞回来"被推翻**：`guitar` / `piano` 的收回 lift 都是 **0.84 < 1**（低于随机）。
10. **"有音高覆盖率能分开人声曲/器乐曲"被推翻**：37/40 判成人声曲，比能量 VAD 还差 ——
   因为 lead synth 本身就是有音高的（§5）。

11. **「把新轨直接塞进候选集就行」被推翻**：naive 接法让骨架一致率从 0.852 掉到 0.826
    （跌破常数基线）、第一点缀落在 lift 前三从 0.699 掉到 0.356。
    **`tendency = 密度 × 落格率` 这个排序量对稠密轨是坏的**，必须按角色分名单（§8.2）。

### ⚠️ 维持存疑

12. **代理判据没变**：全部结论仍建立在「±30 ms 内有没有事件」上，**本轮没有人工听审**。
13. **basic-pitch 的三个阈值未标定**（`onset 0.4 / frame 0.3 / 58 ms`）。
    试过用 confidence 筛 `melody`（≥0.5/0.6/0.7），lift 反而从 1.61 掉到 1.46/1.42/1.51 ——
    **confidence 不是好的筛选量**，但这不等于"没有更好的筛法"。
14. **`melody` 的构造方式只试了两种**（全部声部 / 最高声部）。
    "按音高轮廓取转折点""只保留乐句首音"等更聪明的取法未试。
15. **`fx` 的 4 kHz 分界与 0.35 高频占比门是可解释初值，未扫参**。
16. **`piano` 好、`guitar` 差与 Demucs README 的说法相反**，样本只有 40 首日系音游曲。

## 11. 已知局限

1. **代理判据**：全部结论建立在 ±30 ms 时间重合上，**没有人工听审**。
2. **样本边界**：40 首全是 ST MASTER、定数 13.0–14.5、日系音游曲；
   `outro` 只有 6 段、`bridge` 4 段、`drop` 1 段，这三类的数字**不可引用**。
3. **`stemplan` 的一致率是"复用旧段落划分 + 只重跑规划"**：结构分段没有重跑，
   所以段落边界与 v0.4 完全相同 —— 这让对照更干净，但**没有检验"新特征会不会改变分段"**。
4. **basic-pitch 三阈值、`fx` 两参数、`TRACK_LIFT_PRIOR` 都只在这 40 首上成立**。
5. **`melody` 的 lift 可能被"最高声部"这个取法低估**：如果谱师踩的是内声部的节奏型，
   lead 筛选会把它筛掉。本轮无法区分"melody 本身没用"与"lead 取法不对"。
6. 六路分离的 `guitar`/`piano` 质量**没有独立评估**（没有多轨分离的 ground truth），
   只能从下游 lift 反推。
