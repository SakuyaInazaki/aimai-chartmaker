## 0. 为什么重做：用户 2026-09-19 的裁定

上一轮 `config-difficulty-intensity.md` §2.2 给每类配置算了一个合成的"内在难度分 (D+H)/2"
并排了一张 17 行的难度序。用户的裁定（原话）：

> 「大体上肯定是按照每张谱的定数和它对应的 bpm 和它的配置这样对照着来看的啊，
> 没有说一定要有什么什么配置，一个谱也不可能把所有的配置都放进去。」

所以本轮**不给配置打分、不排难度序**。能做的只有一件事：**把每张谱摊成一行
（定数 / BPM / 它实际用了哪些配置、各占多少），按定数档 × BPM 档分格，对照着看**。
"配置不是必选项"这条直接进了口径设计——**出现率**（多少张谱用了它）与
**小节占比**（用了的谱里它占多少）分开报，就是为了不把"这张谱没用某配置"读成"缺了什么"。

对应地，`config-difficulty-intensity.md` 顶部已加一段撤回声明（只加不删）。

## 1. 一句话结论

**定数往上走，谱面不是"换配置"，是"把配置种类摊开、每种都写得更久"**：配置词汇量中位
从 13.0–13.2 档的 8 种升到 13.9 以上的 12 种（ρ=+0.46，控 BPM 后 +0.45），17 类配置里 **15 类
的出现率随定数上升**；只有侧边双押真正反着走（ρ=−0.090，4 个 BPM 档一致为负），
连续双押 ρ=−0.042 是已贴天花板（各档 92–100%）的抖动。
**BPM 往上走，谱面不换配置也不加配置**（词汇量 ρ 控定数后只剩 +0.07），变的是**分音与块长**：
≥200 BPM 档 {8} 分音占 61%、{16} 只占 5%，而 <140 档反过来（{8} 19% / {16} 32%）；
配置片段切得更勤（子弹 3.2→5.5 段/分钟）但每段更短（错位从占 38% 时长掉到 12%）。

## 2. 方法与口径

### 2.1 一谱一行

- **定数**：`resource/player-preview/data/manifest.json` 的 `internal_level`（388/388 全有）。
- **主 BPM**：谱面内按 `(BPM)` 事件切段、**按占时长度**合并同值段，取**占时最长的一段**。
  变速谱在 CSV 里记全部段（`bpm_segments` 列，形如 `165@93.1s`）。
  388 谱里 **26 张变速**，主 BPM 占时比中位 0.82；其中 `916-ってゐ！`（184 段）与
  `917-東方妖々夢`（311 段）是渐变速谱，最长段只占 3–4%——对这两张另算了
  **占时加权中位 BPM** 做交叉验证，**388/388 两种口径落在同一个 BPM 档**。
- **note 总数**：解析器口径，与 manifest 官方分项 **376/387 完全一致**（97.2%，最大偏差 3），
  不一致的 11 张偏差中位 1 个 note。
- **NPS**：note 总数 ÷ 有 note 小节的合计时长。
- **小节占比**：谱内每小节都是 4 拍、同 BPM 下等长，所以"配置覆盖的小节数 ÷ 有 note 的小节数"
  **同时就是时长占比**。
- **片段数**：该配置在小节表上的**连续小节段数**（见 §2.3），并派生
  **每分钟片段数**（跨 BPM 档比较的稳健口径，见 §2.4）。

### 2.3 ★ 检测器可替换（应对手序版重写）

本模块**不直接调用** `configs.py` 的任何检测函数。"这一小节命中了哪些配置"一律经
`config_profiles.bar_config_table()` 取得，它接受三种注入，优先级
`bar_configs`（一张 `{小节: {配置名}}` 表）> `hits`（任何带 `config`/`bar_start`/`bar_end`
的片段对象或字典）> `detector`（`fn(res, slots) -> hits`），都不传才回落到 `configs.detect_all`。

因为命中只经"小节表"这一层，**片段数被重新定义为"连续小节段数"**而不是检测器内部的
`ConfigHit` 条数——这样换检测器时这个口径也不变。单测
`test_注入bar_configs时配置列只跟注入的表走` / `test_注入detector可调用且结果照用` /
`test_片段数走注入的表` / `test_build_rows可整体换检测器` 钉住了这一点。

等 `hands.py` 手序版落地、`configs.py` 按手重写之后，本报告的全部数字
**换一条命令就能原样重跑**：

```bash
python -m tools.chart_analysis.chart_matrix \
    --csv docs/research/data/chart-config-matrix.csv --json <完整结果>
```

### 2.4 两个数为什么必须分开报

- **谱面出现率** = 这一格里有多少比例的谱**用过**它（哪怕只有 1 小节）；
- **小节占比中位** = **只在用了它的谱里**取中位（不把没用的 0 拉进来）。

再加一个**每分钟片段数**，因为小节占比会被**小节粒度**放大：低 BPM 谱一小节长
（<140 档中位 1.89 秒 vs ≥200 档 1.14 秒），一次命中就整小节算进去，最小可分辨占比
在 <140 档是 1/55、在 ≥200 档是 1/110。凡是跨 BPM 档比"用得多不多"，下文都同时给
占比与每分钟片段数两个口径，**只有两个口径同向才当结论**。

**读法**：

- **NPS 在每一个 BPM 档内都随定数单调上升**（<140 档 4.20→7.11、140–169 档 5.11→7.28、
  170–199 档 5.42→8.32、≥200 档 5.55→8.36），这是全表唯一四档全单调的量。
- **{8} 与 {16} 是一对此消彼长的旋钮**：横着看（同定数档、BPM 升高）{8} 占比升、
  {16} 占比降；竖着看（同 BPM 档、定数升高）{8} 降、{16} 升。
  14.2–14.5 × 140–169 这一格 {16} 占 74%、{8} 只占 4%；13.0–13.2 × ≥200 那一格反过来
  （{8} 72%、{16} 0%）。等效速度（分音 ÷4 × BPM ÷60，知识 015）被谱师**当作一个整体量**
  在调——BPM 给多少，分音就还回去多少。
- **each 占比不随定数升**（全库 56%，13.0–13.2 档 59% 反而略高于 14.2–14.5 档的 49%）。
  同样地 slide 占比从 15% 降到 11%。**升定数靠的不是多押多星星**。
- 小节数中位随 BPM 单调升（55→110），谱长秒数却基本不动（113→124 秒）——所以
  "每小节"这个单位在不同 BPM 档下**不是同一个时间尺度**，§2.4 的两口径必要性就在这。
- ⚠️ {8} 与 {16} 两列**不覆盖三连谱**：以 {12}/{24} 为主的谱（如个案里 `454-FestivaLight` {12} 81%、
  `432-Doll Judgment` {12} 80%）在这两列上都接近 0，所以两列之和不必接近 1。
  完整分音分布在 `chart-config-matrix.csv` 的 `div4/div8/div12/div16/div24/div32` 六列。

### 3.5 每格最常见的配置组合（按"主料集"计）

每分钟片段数随 BPM 明显上升**（子弹 3.20→5.45 = +70%、连续双押 2.87→4.69 = +63%、
普通交互 1.82→3.10 = +70%、单双双单 1.67→2.27 = +36%，且 **5 个定数档全正**），
而它们的小节占比不升反降——**同一句话的两面：高 BPM 谱把配置切成更多、更短的块。**

**结论三：错位掉得最狠，而且有机制。** 错位（星星头与启动拍之间塞音，知识 017）在 <140 档
占掉 **38.5% 的时长**、片段平均长 3 小节 ≈ 5.5 秒；到 ≥200 档只剩 **12.2%**、片段 2 小节 ≈ 2.3 秒。
星星启动按"拍"计时（知识 014），BPM 越低窗口越长、越塞得下东西——这正是
**知识 003 第 4 条「低 BPM ≠ 简单」的谱面侧证据**：低 BPM 谱没法靠速度堆密度，就靠错位
把每一拍的空隙填满。反过来 ≥200 BPM 谱的 {8} 分音占 61%，密度由速度本身提供。

**结论四：真正随 BPM 走的是分音。** 见 §3.1 的 {8}/{16} 两张表——这是全表随 BPM
变化最大的量（{8} 19%→61%、{16} 32%→5%）。**BPM 与分音是一个联动旋钮，配置不是。**

分三类读：

2. **全档常驻但只当点缀（3 类）**：纵连（68%，占 4.6% 小节）、三角交互（59%，2.9%）、
   双押纵（57%，3.6%）。到处都有，但一次只给 1–2 小节。

     但在 14.2–14.5 × 140–169 那格小节占比 7.5% 最高）；

     全表住址最窄的配置；

   - **三角交互**：住址 13 格（13.3 以上全覆盖）。

4. **没有任何格子达到 50%（3 类）**：定拍（峰值 43%）、逆楼梯/方向盘（峰值 43%）、

**一句话**：能当主料的只有那六件套；几何配置全部是**高定数才请出来的点缀**，
请出来也只占 2–6% 的小节。

- 同档、BPM 243、{8} 占 83%、NPS 8.36（十例最高）。主料 4 类（连续双押 36% + 子弹 29% + 普通交互 11% + 单双双单 10%），**73 段**是十例最多——子弹单独就切出 24 段。**高 BPM 高定数 = 八分密流 + 高频切块**，错位只剩 5%。

## 7. 局限（哪些环节仍不可靠）

按"会不会改变结论"从重到轻排。

### 7.1 ★ 检测器是键位版，不是手序版 —— 全部数字待重跑

`configs.py` 现状是**按键位与时间几何**判定的（不含左右手分配）。而知识库里
交互 / 楼梯 / 大宇宙 / 方向盘 / 散点这一族的定义**本质上是关于两只手的**
（知识 018/022/023/024）。键位版只能做代理。`hands.py`（手序分配器）落地并按手重写
`configs.py` 之后，本报告的每一个数字都要重跑一遍——模块已按"检测器可注入"设计
（§2.3），重跑成本是一条命令，但**在重跑之前，§5 的四个答案都只是候选结论**。

### 7.2 ★ "配置词汇量"是 17 类透镜下的词汇量，不是谱面真实的配置种类数

`.agent/knowledge/` 目前有 **39 条配置类条目**，检测器只覆盖其中 **14 条**
（拆成 17 个标签：纵连另出长纵连、连续双押另出双押纵与侧边双押）。
死镰段 / 水神段 / 如龙段 / 二连扫 / 反手交互 / 绕手交互 / 2加1 / 3加1 / N加1 / 出张 /
混fr / 连续拍滑 / 双压连续拍滑 / CYCLES 型星星 / 菱形星星 / 夹键拍滑 / 穿心与风车 /
绕圈星星 / 一笔画 / 同头星星协调段 / 井字星星与四合院 / 同起点拍滑 / 三叉戟 /
鼓动段与防蹭段 / 拆弹 —— **这 25 类一个都没进统计**。

所以"中位 10 类、封顶 15 类"是**透镜的上限**，不是谱面的上限；
"定数每升一档词汇量 +1"这条趋势在扩大透镜后有可能变形（尤其是星星类配置，
它们在高定数谱里密度更高，会把高定数档的词汇量进一步推高，趋势方向大概率不变、幅度会变）。

### 7.3 小节粒度会放大低 BPM 档的"小节占比"

配置命中经"小节表"这一层，一次命中就把整小节算进去。<140 档每小节 1.89 秒、
≥200 档 1.14 秒，最小可分辨占比分别是 1/55 与 1/110。所以 §5.2 里
"错位占比 38.5%→12.2%"这个 3.2 倍的落差里，有一部分（粗估 1.5–1.7 倍）是粒度造成的。
报告对每一条跨 BPM 的结论都同时给了**每分钟片段数**做交叉验证，
错位（−0.062）与跳拍（−0.043）在这个口径下仍为负、但弱得多——
**"低 BPM 谱更吃错位"的方向可信，"降到三分之一"这个幅度不可信。**

### 7.4 几何族的强共现可能被检测器放大

大宇宙 / 楼梯 / 三角 / 散点 / 轴 五类在 `configs.py` 里**共用同一个前置**
（`uniform_runs(..., single_only=True)`：匀拍单点连续段）。它们两两 lift 2.0–3.4、φ 0.15–0.42
的强共现，**有多少是"谱师就这么写"、有多少是"同一段匀拍单点被五个检测器同时命中"，
本轮分不开**。要分开需要手序版检测器 + 人工复核若干片段。

同族的另一个信号：**大宇宙出现率 41%（159 张谱）** 与第一轮扫描
（`config-usage-survey.md`：严格判据下只有 **19 个谱**）差了 8 倍。两套判据都不是用户确认过的，
说明**大宇宙这类配置的检测阈值极其敏感**，它在 §5.1「随定数启用」里的位置需要用户裁定判据后复核。

### 7.5 观察性统计，没有控曲风与谱师

定数与主 BPM 在本语料里**基本独立**（ρ=+0.159），所以 20 个格子填得还算均匀，
"控 BPM 看定数"是有意义的。但**曲风、版本年代、谱师**一个都没控。
高定数谱在版本上偏新，几何配置的上升有多少是"定数要求"、有多少是"近年写法流行"，
本轮无法区分。388 张里 remas 有 56 张，也没单独分开看。

### 7.6 语料与元数据

- 语料 = 本地 388 张官方 ST 谱，定数 **13.0–14.5**。**结论不能外推到 12 级以下或 15 级**。
- note 总数与 manifest 官方分项 **376/387 完全一致**，11 张偏差 1–3 个 note（偏差中位 1）。
- 26 张变速谱用"占时最长段"定主 BPM；`916-ってゐ！`（184 段）与 `917-東方妖々夢`（311 段）
  是渐变速谱，最长段只占 3–4%。已用占时加权中位 BPM 交叉验证，**388/388 同档**，
  但这两张的"主 BPM"本身仍是一个近似。
- **分音列有杂值**：388 张里 **58 张**含非常规分音（`{3}/{18}/{30}/{36}` 这类，以及
  `{#秒}` 绝对时长记法折算出的 `{615}/{641}/{995}` 等大数）。它们占比都很小
  （最大的一张 2.6%），不影响 {8}/{16} 的趋势，但意味着**六列分音占比不会加到 1**。

### 7.7 全部阈值都是 agent 设定，未经用户裁定

主料阈值 10%（主料集共存分析另用 5%）、住址阈值 50%、格子最小样本 8、
共存分析的最小谱数 15、定数与 BPM 的档口切点——**没有一个来自用户或知识条目**。
定数档按用户给的档口切，BPM 档口是任务给定的。换阈值会改变 §5.3 / §5.4 的具体名单
（方向不会变：几何族仍在高定数角、六件套仍是底色）。

### 7.8 本轮完全不涉及"放在曲内哪里"

没有用音频。"这个配置该放在曲子的哪一段 / 多强的位置"属于
`config-difficulty-intensity.md` §2.4–2.5 的外在放置层（160 首配对曲），
本报告只回答"哪种谱会用它、用多少"，**不回答"放哪"**。

## 8. 知识条目草案（**不写入 `.agent/knowledge/`**，编号留 `NNN`，等主会话统一编号与用户裁定）

> 以下四条都基于**键位版**检测器的 388 谱统计，且只覆盖 14 条配置知识（17 个标签）。
> 手序版落地后必须重跑再定稿。

### 草案 NNN — 定数升档在配置上的含义：加种类、加时长，不换配方

- **要点**：同一 BPM 档内定数每升一档，谱面**不更换主料配置**，而是
  ①配置词汇量中位 +1 类（8→9→10→12→12，ρ=+0.46，控 BPM 后 +0.45）；
  ②在常驻六件套（子弹 / 连续双押 / 错位 / 普通交互 / 跳拍 / 单双双单）之上**叠加**
  几何配置（三角 / 楼梯 / 大宇宙 / 轴 / 散点 / 方向盘）里的 1–2 类；
  ③原有配置每类的小节占比同步上升（普通交互 11%→27%、错位 17%→28%、跳拍 8%→19%）。
- **反向**：17 类里**只有侧边双押随定数下降**（4 个 BPM 档一致为负）。
- **重要否定**：**each 占比（59%→49%）与 slide 占比（15%→11%）随定数下降**。
  升定数靠的是密度（NPS 5.26→7.79）与细分音（{16} 占比 9%→52%），不是多押多星星。
- **来源**：388 官方 ST 谱扫描（`docs/research/chart-config-matrix.md` §5.1）。
- **置信度**：**存疑**（键位版检测器；仅 14 条配置进统计）。
- **关联**：知识 003、004、015、031；条目 017–030。

### 草案 NNN — BPM 是分音与块长的旋钮，不是配置种类的旋钮

- **要点**：控住定数后，BPM 升高**几乎不改变一张谱用哪些配置**
  （词汇量 ρ 从 +0.13 掉到 **+0.07**；17 类里没有一类的出现率 |ρ|>0.21）。变的是两件事：
  ① **分音**：{8} 分音占比 19%→61%、{16} 占比 32%→5%（全表随 BPM 变化最大的量）；
  ② **块长**：配置片段切得更勤（子弹 +70%、连续双押 +63%、普通交互 +70% 段/分钟，
  5 个定数档全正），每段却更短。
- **推论**：知识 003 第 3 条「同配置 BPM 越高越强」在谱面侧的体现是
  **谱师用分音把等效速度换回来**（等效速度 = 分音÷4 × BPM÷60，知识 015），
  而不是换用更简单的配置。**"高 BPM 应避开几何配置"这条不成立**
  （三角 41%→68%、楼梯 41%→57%、大宇宙 31%→41%，方向都是升）。
- **来源**：同上（§5.2、§3.1）。
- **置信度**：**存疑**（同上；且"块长"结论受小节粒度影响，见 §7.3）。
- **关联**：知识 003（第 3、4 条）、014、015、017。

### 草案 NNN — 低 BPM 谱靠错位撑密度（知识 003 第 4 条的谱面侧证据）

- **要点**：错位在 <140 BPM 档占掉谱面 **38.5% 的时长**（片段平均 3 小节 ≈ 5.5 秒），
  到 ≥200 档只剩 **12.2%**（2 小节 ≈ 2.3 秒）；小节占比与 BPM 的 ρ = **−0.413**，
  5 个定数档一致为负，是全表最强的 BPM 趋势。
- **机制**：星星启动按"拍"计时（知识 014），BPM 越低启动窗口越长，越塞得进错位音；
  高 BPM 下塞不进，密度改由速度本身提供（{8} 分音占 61%）。
- **配套**：跳拍同向（22.4%→7.7%，ρ=−0.313）；定拍（9.2%→3.9%）与纵连（7.5%→4.4%）同向但弱。
- **谱例**（定数相近、BPM 相差一倍）：`454-FestivaLight`（13.4 / BPM 125）错位占 47% 小节；
  `825-セハガガガンバッちゃう！！`（13.3 / BPM 202）错位只占 14%，slide 占比却是前者的两倍。
- **来源**：同上（§5.2 结论三、§6 个案）。
- **置信度**：**存疑**（方向可信、幅度受粒度影响，见 §7.3）。
- **关联**：知识 003 第 4 条、014、017。

### 草案 NNN — 一张谱是「六件套当底色 + 5 类当主料 + 5 类当点缀」

- **要点**：官方谱典型用 **10 类**配置（四分位 8–12，全距 2–15），其中写到 ≥10% 小节的
  **只有 5 类**；**没有一张谱用满全部配置**——从数据侧印证用户那句
  「一个谱也不可能把所有的配置都放进去」。
- **底色六件套**：子弹 / 连续双押 / 错位 / 普通交互 / 跳拍 / 单双双单，
  在 18 个有效格里**全部**出现率 ≥50%，全库各占 12–24% 小节，是仅有的"主料级"配置。
- **点缀族**：几何配置（三角 / 楼梯 / 大宇宙 / 轴 / 散点 / 方向盘）即使在自己的峰值格里
  也只占 2–6% 小节；**方向盘的主料率是全表唯一的 0%**（388 张谱里没有一张把它写到 10% 小节）。
- **主料层面的共存与互斥**：
  - **最接近互斥**：三角交互 × 侧边双押（lift **0.28**，63 vs 65 张里只有 3 张同为主料）；
    次之侧边双押 × 散点（0.37）、双押纵 × 散点（0.62）、侧边双押 × 楼梯（0.66）。
    读作**"几何族"与"双押/侧边双押族"在主料层面基本不共处**。
  - **最强共存**：几何四人组内部——大宇宙 × 楼梯 **3.43**、三角 × 楼梯 **3.23**、
    三角 × 散点 **3.08**、三角 × 大宇宙 **2.96**；族外只有 双押纵 × 定拍 **2.01**。
  - ⚠️ 按"整张谱出现过"的松口径，**17 类里没有任何一对互斥**（最小 lift 0.88）——
    互斥只在主料口径下成立。
- **来源**：同上（§5.3、§5.4）。
- **置信度**：**存疑**（键位版；几何族共现可能被共用前置放大，见 §7.4）。
- **关联**：知识 029、030；条目 017–030。
