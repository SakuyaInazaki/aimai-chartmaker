## 0. 一句话结论

**"按手定义"不是给旧判据加一列手序，而是把一半的旧命中判成了别的东西。**
17 类共有配置在 388 谱上总命中从 42 124 小节降到 26 731（**−37%**），其中
`普通交互` −87%、`错位` −68%、`定拍` −67%、`楼梯` −75%；而这些减少**不是漏检**——
逐条拆开后 58% 的旧 `普通交互` 段根本不满足知识 018 的"每击打一次就换手"，
51% 的旧 `错位` 段里那个"错位音"被分给了**另一只手**（知识 017 明说那是打错）。
同时手序版新增 23 类键位版**原理上做不出来**的配置（星星篇 + 第二期），
覆盖 388 谱里 381 张（出张）/ 347 张（反手）/ 311 张（一笔画）。

正例召回：知识条目与 ep2/ep3 精确定位的 **43 段 ground truth，手序版 43/43 全部命中**
（键位版在它有的 16 段上 16/16）。假阳性：在三首人工逐条核对过的谱（96 段）上，
手序版在**共有配置名**下只新增 5 个小节命中（全部是 `错位`，且形态符合知识 017），
减少 125 个——**假阳性没有增加**。

### 1.1 输入与输出

输入 = `hands.assign()` 的输出，**不看原始键位串**：

```python
from chart_analysis import configs_hand as ch
hits = ch.detect_all(res)                    # [(config, bar_start, bar_end, evidence, hands_pattern, …)]
rows = ch.bar_scores(res)                    # 逐小节两个分数

```

每个片段带 `hands_pattern`（左右手角色一行速记）与 `evidence`（手级证据），
`source` 写明依据的知识条目号。CLI：

```
PYTHONPATH=tools python3 -m chart_analysis.configs_hand "133-BREAK YOU" --bars 66-66
# m066-066 [057] 一笔画
#     证据: 4 根首尾相连 1-6 → 6-2 → 2-5 → 5-1；划轨手 LLLL（一只手一路划完），闭环
#     手: L:一路不抬划完 4 根  R:专拍头（领先一拍）
```

## 2. 两个分数并存（不合成）

`bar_scores()` 逐小节同时输出、**不相加也不平均**：

- **`physical_hardness`（体力/精度）**：沿用键位版 `configs.bar_hardness` 的五项加权和
  `0.22·K + 0.22·M + 0.26·V + 0.10·U + 0.20·C`，其中 **C 换成手序版命中**的
  `CONFIG_WEIGHT_PHYS`，M 改成**按每只手自己的相邻任务**算位移（不再用"隔一个音 = 同一只手"的代理），
  U 取 `hands.py` 的绝对/硬无理数；
- **`hand_difficulty`（手的调度余量）**：直接透传 `hands.BarHand.hardness`。

外加逐小节的手序指标：`alt_rate` / `max_same_run` / `cross_count` / `chuzhang` /
`scrape` / `n_switch`（知识 054 换手的退化统计）。

**实测证据：两个分数确实是两个轴。** 160 首上曲内 Spearman（Fisher 均值）
`ρ(physical_hardness, hand_difficulty) = 0.195`；而
`ρ(音乐强度, physical_hardness) = 0.188`、`ρ(音乐强度, hand_difficulty) = 0.049`。
**音乐强度基本不通过"手更忙"传导**——这条支持 `docs/hand-sequencing.md` §5.2 的
「两个分数应当并存而不是互相替换」，并把它从"权重表相反"推进到"与外部变量的相关也不同"。

单测 `test_两个分数并存且不合成` 钉住：输出里不得出现任何合成列
（用户已撤回 `config-difficulty-intensity.md` 的 `(D+H)/2` 排序）。

### 3.1 假阳性：三首人工核对过的谱（96 段）

`sampling-mode-study.md` §2.2 在 SPICY SWINGY STYLE / Death Scythe / 幻想のサテライト
上人工逐条核对过 96 段。在**两版共有的 17 个配置名**下：

| 谱 | 片段（键位→手序） | 共有配置名下新增小节 | 减少小节 |
|---|---|---:|---:|
| `785-SPICY SWINGY STYLE-mas` | 51 → 54（共有 44 + 星星族 10） | **3**（全是 `错位`） | 21 |
| `134-Death Scythe-mas` | 101 → 96（共有 30 + 星星族 66） | **0** | 46 |
| `278-幻想のサテライト-mas` | 135 → 115（共有 50 + 星星族 65） | **2**（全是 `错位`） | 58 |

新增的 5 个小节逐条看过，形态都是知识 017 的标准形
（`5-8 头→错位音 4→启动拍（同一只手 L）`、`2^5 头→错位音 1→启动拍（同一只手 R）` 等）——
键位版漏掉它们是因为它的"双手同刻同任务"排除规则把整槽跳过了。

### 4.3 `大宇宙` 159 张 → 102 张：膨胀被压回来了多少

- **键位版**：579 小节 / **159 张谱**（判据 = 匀拍单点段里奇数位落 pair A、偶数位落 pair B，
  两对相邻键 —— 奇偶分组**隐含了严格交替手序的假设**）。
- **手序版**：324 小节 / **102 张谱**（判据 = 各手键集合恰 2 个相邻键、两集合不交、
  并集 4 键、**每只手自身的换键率 ≥0.6**）。
- **第一轮 `config-usage-survey.md` 的严格判据**：**19 张谱**。

三者的差别是**两个独立的旋钮**，不是同一个数的三个版本。把手序版的两个旋钮各拨一遍：

| 段长门槛 | 要求"每手真的横跳" | 谱数 | 小节数 |
|---|---|---:|---:|
| ≥8 槽（本轮默认） | 是（换键率 ≥0.6） | **102** | 324 |
| ≥8 槽 | 否 | 219 | 1075 |
| **≥12 槽**（survey 口径） | 是 | **33** | 109 |
| ≥12 槽 | 否 | 86 | 333 |

1. **段长门槛**：survey 要求 **≥12 槽**，本轮两版都用 **≥8 槽**（= 2 个完整循环，知识 024 没给门槛）。
   把门槛提到 survey 的 ≥12 槽，手序版落到 **33 张**——已经和 19 张同一个量级。
2. **是否要求两对键相邻**：survey 的 19 张里点名的例子包含 `{1,5}/{3,7}`、`{8,6}/{5,7}`
   这类**不相邻**的键对，即它**没有**执行知识 024「两对**相邻**键」这条硬约束；本轮两版都执行了。
   剩下的 33 → 19 的差多半出在这里与"12 槽 vs 12 音"的口径上。
3. **"每手真的横跳"这个旋钮最狠**：关掉它，102 → 219 张（翻一倍）。
   键位版的奇偶分组**等价于把它关掉**——这就是 159 张的主要来源。

手序版真正挡掉的那一类是**"每只手先敲两下 A 再敲两下 B"**——
例如 `1212-Halcyon m030` 的 `3,5,3,5,4,6,4,6`：两手的键集合确实是 `{5,6}` 与 `{3,4}`，
但 L 手打的是 `5,5,6,6` 而不是 `5,6,5,6`，**不是知识 024 说的"来回横跳（2 键 trill）"**。
键位版按奇偶分组看不出这个区别（奇数位 3,3,4,4 / 偶数位 5,5,6,6 各自只有 2 个相邻键，条件全过）。

### 草案 NNN — 「配置」有两层：谱面形状与手的分工，后者才是定义

388 谱实测：把知识 017–030 的文字定义按**手**操作化之后，17 类共有配置的命中量降了 33%，
而降掉的部分不是漏检——58% 的旧 `普通交互` 段两手根本不逐音交替、
51% 的旧 `错位` 段那个错位音落在另一只手上、26% 的旧 `错位` 段拍头与划轨已经分手（= 054 换手）。
**含义**：谱面形状（键位 + 时间）只是配置的**必要条件**；
同一串音符换一个手序就会从"普通交互"变成"反手"，从"错位"变成"换手"。
生成端按 `docs/hand-sequencing.md` §6.1 的铁律（先分手、再落 note）工作时，
**选配置 = 选两只手各自的角色**，而不是选一个形状。
置信度：agent 实测（388 谱），**待用户裁定**。

### 草案 NNN — 「体力硬度」与「手序难度」是两个近乎正交的轴

160 首音频配对实测（曲内 Spearman，Fisher 均值）：
`ρ(体力硬度, 手序难度) = 0.195`；`ρ(音乐强度, 体力硬度) = 0.188`，
而 `ρ(音乐强度, 手序难度) = 0.049`。
**含义**：音乐强度通过"写得更快、摆得更狠"传导（体力轴），**几乎不通过"手更忙"传导**；
`hand_difficulty` 最强的共变量是 `出张数`（ρ = 0.334）而不是强度。
所以两个分数必须并存、不得合成（这与用户撤回 `(D+H)/2` 的裁定同向）。
置信度：agent 实测，**待用户裁定**。
