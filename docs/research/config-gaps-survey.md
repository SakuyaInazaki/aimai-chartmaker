## 1. 菱形星星 / 类菱形星星（对应知识 052）

### 1.1 方法

教程对这个词只给了一句评价（「一个字形容就是**蹭**，无论是正攻还是邪道，能黄就是好」），

三条检索口径（**agent 操作化**，只用来找候选，结论以人读原文为准）：

| 代号 | 形态（从 simai 记法直接可读） | 388 谱里的处数 |

| **A 收口** | **同刻**两条星星，两个头键在环上**相邻**，**终点是同一个键** | **197**（59 张谱） |

### 1.3 两手分工的定性描述（agent 观察）

在上面全部 **A + B 带夹音的 115 处**里，两手的做法高度一致：

- **两只手各领一条轨道，头与条不分家**——星星头由哪只手按，那条轨道就由哪只手划
  （`hands.py` 在 6 个谱例里全部给出这个解；知识 065 允许头与条分属两手，
  但官谱在这个形态上并不使用那个自由度，唯一例外是 ④ 頓珍漢 的 `5` 与 `5-2`）；
- **被夹的音不是"某一只手顺手补"，而是两只手同时向外各扒一格再收回来**：
  B 族 **92 处里有 84 处**（91%）的夹音是**同刻成对**（双押），
  两个键分别落在两个头键的**外侧**，两手的动作完全镜像；
  A 族 23 处里 10 处成对、13 处单音（KING is BACK!! 那一串是单音的典型）；
- **夹音离头键很近**：B 族 216 个夹音里 148 个距最近的头键 **1 格**、66 个 2 格、只有 2 个 3 格；
  A 族 33 个夹音**全部**距头键 1 格。换句话说，官谱从来不把夹音扔到屏幕另一边——
  **手不用离开自己刚按下的头键太远**。

### 1.4 最重要的一条：夹音全部落在**启动拍之前**

| 族 | 带夹音处数 | 夹音**全部**落在两条轨道**开始移动之前** | 有夹音落在轨道已经在动的时候 |
|---|---:|---:|---:|
| A 收口 | 23 | **23（100%）** | 0 |
| B 交叉 | 92 | **90（98%）** | 2 |

启动拍 = `60/BPM` 一拍（知识 014），与 `{x}` 分音无关。官谱的写法是固定的三段式：

```
（第 1 格）两条星星的头同时落下            → 两手各按一个头键
（中间 1–2 格）被夹的那一个 / 那一对音      → 两手向外各扒一格，轨道还没开始动
（启动拍这一格）一对 break 或一对 tap       → 轨道同时开始走，两手同时划
```

`663-KING is BACK!!` 的 `1-5/2-5,,3,,1b/2b`、`434-日本の米は世界一` 的
`7-3/8-4,16,7b/8b`、`318-Scars of FAUNA` 的 `2-5/7-4,36,45,,2b/7b` 都是这个骨架——
**那对 break 就是启动拍的标记**。

### 1.5 与知识 052 的关系（哪些被官谱支持、哪些要改）

| 052 的说法 | 官谱普查结果 |

| 结构判据"两条同时进行的 slide 在屏幕上夹出一块狭长区域，且该区域内或紧邻处有必须击打的 note" | **方向对，但"有夹音"是少数派**：A 族 197 处里只有 23 处（12%）夹着音，B 族 746 处里 92 处（12%）。**"两条轨道夹出缝"本身太常见，不足以当判据**；真正少见的是"缝里还要打音" |

### 1.6 局限

- 轨道几何是按语法文档描述做的**折线近似**，`p/q/s/z/V` 四类误差最大（官方"始点-终点关系表"
  未逐格转录，见 `docs/simai-syntax.md` §8）；本节结论主要建立在 `-`（直线）与 `qq/pp` 上，
  受近似影响小；
- "菱形 / 类菱形"这两个名字**教程没有给定义**，本节自始至终没有去认领这两个名字——
  只描述了"两条轨道收口/交叉 + 缝里带音"这个**形态**在官谱里长什么样。
  形态与术语是否对应，仍需用户或教程原文裁定（**存疑**）；
- "同屏"用的是可视窗口的重叠，但真机上轨道的显示提前量、消隐时机未取证（**存疑**）。

### 1.7 知识草案（**agent 观察 / 存疑**，不入库、待用户裁定）

> **草案 N-1 — 两条星星夹出的缝里带音时，官谱把它塞进启动拍**
> 要点：当两条星星同刻发出、轨道收到同一个终点或在内屏交叉，而缝里还要打音时，
> 官谱 115 处中有 113 处把这个音放在**两条轨道开始移动之前**的那一两格里，
> 并用**启动拍上的一对 break/tap** 标记轨道起步。
> 手级：两手各领一条轨道（头与条不分家）；被夹的音绝大多数是**同刻双押**，

> 置信度：agent 观察（388 谱全量计数）/ 存疑（术语归属、轨道几何近似）。
> 关联：052、014（启动拍）、011（撞尾）、065（头与条可分属两手）、048（容错窗口）。

## 2. 绕手交互（对应知识 038）

### 2.1 方法

038 的定义只有教程一句话（「打起来很绕手的交互，非常吃协调」），五个谱例里只有
Blew Moon 逐帧核对过，其余四首是按达成率区间**粗定位**。本轮两步走：

1. **精确定位**：用 `findseq.py` 做**键序列匹配**——把整谱按时刻还原成键 token 串
   （同刻合并，如 `18`），在其中搜 ep2 报告记下的那几串键，命中处即小节；
2. **手级量化**：`hands.py` 逐小节给出交替率 / 同手最长连打 / 出张，另加三个
   **agent 操作化的诊断量**：
   - **键对变化率** = "(左手最后落的键, 右手最后落的键)" 这个二元组在小节内改变的次数 / 击打数；
   - **同手位移均值** = 同一只手相邻两次落键在 8 键环上的距离均值；
   - **最小覆盖弧** = 以连续 6 个击打为窗口，这 6 个键在环上的最小覆盖弧长（0–7），取小节中位数。

### 2.4 定性描述（agent 观察）

把五个谱例的原文并排看，形态是一致的：

```
Streak     m030| {16}8,   7,8,7,8,7,8,1,8,1,8,1,2,1,2,1,{8}2-5[8:1],
天国と地獄   m040| {16}7,8,7,8,7,6,7,6,5,6,5,6,5,,,,
Blew Moon  m069| 3,4,3,4,,4,5,6,5,6,,6,
トルコ      m041| 8,1,8,1,8,5,8,5,8,2,8,2,4,2,4,2,
おちゃめ機能 m034| {16}2,1,2,1,8,1,8,1,8,7,8,7,18,,,,
```

**一个两键（偶尔三键）的小交互单元被原地敲 2–3 次，然后整体挪一格或跳一次，接着再敲 2–3 次**——
单元在环上一格一格爬（Streak `{7,8}→{8,1}→{1,2}`、天国 `{7,8}→{6,7}→{5,6}`、
Blew Moon `{3,4}→{5,6}`）或者换伙伴键（トルコ 轴固定在 8，伙伴 `1→5→2`）。

两手的做法（`hands.py`）：

- **每个单元内部是干净的两手交替**，一手一个键，手型是现成的；
- **难点全在单元与单元的接缝上**：单元一挪，两只手要同时把自己的落点挪一格，
  而两只手本来就贴在一起（**两手落点相距 ≤2 格的比例 0.9–1.0**），
  所以接缝处经常出现「同一只手连着打两下」（同手最长连打 3–4）或者
  「两手在环上的前后关系翻个面」；
- **两手始终挤在三个相邻键的小片区里**——这是与 018 普通交互（键对固定）、
  021 轴交互（轴固定）、025 散点（满屏分散）都不一样的地方。

> **不得当判据硬用**（存疑）。

## 3. 正三角 / 反三角（对应知识 020）

### 3.1 方法

020 说「正/反目前区分依据**只有手感**」，文末挂着一条 agent 观察（正＝中间键起手、反＝端键起手），
标着"用户尚未确认，不作判断依据"。本轮用 `hands.py` + `configs_hand.detect_triangle`
把 388 谱的三角组全部摊到手级，看**官谱里到底有没有两种系统性不同的手法形态**。

- 三角组的口径沿用 `configs_hand._tri_valid`：3 个音一组、键集 2–3 键、弧跨 ≤3、组内转向、
  **手序 XYX**（一只手打第 1、3 个音，另一只手打第 2 个）；
- 先用键序列匹配把 020 引的两段精确定位（`findseq.py`）：
  - **正三角**：`648-アンノウン・マザーグース-mas.txt` **m060–m061**（`{12}` @222）
  - **反三角**：`311-Caliburne ～Story of the Legendary sword～-mas.txt` **m100–m101**（`{16}` @190）

### 3.2 三个全库计数（388 谱，1524 个三角组，213 张谱）

| 量 | 结果 | 读法 |
|---|---|---|
| **占 2 键 / 占 3 键** | **721 / 803** | 对半开；两类都是官谱的常规写法 |
| **起手手 L / R** | **765 / 759** | **完全没有偏好**——三角组用哪只手起手只由上一个音的位置决定（知识 067） |
| **手序** | 占 2 键 848/893 ＝ 95%、占 3 键 935/1043 ＝ 90% 是 **XYX** | 三角交互在手级上**就是两手严格交替**；一手打第 1、3 个音，另一手夹中间 |

> 注：90–95% 之外的那些不是别的手法，是段落首尾被切断造成的边界残片。

### 3.3 手级上确实存在两种形态

020 引的两段在手级上长这样（`hands.py`）：

```
648 正三角  m060| ,,3,4,2,6,5,7,2,1,3,7,
            m061| 8,6,3,4,1,6,5,8,2,1,3,7,
            R3 L4 R2 | L6 R5 L7 | R2 L1 R3 | L7 R8 L6 | R3 L4 R1 | L6 R5 L8 | R2 L1 R3
```
```
311 反三角  m100| 8-4[8:1],8,7-3[8:1],7,6,6,{16}2,4,3,7,
            m101| 5,6,1,3,2,8,6,7,4,5,3,6,2,7,1,8,
            R2 L4 R3 | L7 R5 L6 | R1 L3 R2 | L8 R6 L7
```

两边**键集是同一批**（{2,3,4}、{5,6,7}、{1,2,3}、{6,7,8}）、**手序都是纯交替 XYX**、
**起手手 L/R 各占一半**——能区分的只有**打两下的那只手，第二下往哪边挪**：

| | 648（用户标为**正**） | 311（用户标为**反**） |
|---|---|---|
| 三个音的位置次序 | **中间键 → 一端 → 另一端** | **一端 → 另一端 → 中间** |
| 第 3 个音落在哪 | 第 1 个音的**外侧** | **夹回前两个音之间** |
| 打两下的那只手 | 第二下**背离**另一只手挪 | 第二下**朝着**另一只手挪，落进对手刚划过的那一格旁边 |
| 两手的走势 | 从中间往两边**撑开** | 往中间**收拢** |
| 引文内计数 | **7/7 组全是"背离"** | **4/4 组全是"朝向"** |

（把 `d = cstep(k0,k2)`、`e = cstep(k0,k1)` 拿来比符号就能判：同号＝朝向、异号＝背离；
占 2 键时 `d = 0`，不参与正反。这是 **agent 的操作化**，不是术语。）

### 3.4 这两种形态在 388 谱里的分布

| 层级 | 结果 |
|---|---|
| **组级**（803 个三键组） | 背离 **410** / 朝向 **393** —— 对半开 |
| **段级**（含 ≥3 个三键组的 37 段） | 分布是 **U 形**：全朝向 6 段、0.2–0.4 共 8 段、**0.4–0.6 只有 2 段**、0.6–0.8 共 5 段、全背离 16 段 → **一段之内基本只用一种** |
| **谱级**（含 ≥4 个三键组的 88 张谱） | 朝向为主 **14** 张、背离为主 **17** 张、**两种混用 57 张** |

→ **在段落这一层，两种形态是可区分的、而且官谱倾向于一段只用一种**（37 段里 22 段是纯的，
中间地带只有 2 段）；**但在整谱这一层多数是混用的**，所以"正/反"不是把官谱分成两族的分界线。

### 3.7 局限

- **切组的相位有歧义**：一串匀速单点切成三个一组有三种切法，选哪一种由"哪种切法能切出更多合法三角组"
  决定（`_tri_chains` 的做法）。311 m100 就因为检测器的连续段**越过了 020 的引文边界**
  （多吃进后面的 `4,5,3`），把 4/4 朝向算成了 3/4；按 020 引文切就是 4/4。
  **凡是跨过引文边界的计数都不可靠**（准则 9）；
- **"朝向/背离"是 agent 为本轮定义的量**，与用户口中的"正/反"是否同一件事**未经确认**；
  用户明确说过这个区分"只有手感、还没认真思考"，所以本节**只报告官谱里能数出来的结构差别**，
  不认领"正三角/反三角"这两个名字；
- 手感（顺 / 卡 / 累）本轮**完全没有取证**，也无法取证；
- `detect_triangle` 要求手序 XYX，所以"三个音被分成 1+2 或 3+0"的变体不在统计内

## 4. 似踩非踩（MMFC 5.3）

### 4.1 MMFC 原文与定义

`resource/mmfc-guide-extracted.txt`（第 51 页，章节归属 **5.3 踩音与配置**，页眉印的是 5.4）：

> 「海底谭的副歌采用了一种**似踩非踩**的写法，**全程铺满 8 分音符**」

上下文（同段）：MMFC 先把 ウミユリ海底譚 副歌的谱面拆成"踩音"与"配置"两层，踩音层写成
`（120）{8}x,x,x,x,x,x,x,x,`，然后问「**他不选择踩最明显的人声是为了干什么呢？为了写配置**」——
接着引出"海底谭星星"。

→ **似踩非踩 = 谱面按匀速分音把一小节铺满，而这些音并不是去跟某条音轨实际发出的音；
腾出来的表达位交给配置。** 它不是"不踩"（留白），也不是"只踩一部分"（舍音）。

**MMFC 原例在本地官谱里的位置**：`resource/official-chart/336-ウミユリ海底譚-mas.txt`
**m030–m031**（`{8}` @120BPM；同形在 **m060–m062** 的第二次副歌再现，星星换成 `^` 弧）：

```
m030| {8}2,1/8-4[8:1],7,1-5[8:1]/8,2,1/8-4[8:1],7,1-5[8:1]/8,
m031| {8}2,1/8-4[8:1],7,18,2,18,7,18,
m060| {8}3,2/7^4[8:1],6,7/1-5[8:1],2,1/8-4[8:1],7,8/2^5[8:1],
```
一小节 8 个格子**一个不空**，穿心星星逐格换头——这就是 MMFC 说的"踩音层 `x,x,x,x,x,x,x,x`"。
（本地谱与 MMFC 引文相差一个格子的对齐，内容同形。该曲**本地没有音频**，故只能作形态锚点。）

### 4.2 方法（160 首带音频的曲目）

谱面侧（只看谱）：把每一小节的**击打时刻**取出来，若相邻间隔**等距**（相对离散 <2%）
且 ≥8 个时刻，就记为"匀速铺满"，并记下每拍几格。
音频侧：直接取 `tools/calibration/sampling.py` 的 `--diagnostics` 字段
（`coverage` / `extra_ratio` / `n_pool` / `n_slots`，逐小节，口径见该模块文档）。

> ⚠️ 下面出现的切点（"等距"的 2%、"铺满"的 ≥8 格、`extra_ratio ≥ 1/3`）
> **只用来把候选捞出来**，不是判据、不是术语；结论一律只写定性。

### 4.3 第一个结果：线索的方向和原来记的相反

`docs/research/sampling-terminology-survey.md` §未找到 第 6 条推测似踩非踩会落成
"**骨架轨 coverage 低 + extra 高**"。160 首实跑下来**不是**：

| | 匀速铺满的小节（1377） | 其余小节（11633） |
|---|---:|---:|
| coverage 中位 | **0.92** | 0.67 |
| extra_ratio 中位 | **0.12** | 0.00 |
| 每小节时间槽中位 | 8 | 5 |

**铺满会把音轨那点音全都顺手盖住**（所以 coverage 反而高），
真正露馅的是 `extra`——铺出来的格子里有一大批**任何一条 stem 都对不上**。
所以似踩非踩的指纹是 **「coverage 高 + extra 高」**，不是"coverage 低 + extra 高"。

按 `extra_ratio ≥ 1/3` 取尾：**314 个小节、84/160 首**（超过一半的曲子用过）。

### 4.5 官谱怎么用它（定性）

- **它不是罕见写法**：160 首里 **84 首**至少用过一次；但**成段连用**（≥3 小节）的只有 12 处、
  ≥4 小节的 7 处——多数时候它是**一两小节的过渡填充**，不是整段的基调；
- **段落偏好**：在"匀速铺满"的小节里，extra 高的比例按段落排是
  **落ちサビ 0.30 ＞ Bメロ 0.28 ＞ イントロ 0.27 ＞ 間奏 0.24 ＞ Aメロ 0.22 ≈ サビ 0.22 ＞
  ドロップ 0.13 ＞ ラスサビ 0.11**。→ **最强的那两类段落（ラスサビ / ドロップ）反而最不用它**；
  它集中在**落ちサビ、前奏、间奏、Bメロ**这些"要有推进感但不该抢戏"的位置；
- **它和强度无关**：候选小节的段落强度中位 **0.78**，与全部匀速铺满小节的 **0.79** 没有差别——
  **似踩非踩不是"低强度铺底"专用**，高强度段一样在用（`初音ミクの激唱` 的落ちサビ、
  `Got more raves？` 266BPM 的 Aメロ）；
- **骨架轨**：314 个候选里 **225 个**的目标轨是 drums——铺满时最像"在跟"的那条轨仍是鼓，
  这与知识 032「鼓骨架 + 非鼓填充」一致，只是这里填充的比例被推到了极端；
- **分音**：`{16}` 116 / `{8}` 107 / `{12}` 55 —— MMFC 说的"8 分"只是它举的那一例，
  官谱在 8 / 12 / 16 分上都这么写；
- **定数**：13 档 89 / 14 档 225（本语料 13.0–14.5），没有"只有低难度才这么写"的迹象。

### 4.7 对 `sampling.py` 的建议（**只写建议，本轮不改代码**）

1. **把「似踩非踩」作为第四个社区用词写进模块文档**（不新增分类、不动算法）。
   它有明确出处（MMFC《谱面创作基础学》5.3），不是 agent 自造词，可以和
   「全踩 / 舍音 / 留白」并列列在模块 docstring 的社区用词清单里，注明：
   > **似踩非踩**（MMFC 5.3）：谱面按匀速分音把小节铺满，而这些音并不对应音轨实际发出的音。
   > 「海底谭的副歌采用了一种似踩非踩的写法，全程铺满 8 分音符」。
2. **在 `classify()` 的文档里写明它藏在哪**：「`全踩` 这一档里混着一部分其实是**似踩非踩**——
   铺满把音轨的音全盖住了，所以 `coverage` 高；要把它认出来得看 `extra_ratio`
   （谱面格子里对不上任何 stem 的比例）。」
3. **`--diagnostics` 的表头可以顺带提示**：现在 `extra` 这一列没有解释，
   可以在打印的表头或 CLI 帮助里注明它是"采空音/插空音"的诊断量，
   并且**它高不等于谱写坏了**——成段的高 `extra` 恰恰是似踩非踩这种正规写法。
4. **不建议做的事**：不要把似踩非踩做成第四个互斥档位去切 `extra_ratio`。
   社区没有把这四个词当一组互斥分类用；而且"铺满得多满算铺满"一旦定阈值，
   就又回到用户 2026-09-20 批评过的那条路上去了。

### 4.8 局限

- **`extra` 是代理**：它含谱师自由发挥、装饰音、**以及 onset 漏检**，三者分不开
  （知识 032 的老问题）。本节所有"对不上音轨"的说法都受这一条限制（**存疑**）；
- **MMFC 的原例没有音频**（ウミユリ海底譚 不在 160 首里），所以"定义"与"度量"之间
  少了一次直接对照；本节只能用形态相似的曲目替代；
- **"匀速铺满"是谱面侧的机械判据**，会把一部分本来就该那么密的段落（真的每个八分都有鼓点）
  一起捞进来；本节靠 `extra` 再筛一道，但没有人工听审，**不能保证每一处都是 MMFC 说的那回事**；
- 段落标签来自管线的自动分段（`all-in-one` + SSM 投票），本身有误差。
