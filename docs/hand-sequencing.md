## 1. 核心对象：任务（task），不是 note

"手"分配的最小单位不是 note，而是**需要占用一只手的原子任务**。
一个 note 可能产生 0、1 或 2 个任务，两个任务也可能被一只手一次吃掉。

| 任务类型 | 来自 | 开始时刻 | 占手到 | 依据 |
|---|---|---|---|---|
| `tap` | `tap` | note 时刻 | +1 帧（16.67 ms） | 006 |
| `hold` | `hold` | note 时刻 | 尾 +1 帧（尾部放宽 `hold_release_slack`） | 006 / 012 |
| `star` | `slide_star` | note 时刻 | +1 帧（星星头**按 Tap 处理**） | 006 |
| `slide` | `slide_track` | **头 + 60/BPM（启动拍）** | 名义终点（可提前 `slide_release_slack` 放手） | 014 / 048 |
| `wifi` | `w` 形滑条 | 同上 | 同上，但**同时占用两只手** | 006 |
| `touch` / `touch_hold` | Touch | note 时刻 | +1 帧 / 尾 +1 帧 | 006（TouchGroup 未实现，见 §7） |

**两条合并规则**（都来自知识 006「启动拍上的 Tap（拍划）并入划动手法，不单独占用一只手」）：

1. **拍划（tap）**：落在某条轨道启动拍上、与该轨道**头键相同**的 Tap → 并入该轨道任务；
2. **拍划（星星头）**：落在启动拍上、与头键相同的**另一条 slide 的星星头** → 同样并入。
   知识 006 同时规定"星星头按 Tap 处理"，所以星链（一圈星星头连续飞出、049 连续拍滑、
   057 一笔画）里"划到某键的同时按下该键上的新星星头"是**一次按压兼两件事**。
   ⚠️ 这条是把 006 的两句话合起来推出的（agent 推断，存疑），但**它是官方谱能跑通的前提**：
   不并入时 388 谱出现 4 455 次"占用冲突"，并入后降到 136 次（见验证报告 §3）。

**★ 拍星星头的手 ≠ 划轨道的手**（知识 054）。本模型把 `star` 与 `slide` 建成两个**独立可分配**
的任务，二者落到不同手只是一项代价（`w_star_switch`），不是禁止。知识 054 的换手阶梯
（11.8 → 13.5）与知识 007 定式 3（死镰）都要求这一点。

**★ slide 的占手是可伸缩区间**（知识 014 + 048）：

```
[ 最早开始 = 星星头 + 一个四分音符(60/BPM) ,  最晚结束 = 引导星到终点 + 15 帧(≈250 ms) ]
```

任务上记三个量：`t`（启动拍）、`t_end_nominal`（匀速到达终点）、`t_end_max`（名义尾 + 容错）。
**占用冲突判定用弹性下界**（允许"提前快滑" `slide_release_slack` = 250 ms 放手），
**移动代价仍按名义尾算**（保守）。知识 048 说这一窗口是星星篇一半以上"邪道手法"
（提前快滑 / 留尾 / 撞过去）的物理基础。

## 2. 状态与搜索

**状态**（每一步之后）：

```
(左手: 键位 K_L, 名义就绪时刻 R_L, 弹性余量 E_L)
(右手: 键位 K_R, 名义就绪时刻 R_R, 弹性余量 E_R)
last_hand        # 上一个"单任务时刻"归谁（交替先验用）
pending          # {轨道任务 → 打下它星星头的那只手}（一笔画/换手代价用）
```

**推进**：把任务按时间分组（容差 `simul_tol` = 4 ms，伪 each 的 1 ms 偏移算同刻），
逐组做 Viterbi 式转移。一组内枚举全部合法分配向量：

- 1 个任务 → `L` / `R`；
- 2 个任务 → `(L,R)` / `(R,L)`；若两键相邻且都是 tap/star，另加 `(L,L)` / `(R,R)`
  （知识 036 的"一只手一次刷过两个相邻键"，代价 `w_sweep_pair`）；
- Wifi → `LR`（双手），同刻其余任务判多押；
- ≥3 个任务 → 只能挑两个给两只手，其余记 **多押无理**（知识 008）。

**剪枝**：按状态去重 + 保留代价最低的 `beam` = 48 条。388 谱全量 45 秒。

**起手自由度**：`force_first_hand` 可强制首个任务的手。全库实测两种起手的**全谱**
代价差中位数只有 0.08%（§验证报告 §6），因为分页先验会在一两小节内把两手重新锚定。
⚠️ 知识 060 说的是**段内**起手奇偶（"相反起手能规避出张"），**逐星星段的起手枚举尚未实现**，
见 §7 扩展点 4。

## 3. 代价项

每把一个任务交给一只手，累加以下各项（全部可关：把权重置 0）。

| 记号 | 代价项 | 公式 | 知识依据 |
|---|---|---|---|
| P | **分页先验** | `w_page × 越界深度(手, 键)` | 006（右手 1234 / 左手 5678）+ 023（右手够到 5/8，够不到 6/7 → 深度 2） |
| P' | 轨道尾部分页修正 | `w_page × (深度(尾) − 深度(头)) / 2` | 划轨手要把整条轨走完（agent 推断） |
| M | **位移** | `w_move × 环距 / 4` | 003-2（位移越大越难） |
| V | **速度** | 见下 | 015 |
| A | **交替先验** | 上一个单任务同手 → `+w_same_hand`；同键且在舒适速度内再 `+w_same_key_extra`（**负值**） | 018（交互=逐音换手）、019（快纵连要"拆"）、027（定拍一手守住） |
| S | **末尾半边** | 划轨手不在 slide 末尾半边 → `+w_slide_end_side`（**打分项，不是硬约束**） | 007 + ep3 §6.1-3（"该换手的地方不换也能打"） |
| H | **星头换手** | 划轨手 ≠ 拍头手 → `+w_star_switch` | 007 一笔画偏好；054 说明它**允许**发生 |
| C | **一笔画续划** | 上一动作正好停在本轨道头键、时间首尾相接（±`chain_tol`）→ `+w_chain_bonus`（**负值**），且**免除 S 与 H** | 007「划 slide 的手开始后不停」；057 |
| G | **错位先验** | 落在某 slide 启动拍等待期、且贴近其星星头的音符给了**非划轨手** → `+w_misalign_other` | 017（"错位音固定由滑动的那只手自己拍"） |
| U | **无手可用** | `+w_unassigned` 并记多押 | 008 |
| W | 一手扫同刻相邻两键 | `+w_sweep_pair` | 036 |

### 速度项（单手移动时间模型）

```
舒适线   t_req(d)  = t_hit_min + t_per_key · log2(1+d)
扫键舒适线（d=1）  t_sweep_req
硬下界   t_hard(d) = t_hard_same (d=0) ;  max(t_hard_floor, t_hard_floor + t_hard_per_key·log2(1+d)) (d≥1)

dt = 本次出手时刻 − 上一动作名义结束时刻
dt ≥ t_req             → 0
t_hard < dt < t_req    → w_speed × ((t_req−dt)/(t_req−t_hard)) ^ speed_exponent      （凸，越贴线越陡）
dt ≤ t_hard            → 不可行（超速无理）
```

**`t_hit_min = 83.3 ms` 的来源**：知识 015 给出官谱最快同键纵连 = 白系 177.6 BPM 的 32 分
（间隔 42.2 ms）。知识 019 说这种长纵连"绝大多数玩家采用拆"——两手拆打则**单手 84.4 ms**。
取 1/12 s = 83.3 ms 作单手连续击打的下界，正好卡在这条官谱纪录上（比值 1.013）。

**扫键**：知识 015 另给出扫键纪录（怒锤 200 BPM 64 分 = 18.75 ms、白日舞 96 分圈 = 24.5 ms），
与距离无关，所以 `t_hard_per_key = 0`、`t_hard_floor = 18.7 ms`。相邻键在舒适线以下时按
**扫键模式**计价（`w_sweep_step`），对应知识 036「你写下的是 note 序列，玩家可能用扫键一次吃掉两个」。

## 4. 无理判定，以及"蹭的压力"要跟无理分开

知识 048 之后必须区分两件事：

- **`muri`（无理）**：人类正规手法**办不到**或**必须改手法**才办得到 → 硬性验收项（AGENT.md 标准 2/3）；
- **`scrape_pressure`（蹭的压力）**：星星篇里大量的"蹭"是**设计手段**（知识 048「能黄就是好」、
  052 菱形星星"一个字：蹭"、062 防蹭段），**不是无理** → 只作强度/风格指标。

实现口径：**软级**的 `撞尾` / `外键` / `路径蹭键` / `换手拧巴` 归 `scrape`，硬级与绝对级留在 `muri`。

| 标记 | 级别 | 判据 | 知识 |
|---|---|---|---|
| **多押** | 绝对 | 同刻需要 ≥3 只手 | 008 |
| **叠键** | 绝对 | 同一键两 note 间隔 < 33.3 ms | 009 |
| **占用冲突** | 绝对 | 两手都被占住还来任务（整组不可行） | 006/012 |
| **超速** | 绝对/硬 | 单手 `dt ≤ t_hard(d)` / 贴线 > 75% | 015 |
| **Hold 尾多押** | 硬 | Hold 名义尾 ±50 ms 内有同刻 ≥2 note | 012（"Hold 尾判 + 同时双押 = 标准多押"） |
| **外键** | 硬/软 | **启动拍**后 200 ms 内、**同一个键**上出现由**非划轨手**处理的 Tap/Hold；gap ≥150 ms 或 ≤50 ms 或带 Ex → 软 | 010（+ 388 谱校准，见下） |
| **撞尾** | 绝对/硬/软 | 轨道名义到达终点 ±(−50, +200) ms 内该键出现非划轨手的 Tap/Hold；踩在到达时刻=绝对；0–150 ms=硬；正好一个八分且 BPM ≤ 210 → 软 | 011 |
| **路径蹭键** | 软 | 弧形轨道途经的 A 区在经过时刻 ±60 ms 内有非划轨手的 note | **agent 推断，存疑**（033 的"防蹭"） |
| **换手拧巴** | 软 | 同刻左手在右半圈且右手在左半圈、交叉深度 ≥3，且前后 1 s 内两手都没划过 slide | **agent 推断**（007 定式 4 的换位划不算） |

> **★ 知识 010 的"同头（同侧）"在 388 官谱上校准为"同一个键"、窗口锚在启动拍。**
> 四种读法全量跑过（验证报告 §3.4）：按"环距 ≤1 + 锚在星星头"读，388 官谱出现 832 次硬外键；
> 按"同键 + 锚在启动拍"读只剩 13 次。官方谱不会系统性地写硬无理，所以取后者。
> 这是对条目 010 的**校准建议**，不是推翻。

## 5. 17–30 各配置的手级定义（`configs.py` 按手重写的规格）

> **读法**：「L / R 只是记号」——实际落哪只手由 006 分页与段首起手决定，表里写"守 A 的手 / 走 B 的手"。
> **机检判据**一列直接消费 `hands.assign()` 的输出（`left_seq` / `right_seq` / `pairs` / 逐小节指标），
> **不再看原始键位串**。
> 置信度：**用**＝用户讲授、**谱**＝官谱实证（本轮分配器在条目点名的谱例上复现）、**推**＝agent 推断存疑。

| # | 配置 | 左手做什么 / 右手做什么 | 时序关系 | 可机检判据（手级） | 置信度 |
|---|---|---|---|---|---|
| **017** | 错位 | **划星的那只手一个人干完**：头 → 错位音 → 启动拍（拍划）→ 划轨；另一只手同刻在另一条星星线上干同样的事 | 两条星星线相位差一拍，环环相扣 | 存在 slide 任务 T，其 `wait_of` 窗口内有任务 X，且 `hand(X) == hand(head(T)) == hand(T)`，且 X 的键 ≠ T 的头键 | 用+谱 ✅ |
| **018** | 普通交互 | 两手严格逐音交替，各守本方分页 | 匀拍 | 连续 ≥6 个单任务槽，`alt_rate == 1.0` 且 `max_same_run == 1`；跨半圈数 = 0 | 用+谱 ✅ |
| **019** | 纵连 | **同一键上两手交替**（"拆"）；慢速时允许一手连打 | 同键连续 ≥3 音 | 同一键连续 ≥3 个任务；`一手连打` 与 `两手交替` 由 `t_req(0)=83.3 ms` 分界；长纵连（>5）看 `max_same_run` | 用+谱 ✅ |
| **020** | 三角交互 | 每 3 音一组，组内两手交替（占 2 键时一手打两次，占 3 键时三音三键） | 组间有空拍或匀速 | 按 3 音切组；组内手序为 `XYX`（占 2 键）或 `XYX`/`XY?`（占 3 键）；正/反三角的手级差别**未找到**（见 §7） | 用+谱 ⚠️ |
| **021** | 轴交互 | **一只手钉在轴键**、另一只手打两侧邻键 | 轴音隔位重复（BABCB） | 某手的键序列常量（`len(set)==1`）而另一手在 ≥2 个键上摆动，交替率 = 1 | 用+谱 ✅ |
| **022** | 楼梯交互 | 两手**反向**移动，成对推进、每步只走相邻键 | 成对 | 相邻同手步进 `cstep` 恒为 +1 或 −1，且两手符号**相反**；走向切换处出现一次"飞"（同手 d ≥ 2） | 用 ✅（本地无谱） |
| **023** | 逆楼梯 / 方向盘 | 两手**同向**移动、**始终 180° 对位** | 同步 | 每个同刻/相邻对满足 `cdist(L,R) == 4`，且两手 `cstep` 符号**相同**；必有折返 | 用+谱 ✅ |
| **024** | 大宇宙 | **每只手在自己那对相邻键上横跳** | 两手交替 | 各手键集合大小 = 2 且组内 `cdist == 1`；两手键集合不交；两集合并起来恰 4 键 | 用+谱 ✅ |
| **025** | 散点 | 两手交替但**都不收敛到固定小键集** | 匀拍 | 交替率高但每手键集合 ≥4、同手步进种类 ≥3，且不满足 022/023/024 的手级条件 | 用 ⚠️ |
| **026** | 跳拍 | 手序本身不特殊，**空拍不规则** | — | 任务间隔序列的取值种类 ≥3（手序层无特征）→ **跳拍不是手级配置**，应留在时间层判 | 用（概念版） |
| **027** | 定拍 | **一只手在一个键上从不歇**（节拍器）；另一只手处理别的配置、可以有空拍 | 定拍手密度可达另一手的两倍 | 某手键序列常量且**槽槽都有**，另一手同窗内有空槽；与 021 的区别 = 定拍手**不参与交替结构**（相邻两次之间**不一定**夹着另一手的音） | 用+谱 ✅ |
| **028** | 子弹 | 同一键短时间两次：可同手连打、也可两手各一次 | 间隔 ≤ 半拍 | 同键恰 2 次且间隔 ≤ `bullet_gap`；记录是否同手（同手=真连打，异手=分摊） | 用+谱 ✅ |
| **029** | 单双 / 双单 / 夹心 | 双押时两手同刻；单点时一只手（通常是"变化"的那只）出手 | 双击与单点交替循环 | `pairs` 与单任务槽交替出现；"骨架"= 在双押与单点中**键位不变**的那只手 | 用+谱 ✅ |
| **030** | 连续双押 | 连续 ≥3 个 `pairs`；两手各守一侧 | — | `pairs` 连续 ≥3；**双押纵** = 两手键都常量；**绕圈** = 两手同向逐格推进；**侧边双押红线** = `{L,R} ∈ {{2,3},{6,7}}` 且前后无共享键引导 | 用+谱 ✅ |

### 5.2 一条横贯结论

**「几何越规整的配置，手序越省心」** —— 388 谱实测（验证报告 §7）：
方向盘 0.205、大宇宙 0.227、长纵连 0.234、三角 0.244、楼梯 0.256 是**手序难度最低**的一批；
侧边双押 0.515、错位 0.444、单双 0.374 最高。这与 `configs.py` 现有 `CONFIG_WEIGHT`
（大宇宙 1.00 排第一）**几乎相反**，说明二者量的是**两个不同的轴**：
`CONFIG_WEIGHT` 量的是体力/精度负担，手序难度量的是**手的调度余量**。
按手重写 `configs.py` 时，这两个分数应当**并存**而不是互相替换。

## 6. 与生成端的对接

### 6.1 铁律：**写谱时必须先做手分配，再落 note**

不能"先把 note 摆好再检查手序"——那样只能事后发现无理、无法修。正确顺序：

```
段落计划（song sheet：结构 × 强度 × 踩音轨）
   ↓
① 选配置（按手级定义选：这一段两只手各承担什么角色）
   ↓
② 分配手角色与起手（哪只手是骨架/定拍/划轨手；段首起手的奇偶）
   ↓
③ 按角色落 note（把每只手的键序列写出来，再交织成 simai）
   ↓
④ hands.assign() 回读校验 → 绝对/硬无理必须为 0，软无理与 scrape_pressure 记录
   ↓
⑤ 语法校验（docs/simai-error-checking.md §10）
```

### 6.2 song sheet / charting plan 的字段建议

在 `song_analysis.json` 的逐段落计划里增加 `hand_plan` 块：

```json
"hand_plan": {
  "config": "定拍",              // 手级配置名（§5 的表）
  "role_a": {"hand": "R", "job": "定拍", "keys": [2], "density": "每槽"},
  "role_b": {"hand": "L", "job": "变化", "keys": [6, 8], "density": "每两槽"},
  "start_hand": "R",             // 段首起手（知识 060：奇偶影响出张）
  "slide_owner": "role_b",       // 划轨手（知识 007 末尾半边 → 打分项）
  "budget": {"chuzhang": 2, "scrape_pressure": 4, "muri": 0}
}
```

生成端的硬约束只有一条：**`budget.muri` 必须为 0**（绝对与硬级）。
`chuzhang` 与 `scrape_pressure` 是**风格预算**，允许按段落强度调高——
知识 048/062 明确"蹭"是设计手段。

### 6.3 对外 API（`tools/chart_analysis/hands.py`）

```python
from chart_analysis.hands import assign, bar_hand_sequences, chart_summary

ha = assign(parse_chart(text))      # 也接受 list[NoteEvent]
ha.rows            # [(t, bar, key, note_type, hand, occupancy_until), ...]
ha.left_seq        # [(t, bar, key, task_kind), ...]
ha.right_seq
ha.pairs           # [(t, bar, 左手键, 右手键), ...] 同刻双手对
ha.bars            # [BarHand] 逐小节：alt_rate / max_same_run / cross_count /
                   #   chuzhang / max_speed_l,r / conflicts / muri / hand_hardness
ha.muri            # 无理（绝对/硬）
ha.scrape          # 蹭的压力（软）
ha.infeasible      # 不可行事件（带原因，绝不静默）
ha.total_cost, ha.hand_hardness
bar_hand_sequences(ha)   # {bar: {"L": [(t,key,kind)], "R": [...], "pairs": [...]}}
chart_summary(ha)        # 全谱一行，CSV 口径
```

CLI：

```
PYTHONPATH=tools python3 -m chart_analysis.hands <chart.txt|关键字> [--bars a-b] [--json]
python3 -m tools.chart_analysis.hands "336-" --bars 30-31      # 仓库根下亦可
```
