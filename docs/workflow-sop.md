## 0. 一页流程图

```
① 用户给 mp3 + BPM/offset/变速点 + 目标定数
        ↓
② 音频分析（tools/audio_analysis）→ song_sheet.md + song_analysis.json + plot.png
        ↓
③ 读知识库（.agent/knowledge/，写谱前必读；AGENT.md 准则 8）
        ↓
④ 段落规划：每段定「强度档 / 骨架·点缀 / 采音方式 / 配置族 / note 种类配比」
        ↓
⑤ 手序规划：每段定「左手做什么、右手做什么、谁起手」（hand-sequencing §6.1 铁律：先分手再落 note）
        ↓
⑥ 写 simai（逐段，一行一小节）
        ↓
⑦ 检查（tools/chart_check）→ 语法 / 手序 / 配置 / 密度 / 采音 五层
        ↓
⑧ 迭代：错误清零 → 逐条看警告 → 逐条过提示（提示不判对错，但要能解释）
        ↓
⑨ 交付：maidata.txt + 检查报告 +（可选）过程记录
```

## 1. 输入与前置

**用户提供**（`docs/audio-analysis.md` §2.2：用户给的 BPM/offset 是最高优先级）：

- `track.mp3`；
- **BPM**、**offset（`&first`）**、**变速点**（有就给）；
- **目标定数**（决定密度锚、note 总数区间、配置族换档）。

**agent 不做的事**：不自己定 BPM/offset（管线只做**反向校验**、只报告不覆盖）。

> ⚠️ 注意事项（试写踩到的）：**没有目标定数就不要开工**。定数同时决定
> 知识 004 的 note 总数区间、知识 031 §7 的 NPS 锚、知识 071 的星星族换档
> （低定数写「接得顺」的，高定数写「要分手 / 要防蹭」的）。

## 2. 音频分析

```bash
python3 -m tools.audio_analysis <track.mp3> --bpm 162 --first 0 --level 13.6 --out out/<曲名>
```

产出三件：

| 文件 | 给谁 | 里面有什么 |
|---|---|---|
| `song_sheet.md` | 给写谱的模型 | Header（BPM/offset 校验、分音统计、目标 note 总数与密度锚）、§1 段落表（强度 / 骨架 / 点缀 / 建议密度）、**§1.5 写谱提示层**（建议配置族 / 采音建议 / 手序提示）、§2 逐小节四轨网格串、§3 已知限制 |
| `song_analysis.json` | 给程序 | 同源数据；`tools/chart_check` 的采音层直接吃它 |
| `plot.png` | 给人 | 强度曲线 + 段落边界 + stem 活动度 + 逐小节分音，**复核用** |

> ⚠️ 注意事项：
> 1. **§2 的网格串是候选池，不是谱面**（sheet 自己在 Header 里也写了）。
>    知识 005：官谱只从候选池里挑走约一半。
> 2. **★ `rest` 字段不携带密度信息，别把它读成"减压段"**（知识 **090** §6/§7，160 首实测）：
>    `rest=True` 的 2 030 个小节里 1 782 个就是 `落ちサビ`，两者基本等价；
>    而 落ちサビ 的密度中位是**本曲均值的 0.997 倍**，密度 ≥ 本曲均值的曲子占 **49%**——**掷硬币**。
>    它的滑轨密度反而比全曲高（1.41 vs 1.18 条/小节），63% 的小节有星星。
>    **正确读法**：`rest` = "这一段在结构上是最后一次副歌之前的那次副歌"，
>    **不是"这一段要写得稀"**。真正密度低的段落是 **イントロ（本曲均值的 0.785 倍）**。
>    试写一照着 `rest` 把 43–68 写成 6.7 note/小节，官谱那里是 11.1——**直接差了 61 个 note**。
> 3. **「建议 note/小节」系统性偏低**：试写那一首段落级偏差最大 6.6 note/小节、方向一致偏低。
>    **以定数 → NPS 锚（知识 031 §7）为主，段落建议值只用来定段与段之间的相对高低。**
> 4. 前奏/尾奏的「结构封顶」（≤ 全曲均值 × 0.75）是**上界提示不是目标值**：
>    试写把它当目标写了 5.0 note/小节，官谱前奏是 9.7（而且有 26 根星星）。

## 4. 段落规划

对每一段落写下**五件事**，写成一张表（试写的那张见 `e2e-trial-01.md` §2.1）：

1. **强度档**：跟 song sheet 的 `intensity_tier`，但密度目标走**定数 → NPS 锚**；
   段与段的**相对高低**跟强度曲线，**绝对值**跟定数（知识 031 §2 密度地板：
   任何一小节只要还在出音，就得给出基本踩音密度）。
2. **骨架轨 + 点缀轨**：抄 song sheet §1（知识 002/032：鼓骨架 + 大量非鼓填充）。
3. **采音方式**：全踩 / 舍音 / 留白（知识 068）。
   规则（知识 069）：音多 × 情绪高 → 几何手型只踩一部分；音少 × 情绪高 → 每一下写成双押并全踩；
   前奏 / 间奏 → 手不用动的东西。
   **写"舍音"的时候要连"舍哪一半"一起定下来**——做法见 §6.1（知识 **089**）。
4. **配置族**：从 song sheet §1.5 的候选里**挑一小撮**（知识 073：主料只有四五类）。
5. **★ note 种类配比**（v0.2 改写，依据知识 **088**）：
   这一条是试写一**最大的教训**——slide 占 6%、hold 占 0.5%，官谱是 17% 与 5%，
   note 总数的差额有八成出在这两项上。v0.2 把它拆成**可执行的三步**：

   **第 1 步：先从定数取全谱的档**（388 谱谱级中位，分母 = note 总数）：

   | 定数档（`floor(定数×2)/2`） | n | slide 轨占比 | hold 占比 | each note 占比 | note/小节 |
   |---|---:|---:|---:|---:|---:|
   | 13.0 档 | 168 | 14.6% [11.1–17.6] | 5.8% [3.2–8.2] | 59.0% | 7.83 |
   | 13.5 档 | 135 | 12.3% [9.2–16.6] | 4.5% [2.5–6.7] | 54.4% | 9.16 |
   | 14.0 档 | 73 | 10.3% [8.3–15.3] | 4.4% [2.6–7.2] | 48.6% | 10.39 |
   | 14.5 档 | 12 | 10.7% [8.1–14.4] | 5.5% [3.9–6.7] | 45.8% | 10.03 |

   （中位 [Q1–Q3]；`tools/chart_check` 的 `DEN-NOTEMIX` 用的就是这张表。
   ⚠️ 知识 088 正文里那张按 `13.0-13.2 / 13.3-13.5 / …` 五档切的表是**另一种分档**，
   方向一致、数值略有出入，两张表**不要混着引**。）

   ⚠️ **不要把它读成"高定数少写星星"**（知识 070 的老坑）：这是**跨谱**统计，
   说的是"高定数谱不靠堆多押与星星升定数"，**不是"这一首该少写星星"**。

   **第 2 步：把全谱的 slide 预算按段落分下去**（160 首段落级中位，每小节滑轨条数）：

   | 段落 | slide 占比 | 滑轨/小节 | 整段没有星星的比例 | hold 占比 | 整段没有 hold 的比例 |
   |---|---:|---:|---:|---:|---:|
   | サビ / ラスサビ | 16.7% / 16.5% | 1.33 / 1.44 | 7% / 9% | 1.7% / 2.2% | 42% / 26% |
   | 落ちサビ | 15.4% | 1.27 | 8% | 1.5% | 43% |
   | Bメロ | 14.4% | 1.06 | 17% | 2.5% | 47% |
   | Aメロ | 12.2% | 1.00 | 9% | 3.5% | 36% |
   | 間奏 / ドロップ | 10.1% / 10.2% | 0.88 / 1.00 | 18% / 19% | 2.1% / 1.3% | 42% / 42% |
   | **イントロ** | **7.5%** | **0.50** | **25%** | 3.8% | 39% |
   | アウトロ | 0.0% | 0.00 | 53% | 0.0% | 75% |

   三条读法：
   - **★ 星星是副歌家族的东西，前奏是全曲星星最稀的地方**（不是最密——试写一那一首的官谱前奏
     26 根星星只是那 21% 的个例，知识 088 §2 / 092）；
   - **★ 副歌的 slide : hold ≈ 4.4 : 1，而且四成副歌一根 hold 都没有**——
     长条更像前奏 / Aメロ 的东西，**不必每段都塞**；
   - 曲内五段看：**开头少星星多长条、结尾多星星少长条**（知识 088 §5）。

   **第 3 步：落到每一段写几条**——用"滑轨/小节 × 这一段小节数"算出条数，
   再决定这些星星摆成哪种星星族配置（知识 **090** 的段落地盘：
   落ちサビ / ラスサビ 是星星族主场，イントロ 与 間奏 都低于基线）。
   **偏离表里的数完全可以，但要能说出理由**（知识 092：单曲整段相反是常态）。

> ⚠️ 注意事项：
> - **第 ② 次出现的同一段落：踩音不变，靠配置升级，不靠加密**（知识 002 / 031 §8）。
> - **结尾形态按曲子实际结尾判断**（知识 001）：官谱 65% 尾杀、1% 渐弱、33% 其他；
>   音频真的淡出时谱面也跟着降，但降幅系统性小于音频（知识 031 §10）。
> - **休息靠低密段，不靠空小节**（知识 031 §5：休息小节只占 2.43%）。

## 5. 手序规划

**铁律（`docs/hand-sequencing.md` §6.1）：先做手分配，再落 note。**
不能「先把 note 摆好再检查手序」——那样只能事后发现无理、无法修。

每段写下：

```
config     : 手级配置名（hand-sequencing §5 的表）
role_L     : 左手做什么（守哪几个键 / 密度）
role_R     : 右手做什么
start_hand : 段首起手（知识 067：离上一段结束近的那只手；起始键放在上一配置结尾键附近）
budget     : {muri: 0（硬约束）, chuzhang: n, scrape_pressure: n（风格预算）}
```

> ⚠️ 注意事项（试写踩到的）：
> 1. **舒适区按知识 064**：左手 8765 + 1/4，右手 1234 + 8/5；
>    **只有右手落 6/7、左手落 2/3 才算出张**。
> 2. **出张写不出来，只能逼出来**（知识 **091**）：分配器按代价最小选手序，
>    两只手都够得着时它**绝不主动跨界**。想要出张只有两招——
>    **① 用长条 / 星星钉住一只手的专属键**（`3h` 钉右手 → 左手只能去打 2；
>    `6h` 钉左手 → 右手只能去打 7）；**② 写侧边双押**（知识 064 的交叉推论：
>    `{2,3}`/`{6,7}` 必定产生出张）。
>    **把长条写在共享键 `1h`/`8h` 上不会逼出任何东西**——分配器直接交给闲着的那只手。
>    ⚠️ **反过来也要守住**：出张是"让某只手被钉住"这个**音乐与配置决定**的副产物，
>    **不要先定"我要几个出张"再去凑**（知识 064 出张轻易不要写 / 066 不以手法为导向）。
>    **「软级蹭 0 次」不是异常**——388 官谱里 **48% 一次软级蹭都没有**（知识 091 §3），
>    试写一把"0 次蹭 vs 那一张官谱 22 次"当成写浅的证据是**读过头了**。
> 3. **侧边双押要有引导**（知识 030 铁律 + 082 八型）：最省事的是用户原话里的
>    **C 型等距轮转 `18 / 23 / 45 / 67`**，它自己就是引导。
> 4. **星星头与星星条可以分属两手**（知识 065），可以用它腾手；但**错位例外**
>    ——017 的用户原文把头 / 错位音 / 轨道写死在同一只手上。
> 5. **不以特殊手法为导向**（知识 066）：狗刨、同时处理是玩家的解法，不是谱师的许可。

## 6. 写 simai

### 6.1 采音：舍音时舍哪一半（v0.2 新增，依据知识 **089**）

§4 第 3 项定了"这一段要舍音"之后，**具体舍哪些格子**按下面的顺序判——
全部是**乐器层的判断**，不是网格判断（AGENT.md 准则 12：不得按网格 / 分音 / BPM 数格子）。
160 首官谱在 3 191 个「舍音」小节、21 510 个音轨事件上的取舍倾向：

| 线索 | 官谱倾向 | 强度（被踩率差 / 同号曲数） |
|---|---|---|
| **① 鼓件** | **军鼓一定留；"只有踩镲"的那一下先舍**；底鼓看情况（比军鼓弱） | +0.19 / 81% 的曲子同号；踩镲单响被踩 0.37 vs 含鼓皮 0.55 |
| **② 重音** | **留响的、舍轻的** | +0.14 / 89% 同号 |
| **③ 长短音** | **留"后面有空隙"的那一下；密集连打里删中间那几下** | +0.12 / 81% 同号 |

- **① 与 ② 是两条独立的线索**：按 onset 强度分三档后，军鼓效应在每一档里都在（+0.13 ~ +0.16）。
- **② 与 ③ 正交**："强度低 ∧ 间隔短"被踩 0.34（最常舍）、"强度高 ∧ 间隔长"0.65（最常留）。
- **★ 两条直觉被证伪，别用**：
  - 「**小节的第一个音几乎必踩**」——不成立（−0.047，只有 38% 的曲子同号）；
  - 「**多轨齐奏点几乎必踩**」——不成立（+0.053，加到第二条轨不再涨）。
- **这套倾向不随段落变化**（サビ / Aメロ / 間奏 / イントロ / 落ちサビ / ドロップ 上方向与量级一致）
  ——所以它是**一条可以全曲照用的规则**，不需要按段落换。
- ⚠️ 鼓件是 `onsets.py` 的**频带能量启发式**，不是鼓转录；"军鼓"里混着拍手与军鼓边击。
  **有音频时**可以用 `song_analysis.json` 的四轨网格串当参考，但**最终按听感判断**。

**反面教材**：试写一"以为自己在采音、实际在按分音铺匀拍"——骨架轨 coverage 0.87–0.95，
79% 的小节被判成「全踩」，官谱只有 44%。**铺匀拍不叫采音。**

### 6.2 排版约定（试写用的，好改也好读）

```
(162){8}
1b,,,,5,,,,                             ||m001 イントロ 入场
8,,7,,6,,5,,                            ||m002
...
E
```

- **一行一小节**，行尾 `||mNNN 段落/配置` 注释（`||` 必须以换行结尾，知识/语法 §3.6）；
- `{x}` 只在**需要换分音的那一小节**行首写；
- 收尾必须是大写 `E`。

> 🚩 **上面这套带注释的排版只用于"写和改"，不能直接当交付版。**
> **Visual Maimai 会吞掉 `||` 注释行之后那一行行首的 `{x}` 分音**
> （2026-09-20 实测，证据与推断链见 `docs/simai-error-checking.md` §9.1：
> test-01 的 m004–m058 被按双倍密度走，128 小节缩成 108.5 小节）。
> 交付前必须去掉全部 `||`（见 §9），注释另存 `out/<曲名>/maidata-annotated.txt`。

**语法红线**（`docs/simai-syntax.md` §6 + `docs/st-chart-elements.md` §三，检查器会逐条报）：

- ST 谱**禁用**：Touch、EX `x`、滑条绝赞 `]b`、连锁星星、无头 `!`/`?`、`$`、`@`、`m`、伪双押 `` ` ``；
- **允许**：TAP / HOLD / BREAK / 12 种 slide 形状 / **星星头绝赞 `1b-4[8:1]`** / **同头星星 `*`**；
- 分音用 384 的约数；slide 时长用 `[x:y]`；同头星星用 `*` 不用 `/`；
- **LLM 高危项：全角字符**（MiaCode 把 7 类全角都列为 Error）。

> ⚠️ 注意事项（试写踩到的）：
> - **拍滑链不要跨小节线**：链上最后一根星星的头如果落在小节末，它的**启动拍会落到
>   下一小节第 0 槽**；下一小节第 0 槽再写双押就是三只手（试写第 1 轮的 4 条错误全是这个）。
>   改法：链的最后只留启动拍 tap，不再起新头。
> - **slide 的终点别离下一次落手太远**：`8-4` 结束在 4，下一拍要回到 8 就是 4 格；
>   在 160 BPM 的八分上等效 21.6 键/秒，贴着知识 015 的红线。试写改用 `8-5` / `1-4`（3 格）。
> - **Hold 结尾至少留一个八分**（知识 012）。

## 7. 检查

```bash
python3 -m tools.chart_check <maidata.txt> --level 13.6 \
    --analysis out/<曲名>/song_analysis.json --json report.json
```

七层与三个级别的读法见 `tools/chart_check/README.md`。**收敛顺序**：

0. **交付格式先过**：`SYN-VM-COMMENT` 必须为 0——交付版**不许有 `||` 注释**（§9.1 的 VM 吞分音）。
   写稿阶段带注释没问题，但**跑最终验收要跑去注释后的那一份**。
1. **错误必须清零**：语法层的全部错误；手序层的**不可行**与**绝对无理**。
1b. **外部规则层（第七层）命中清零**：MiaCode / MaiMuriDX 口径的外键 / 撞尾 / 叠键。
    它和手序层**不是一回事**——`hands.py` 按 388 官谱校准得很宽，test-01 那一轮它报 0，
    同一份谱在 MiaCode 口径下有 **24 条**（note 066）。官谱基线（40 首）中位 3 / 最大 21，
    **官谱自己也命中，但生成端的目标是 0**。
2. **警告逐条看**：硬级无理（388 官谱自己也有几十次，见知识 077 —— **尽量清零，清不掉写明理由**）、
   note 总数越出定数区间、侧边双押判不出引导、整段留白。
3. **提示逐条过**：不判对错，但**每一条都要能解释**。重点看六组——
   出张落点清单、配置构成（主料几类）、密度五段形状与末段形态、逐段采音方式，
   以及 v0.2 新增的两组：
   - **`DEN-NOTEMIX` / `DEN-NOTEMIX-SECTION`**（知识 088）：note 种类配比与同定数档 /
     同段落官谱分布的对照——**这正是 §4 第 5 项那张表的自动化版本**；
   - **`DEP-SHALLOW`**（知识 093，深度层）：手序难度 / note 种类占比 / 主料构成
     三项里同时有 ≥2 项明显低于同定数档官谱时给出的「写得太浅？」复核清单。
     ⚠️ **它触发得并不稀罕**——五首官谱基线里 ぽっぴっぽー（3 条）与 コトバ・カラフル（2 条）
     也会触发，所以**不是"必须改"**，只是"回头看一眼、偏离要能说出理由"。
     ⚠️ **手序难度不是难度代理**（知识 078），**不得当目标去优化**。

**官方谱基线**（五首，见检查器 README）：语法 0 错 / 不可行 0 / 绝对无理 0 是合格线；
硬级不是 0（ジングルベル 10 次）；出张 12–29 ‰；侧边双押的八型引导全部判得出。

> ⚠️ 注意事项：
> - **「0 错误」不等于写得好**。试写终稿 0 错误 0 警告，手序难度只有官谱的 41%、
>   slide 只有官谱的 28%、软级蹭 0 次（官谱 22 次）。**检查器拦不住「写得太浅」。**
> - **软级的「蹭」不要清零**：知识 048/052/062 明说蹭是设计手段，官谱主动写。
> - **配置层的「种类数」量的是检测器认出来的名字，不是你主动铺的手分工**（知识 075）。
>   压它没有意义；该自检的是「我主动铺了几种手分工」。
