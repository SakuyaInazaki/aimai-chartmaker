  ### agent 理解
  - **⚠️ 定义是 agent 补的**：教程没说"菱形"指什么。本条给出的结构判据——**两条同时进行的 slide 轨道在屏幕上夹出一块狭长区域，且该区域内或紧邻处有必须击打的 note**——是 agent 从谱例反推的（**存疑**）。"类菱形"教程同样未给判据。
  - **手级定义（agent 推断，存疑）**：
    - **拍头手 / 划轨手**：两只手同相位，各领一条边（KING is BACK!! ＝左手 1、右手 2）；
    - **另一只手任务**：夹在中间的那个 tap（谱例里的 `3` / `6`）**由离它近的那只手顺手补**——也就是说这只手要在"刚划完 / 马上要划"的间隙里插一下，手掌必然从自己的轨道上方扫过；
    - **换手时机**：不换手；这正是它"蹭"的根源——**没有一种手序能让手掌避开自己的轨道**，只能靠 048 的容错窗口抢时间。
  - **"正攻/邪道都行，能黄就是好"的制谱含义（agent 推断，存疑）**：菱形星星**不是靠手序解的配置，而是靠判定容错解的配置**。对本项目的意义有两条：
    1. 它说明 **"轨道被蹭"本身不等于无理**（008/010/011 判的是"规避不掉且必然掉分"）——菱形星星是设计者**主动接受蹭、依赖 048 窗口仍能判黄**的写法；
    2. 但生成器**不应主动制造它**：它把难度押在玩家的个人手型与熟练度上（教程 051 处明说这一族"个人差较大"），与本项目"手序合理"的验收目标相冲突。**建议列为"识别得出、但不主动生成"的配置**。
  - **与 011 撞尾的界限**：谱例里 tap `3` 落在两条轨道之间、且**在两条星星的启动拍之前**——即 tap 出现时轨道还没开始动，所以不构成 011 意义上的撞尾。**把 tap 挪到启动之后就会直接变成撞尾**，这条位移量是设计上的生死线（*推断*）。
- **理由**：教程只给评价不给定义，故结构判据标 agent 推断；两首谱例的定数/难度/BPM 与教程逐项吻合，形态自洽。

## 修订记录

- **2026-09-20（官谱普查，agent 观察）**：本条「agent 理解」里的三条推断**被官方谱写法推翻或大幅收窄**，原文保留不改。
  1. 「夹在中间的那个 tap 由**离它近的那只手顺手补**……这只手要在间隙里插一下」——**在官谱的主流形态上不成立**：交叉族里九成的夹音是**同刻成对的双押**，两只手**同时向各自头键的外侧扒一格**再收回来，没有"一只手顺手补"这回事。本条这条推断只对它自己举的 `663-KING is BACK!!` 那种**单音**形态成立。
  2. 「**没有一种手序能让手掌避开自己的轨道**，只能靠 048 的容错窗口抢时间」——**与官谱写法相反**：带夹音的 115 处里 **113 处的夹音落在两条轨道开始移动之前**（启动拍之前），此刻轨道根本还没开始走，手掌无轨可蹭。**官谱是用启动拍把夹音和轨道在时间上错开的，不是靠容错窗口硬吃。**
  3. 「把 tap 挪到启动之后就会直接变成撞尾，这条位移量是设计上的生死线（*推断*）」——**被官谱强支持**，可以从"推断"上调为"官谱实证的写法规律"。
  - 另外两点：① 本条的结构判据（两条轨道夹出狭长区域 + 区域内有必须击打的 note）**方向对，但"有夹音"是少数派**——"两条轨道夹出缝"本身在官谱里极常见（跨 260 张以上的谱），**真正少见的是缝里还要打音**（约一成），所以"夹出缝"不足以单独当判据；② 「建议列为识别得出、但不主动生成的配置」这条涉及生成策略，**属用户裁定范围，本轮不动**。
  - 官谱的写法骨架（两头同落 → 轨道起步前打夹音 → 启动拍上一对 break/tap 起步）、两手分工与计数见**知识 083**。
