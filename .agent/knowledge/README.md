# .agent/knowledge — 制谱意识知识库

## 为什么需要这个目录

模型（coding agent）的上下文长度有限。**跨上下文区间来保持对"制谱意识"（谱面设计认知）的理解是不合理、不可靠的，且容易产生幻觉。** 因此，所有关于谱面设计的稳定认知——无论大小——都必须沉淀为文件，长期维护、随时检索。

- 本目录 = **稳定认知**（"我们知道什么"）：谱面设计的原则、规律、经验、结论。
- `.agent/notes/` = **过程记录**（"我们做过什么、为什么"）：项目演变的变更日志。
- `docs/` = **正式文档**（语法规范、设计文档等长篇成果）。

三者分工：docs 是供人/agent 阅读的成体系文档；knowledge 是原子化的制谱意识小点；notes 是变更历史。

> ⚠️ **重要原则：知识条目不是金科玉律。** 长期维护过程中，历史认知时常会被新的资料、实验或社区共识推翻——这是正常且预期发生的。每条目只代表"当前最佳认知"（由置信度标注把握程度），**读取时保持批判，与新证据冲突时以新证据为准**，按修订规则推翻旧条目。

## 条目约定

- 文件名：`NNN-简短主题.md`，`NNN` 三位递增编号，一条目 = **一个可以独立成立的小点**（可大至一套强度理论，小至"错位是同级最强星星用法"）。
- 每个条目包含字段：
  - **日期**：创建/修订日期
  - **要点**：一句话讲清这个认知
  - **详情**：展开说明（可含谱例代码、数据）
  - **理由**：为什么成立（逻辑或证据）
  - **来源**：出处（资料名/章节/URL/官方谱例）
  - **置信度**：`确信`（社区共识/官方依据）/ `经验`（谱师经验）/ `存疑`（待验证）
  - **关联**：相关条目编号、docs 文档
- 修订规则：认知更新时**直接修订原条目**并在文末追加"修订记录"（日期+内容）；被推翻的条目标注 `[已废弃]` 并指向替代条目，不删除历史。
- **推翻规则**：发现旧条目与新证据（新资料、实验结果、官方谱例、社区共识变化）冲突时，**不得固守旧认知**——评估证据后修订或废弃旧条目；推翻同样要写进"修订记录"并说明依据。新条目可以完全取代旧条目。

## 使用规则（所有 coding agent 必须遵守）

1. **写前必读**：生成谱面、评审谱面、设计生成器规则之前，必须先读取本目录（及索引）中相关条目，不得依赖对话上下文中的"印象"。
2. **批判性读取**：条目是"当前最佳认知"，**不是金科玉律**；注意置信度——`存疑` 条目不得当作硬约束使用，`确信` 条目与新证据冲突时也要优先相信证据并触发推翻流程。
3. **学到必写**：从资料、调研或实验中获得的任何新制谱意识小点，**立即**新增条目（哪怕只有一句话），不得留在对话里。
4. **存疑必标**：把握不足的认知标注 `存疑`，待后续资料/实验确认后再升级。
5. **允许推翻**：新证据与旧条目冲突时，评估后修订或废弃旧条目（写修订记录），不得因"之前是这么写的"而固守。
6. **同步入库**：条目与触发它的变更在同一个 git 提交中推送。
7. 用户后续补充的资料消化出新认知点时，同样按此流程新增条目。
