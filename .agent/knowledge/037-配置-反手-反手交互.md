# 037 — 配置：反手 / 反手交互

- **日期**：2026-09-19
- **要点**：反手 = **双手交叉在一起的动作**；反手交互 = **在双手交叉的状态下打的交互**，难点在协调力而不是手速。教程认为**出张包含反手**（反手是出张的一种极端情形）。

  ### agent 理解
  - **判据（可机检的那一条）**：把每个音按"轮到哪只手"配出去以后，看**两手当前所在键的角序是否与 006 的分页处理相反**——正常是左手在 5678 半圈、右手在 1234 半圈；反手就是**两手同时挤进同一个半圈**，或者左手的键顺时针跑到了右手前面。
    以引文为例（左手起手，左右交替）：L=3 / R=4（都在右半圈，左手还压在右手的逆时针一侧）→ L=1 / R=2（仍在右半圈）→ L=7 / R=8（进左半圈）→ L=6 / R=5（都在左半圈）。**整段四对相邻键，两手始终被塞在同一半圈里**，这就是"交叉"的来源。（agent 推断，存疑：教程只说"双手交叉"，没有给形式化判据。）
  - **成因常常是"前面那只手没空"**：画面注点破了机制——右手还按着长条，轮到的就只能是左手，于是从"右起"翻成"左起"，后面整串交互的奇偶性跟着翻转，落在右半圈的音就都变成左手的活。**写谱时的含义**：hold / slide 的尾巴决定了下一串交互的起手手，**长条的结束时刻就是换手奇偶性的开关**。
  - **强度归因**：教程两次强调"吃协调力"而不是手速。按 003 的四因素，反手交互的强度不来自 BPM 或 note 种类，而来自**手臂的物理干涉**——两条手臂在同一半圈里叠着，可及范围被对方挤掉（对比 023 里"右手最多够到 5 号键"的可及范围）。所以**同样的音符串，翻成反手以后定数会明显上去**。（agent 推断，存疑）
  - **与出张（043）的关系**：教程明说"出张包含反手"。043 是"某只手离开自己的舒适半圈"；反手是**两只手都过界并且交叉**，是出张里最贵的那一档。
- **理由**：定义与"出张包含反手"是教程明文；谱例由屏幕引文逐字命中官方谱确认；判据与成因为 agent 在引文范围内的推断。
