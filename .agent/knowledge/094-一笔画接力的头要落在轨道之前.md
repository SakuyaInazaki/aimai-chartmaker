# 094 — 一笔画 / 绕圈接力：下一根的头要落在上一根轨道抵达终点**之前**

> ⚠️ **本条为 agent 观察，未经用户确认。** 来源：`.agent/notes/066`（test-01 的 24 处撞尾
> 全部由这一条引起）+ MiaCode `MURI_DETECTION_SPEC` / 上游 MaiMuriDX 的判定常量
> + 两份官方谱的实测形态。**这是判定机制，不是制谱品味。**

- **日期**：2026-09-20
- **要点**：一笔画 / 绕圈接力里，**下一根星星的头要在上一根的轨道抵达终点之前落下**。
  官谱的头间距是**半拍到一拍**（`133-BREAK YOU!!-mas.txt` m066 半拍、
  `112-Mysterious Destiny-mas.txt` m020 一拍）——这正是知识 **057** 说的
  「**头永远比轨道领先一拍**」。**排到两拍，头就正好掉进上一根轨道尾的判定区里，撞尾；
  与键位无关**，换哪两个键都一样。
- **详情**：

  ### 机制：轨道什么时候才到终点
  slide 的头被打下之后**停一拍才开始滑**（知识 **014**），滑完还要走完整条轨迹，
  所以"轨道进终点判定区"这件事发生得**比头晚得多**：

  | 写法 | 头 | 启动拍（开始滑） | 轨道进终点区 |
  |---|---|---|---|
  | `X^Y[8:1]` @205 BPM | t₀ | t₀ + 1 拍 = t₀+293 ms | **t₀+425 ms**（≈ 1.45 拍） |
  | `X-Y[8:1]` @205 BPM | t₀ | t₀+293 ms | **t₀+415 ms** |

  （进区时刻 = 启动拍 + 该形状的最后一个 A 区进入比例 × 滑动时长；比例来自
  MaiMuriDX `slides.py::SlideInfo.pad_enter_time`，本项目导出在
  `tools/chart_check/data/slide_geometry.json`。）

  ### 判定区：进区前 50 ms 到进区后 200 ms
  社区检测器（MiaCode 的谱面检查 / MaiMuriDX / Visual Maimai 无理面板，三者同源）
  把 **[进区 − 50 ms, 进区 + 200 ms]** 当成该判定键的危险区，
  这段时间里那个键上再出现 tap / hold / **下一根星星的头**就是**撞尾**
  （常量：撞尾阈值 36 tick = 200 ms、区间左端冗余 9 tick = 50 ms，判定时基 180 TPS；
  见知识 **011** 与 `docs/simai-error-checking.md` §8.5）。

  205 BPM `{8}` 下这段危险区是 **t₀+375 ms ~ t₀+625 ms**。

  ### 于是：接力排在第几拍，结论是定死的
  | 下一根头的位置 | 落在哪 | 结果 |
  |---|---|---|
  | 半拍后（t₀+146 ms） | 危险区**之前** | ✅ 官谱写法（BREAK YOU!! m066） |
  | 一拍后（t₀+293 ms） | 危险区**之前** | ✅ 官谱写法（Mysterious Destiny m020），同时落在上一根的启动拍上，两件事并成一个双押 |
  | **两拍后（t₀+585 ms）** | **危险区正中** | ❌ **撞尾**（gap −161 ms） |

  ### 官谱实证
  - **`133-BREAK YOU!!-mas.txt` m066**（BPM 167、`{16}`）：`2-5[8:1],2,5-1[8:1],5,`
    ——两根头只隔 2 个十六分 = **半拍**；`2-5` 的轨道 t₀+515 ms 才进 A5，
    而 `5-1` 的头 t₀+180 ms 就落了，**头比轨道早 335 ms**。
  - **`112-Mysterious Destiny-mas.txt` m020**（BPM 140、`{4}`）：`8^3[4:1],3^6[4:1],,,`
    ——两根头隔 **一拍**；`8^3` 的轨道 t₀+814 ms 进 A3，`3^6` 的头 t₀+429 ms，**早 385 ms**。
  - 反例（本项目自己写的，note 066）：test-01 把接力排成**两拍**，
    10 个小节形如 `2^5[8:1],,2,7,5^8[8:1],,5,1,`——**每一个都撞尾**。
    改法是把下一根的头从第 5 个八分提到**第 3 个八分**（与上一根的启动拍 tap 合成双押），
    **头尾相连一字未动**、节奏与 note 数不变，24 处命中归零；
    副作用是配置检测器这才认出「一笔画」这一类。

  ### 怎么读这一条
  - 它**不是阈值规则**，不要拿"头间距 ≤1 拍"去卡谱。它说的是一件物理事实：
    **头领先轨道，是 slide 停一拍再滑这个机制的必然结果**；
    谁把接力排得比这慢，谁就把头放进了上一根的尾巴里。
  - 反过来，**头排得越紧越安全**（半拍比一拍更早离开危险区），
    真正的上限来自手够不够得着（知识 015）与一笔画的打法（知识 057：一手专拍头、一手专划）。
  - 撞尾是**软硬分级**的（知识 011），加 Ex 保护可降级；但生成端没有理由去用保护换一个
    本来可以靠相位避开的问题。
- **理由**：这一条来自判定机制本身——启动拍等待（知识 014）把轨道推后了一整拍，
  而危险区是钉在"轨道进终点区"上的，两者相减就得到"头必须更早"。
  **不是审美偏好**：把同一副接力骨架的头从第 5 个八分挪到第 3 个八分，
  形状、键位、note 数、配置族全不变，撞尾从 10 处变 0 处。
  官谱的两个实测形态（半拍 / 一拍）只是这条机制的两种合法排法，不是它的依据。
