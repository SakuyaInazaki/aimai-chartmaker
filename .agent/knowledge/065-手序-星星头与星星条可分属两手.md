# 065 — 手序：星星头与星星条可分属两手（用户裁定）

- **日期**：2026-09-19
- **要点**：星星头和星星条理论上是两个部分，但**没有严格规定**拍星星头的那只手一定能、或者一定不能划星星条——**A 拍头，可以 A 划条，也可以 B 划条**，两种分配都合法。
- **详情**：

  ### 用户原话（逐字）
  > 理论上来讲，星星头和星星条是两个部分，但是也没有严格规定说拍星星头的手就一定能或者不能划星星条，也就是A拍头可以A划条也可以B划条。

  ### 主会话解读
  - 原话里有**两条否定**：既没有"拍头的手**一定能**划条"这条规定，也没有"拍头的手**一定不能**划条"这条规定。因此 `hand(head)` 与 `hand(track)` 是**两个自由变量**，`同手` 与 `异手` 都是合法解。
  - 用户**没有**表达任何一侧的偏好（没有说哪种更好、更常见、或代价更低）。所以"谁划"这件事**不存在用户侧的默认值**。

  ### 对手序模型的含义
  1. **知识 007 的两条要被降级**（已在 007 追加修订记录）：
     - 「划 slide 的手应与 slide 末尾所在半边相同」→ 社区经验 / 打分项，**不是硬规则**，被本条覆盖；
     - 一笔画的「一只手专门拍、一只手专门划」→ 同样是社区经验，不是"必须"。
  2. **`hands.py` 的两个代价项失去用户侧依据**（主会话建议，见重调清单）：`w_star_switch`（划轨手 ≠ 拍头手就加代价）应撤销；`w_slide_end_side`（末尾半边）应撤销或降为极小 tie-breaker。
  3. **模型结构不变、方向性变**：把 `star` 与 `slide` 建成两个独立可分配任务这一设计（知识 054、`docs/hand-sequencing.md` §1）是对的，本条只是取消了"倾向同手"这个先验。
  4. **验收口径**：既然两种分配都不禁止，"手序合理"应判**存在一套合法手序**，不判"必须是我给的那套"——这与知识 054 里记的教程口径（"不换手也能获得不一样的乐趣"）一致。
- **理由**：用户谱师讲授，原话即边界。教程侧（知识 054）只说"头与本体是两个独立部分、并不一定要在一个手顺里解决"，用户在此基础上把**两个方向都明确为无硬规定**。
