# 077 — 双押 / 多押的手分配；"蹭"不等于无理

> ⚠️ **本条为 agent 观察，未经用户确认。** 口径：388 个官方 ST 谱上的手序判定实测。

- **日期**：2026-09-20
- **要点**：同一时刻有**两个**需要处理的对象 = 两只手各一（双押）；同一时刻**三个或以上** = 多押，属绝对无理（知识 008）。但把所有"**蹭**"（软级的撞尾、外键、路径蹭键）都算成无理是错的——**官方谱里的"蹭"多数是设计手段**，必须与无理**分开计量**。
- **详情**：

  1. **无理与蹭分两本账**：模型里 `muri`（能不能打）与 `scrape`（蹭的压力）是两个独立输出。若把软级的蹭都记成无理，388 张官方谱会被判成满篇无理——**那显然不对**，因为"提前快滑、留尾、快滑快抬防蹭"这些正是星星篇讲授过的标准手法（知识 048/051/052/059/062）。
  2. **叠键红线（知识 009）与 Hold 尾多押（知识 012）是可机检的硬标记**：官方谱里"Hold 判定尾 + 同刻双押"这种组合并不少见，可以独立报出来供复核。
  3. **外键红线（知识 010）的"同头（同侧）"应读作"同一个判定键"，且窗口锚在星星的启动拍**（**agent 观察**）——四种读法在 388 谱上给出的硬外键次数差了两个数量级，只有这一种读法下官方谱不会被判成系统性写硬无理；这与社区解析器 MiaCode 的规则名 `SlideHeadTap` 一致。**本条不改写知识 010，只记录这条对照。**
  4. **知识 011 的"210 BPM 以下八分撞尾可容忍"在实测中很关键**：不启用它，官方谱的硬撞尾数会高出数倍。
  5. **真正指向谱面的绝对无理极少**：388 谱里只有个位数的真·多押与绝对撞尾（疑似作谱失误），其余绝对级计数是模型自身的缺口。

  **证据注脚**：388 谱 绝对无理 146（占用冲突 136 = 模型缺口 / 多押 5 / 绝对撞尾 5）；硬级 Hold 尾多押 74（17 谱）、超速 24、外键 13、撞尾 7；软级 scrape 共 859（撞尾 461 / 外键 198 / 路径蹭键 172 / 换手拧巴 28）；知识 010 四种读法分别给出 832 / 279 / 243 / **13** 次硬外键；知识 011 规则不启用 34 次硬撞尾 → 启用后 6 次。

- **理由**：官方谱是"人类可玩"的既成事实，任何把官方谱大面积判成无理的判据都应先怀疑判据本身；无理判定要能区分"打不了"与"要蹭一下"。
