# 005 — 采音要"简"

- **日期**：2026-09-10（2026-09-11 补充实证）
- **要点**：maimai 的采音要"简"——删到不能再删；把 maimai 当太鼓/4K 下落式写、采得过密是新人谱师最典型的通病。
  🧪 **2026-09-11 实测佐证：官方谱只从候选池里挑走约一半的音**（precision 0.546，n=8）。
- **详情**：
  - 新手误区："哪个响就一直踩哪个"、能听到的音全踩上；
  - 正确做法：只采支撑段落结构的关键音轨与重音，留白本身就是表达；
  - 星星速度同样贴合情绪：激烈段快、平和段/开头结尾慢。
  - 🧪 **量化（8 首官方 mp3 × 官方谱配对实测）**：把管线量化落格后的 onset 当"候选池"
    （平均 828 个格子/曲），对照官方 MASTER 谱的实际 note：
    - **recall 0.821** —— 82% 的官方 note 能在候选池里找到对应格子（候选池够用）；
    - **precision 0.546** —— **候选池里只有 55% 被官方采用，其余 45% 是"多余的音"**；
    - 逐曲 precision **0.234**（Back 2 Back，全曲最稀的谱）— **0.695**（Xevel，全曲最密的谱），
      **precision 与谱面密度强相关**：候选池大小基本固定，谱越密"用掉"的越多。
    → **"删到不能再删"不是修辞，而是可量化的：按定数决定要从候选里删掉多少**（稀谱删掉 3/4，密谱删掉 1/3）。
- **理由**：maimai 谱面强度靠"采音+配置"的相对变化表达，全踩等于没有强弱；社区教程一致强调"删到不能再删"；
  8 首配对实测给出了这条经验的量化版本。
- **来源**：写给 maimai 新人谱师的 6 个建议（墨滢）https://www.bilibili.com/opus/736833117612933144 ；
  舞萌简明初级教程 https://www.bilibili.com/opus/461149354380109054 ；
  量化佐证 = `docs/research/audio-chart-calibration.md` §5.2（n=8，代理判据）。
- **置信度**：**经验（社区共识）**；其量化版本（55%）为 **存疑/经验**（n=8、候选池大小取决于管线量化口径）。
- **关联**：知识 001/002（切轨、情绪贴合）、**032（官方谱踩音归因实测）**、031（密度量级）；
  `tools/audio_analysis/sheet.py` 的 song sheet Header 已把这条写进给 LLM 的硬提示。

## 修订记录

- **2026-09-11**：补充 8 首官方音频×官方谱配对实测的候选池有效率（recall 0.821 / precision 0.546，
  逐曲 0.234–0.695），作为"删到不能再删"的量化佐证。**原有主张未变**。
  ⚠️ 口径：候选池 = 本项目管线量化落格后的 onset 集合，**其大小取决于分轨与量化实现**，
  换一套管线这个 55% 就会变；它衡量的是"本管线给出的候选相对官方谱有多冗余"，
  不是"音乐里客观有多少音可踩"。

- **2026-09-13（第三轮，n=8 → n=40 → n=160）**：配对标定扩到 **160 首**官方 ST 曲包。
  依据 `docs/research/audio-chart-calibration-n160.md` §5.2。**原文一律保留，只加本条记录。**

  | 口径 | n=8 | n=40 | **n=160** |
  |---|---:|---:|---:|
  | 候选池 recall | 0.821 | 0.837 | **0.840** |
  | 候选池 precision | 0.546 | 0.550 | **0.549** |
  | 逐曲 precision 范围 | 0.234–0.695 | 0.234–0.763 | **0.217–0.812** |

  → **「官方谱只从候选池里挑走约一半」在 20 倍于首轮的样本上第三次复现，
  55% 这个数字三轮之间的移动不超过 0.4 个百分点。**
  「precision 与谱面密度强相关（稀谱删掉 3/4、密谱删掉 1/3）」的形态也维持。
  **量化版本的置信度可以从 `存疑/经验` 上调为 `经验`**（⚠️ 仍不是 `确信`：
  候选池大小取决于本项目的分轨与量化实现，换一套管线这个 55% 就会变）。

  ⚠️ **同时修掉了一个实现缺陷**：候选池有效率原本拿**做过 φ\* 解码延迟补偿**的官方时间槽
  去比"量化落格后的网格"，而网格锚在用户给的 `&first` 上、与官方 note 本来就同一个时钟，
  再平移一次反而把 note 推离网格。n=40 时最大 |φ\*| 只有 25 ms、被 30 ms 容差盖住；
  n=160 里《L4TS2018》（φ\* = −37.5 ms）的候选池 recall 被压到 **0.003** 才暴露。
  修正后 pool recall 0.8328 → **0.8396**。→ **n=8 / n=40 报的候选池数字属于轻微低估，
  量级不影响本条目的任何结论。**
