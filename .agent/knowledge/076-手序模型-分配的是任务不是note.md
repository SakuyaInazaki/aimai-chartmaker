# 076 — 手序模型：分配的是"任务"不是 note（slide 占手 / 拍划并入 / 一手不吃两对象）

> ⚠️ **本条为 agent 观察，未经用户确认。** 口径：388 个官方 ST 谱上的分配器实测（`tools/chart_analysis/hands.py` v0.3）。**模型里的代价权重与速度下界数值都是 agent 设定的工具内部口径，不是制谱结论**，本条只记结构性的几条。

- **日期**：2026-09-20
- **要点**：可计算的手序模型里，被分配给左右手的是**任务**而不是 note——
  一根 slide 拆成**星星头**与**划轨道**两个可分属两手的任务（知识 065）；
  一个任务**占住一只手一段时间**，slide 的这段时间是个**可伸缩区间**：
  最早到**启动拍**（知识 014）才能开划，最晚可以**拖到终点的容错窗口**（知识 048）。
  **舒适区（知识 064）是"这只手该落哪里"的先验**，**一只手同一时刻不吃两个对象**（知识 066）。
- **详情**：

  1. **拍划并入**（知识 006）：落在启动拍上、与头键同键的 tap——**以及另一条 slide 的星星头**——并入划动这个手法，不额外占一只手。⚠️「星星头也并入」是把知识 006 的两句话合起来推的（**agent 推断**），但它是官方谱能跑通的前提：不并入，388 谱会冒出数千次"一只手同时被两件事占住"的冲突。
  2. **一笔画续划**（知识 007/057）：上一条轨道停在下一条轨道的头键上且时间首尾相接时，**手不松开接着划**，不吃松手延迟。
  3. **同头多 slide（`*`）视作一次连续划动**（**agent 推断，存疑**）。
  4. **一手不吃两个对象**（知识 066 的直接落地）：模型里"一只手同时处理两件事"这个开关**默认关闭**——手法是玩家的解法，不是谱师的许可；不得用"玩家可以同时处理"来放宽无理红线。
  5. **交替是默认**（知识 018），同键续敲只在舒适速度内才比换手省事；**长度 ≤3 个"需要击打按键的 note"（tap / hold 头 / 星星头）的短纵连免拆**（知识 019 用户补充）。
  6. **单手连续出手存在速度下界**，其来源是知识 015 的官谱纪录反推；**具体数值是工具内部口径**（见 `docs/hand-sequencing.md` §3），**本条不把它当结论**。
  7. **段与段之间不重置两手状态**：段首谁出手由上一段结束时手在哪决定（知识 067）。起手的选择**会一路传播下去**（全库对照：强制左手起手与强制右手起手，整谱手序难度有可感的差别），但**从不改变"能不能打"**——起手属于风格与难度维度，不是验收硬约束。

  **证据注脚**：388 谱基线 绝对无理 146（0.54‰），其中 136 是模型自身的占用冲突缺口，真正指向谱面的只有 5 次多押 + 5 次绝对撞尾；不并入拍划则占用冲突 4 455 次；短纵连免拆直接消掉 3 次"超速"；起手奇偶对照——两种起手下**无理数不同的谱占 0.0%**，而整谱手序难度相对差中位 0.85%、超过 1% 的谱占 43.3%。

- **理由**：AGENT.md 验收标准 2/3（人类可玩、手序合理）需要一个可计算模型；该模型在 388 官方谱上跑出接近零的绝对无理，说明结构性假设（任务分配、slide 可伸缩占手、拍划并入）站得住。

- **置信度**：**经验（agent 观察，n=388 谱 / 272 207 个手任务，未经用户确认）** / **存疑**（① 星星头并入、同头多 slide 合并均为 agent 推断；② 全部代价权重与速度下界数值为 agent 设定，**不构成任何对外的分级或术语**；③ 残留的 136 次占用冲突是模型缺口，不是谱面问题）。
