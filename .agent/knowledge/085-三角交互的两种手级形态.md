# 085 — 三角交互在手级上就是两手严格交替；官谱里存在两种可区分的排列（背离 / 朝向）

> ⚠️ **本条为 agent 观察，未经用户确认。** 口径：388 个官方 ST 谱；三角组沿用 `configs_hand._tri_valid`（3 个音一组、键集 2–3 键、弧跨 ≤3、组内转向、手序 XYX）。**"背离 / 朝向"是 agent 为本轮定义的说法**，与用户口中的「正 / 反」是否同一件事**未经确认**。

- **日期**：2026-09-20
- **要点**：知识 020 说正/反三角「目前区分依据**只有手感**」。回到官谱看手级：① 三角交互**不靠任何特殊手法**——它就是**两手严格交替**（一只手打第 1、3 个音，另一只手夹中间）；② **起手用哪只手没有偏好**，由上一个音的位置决定（知识 067）；③ 官谱里确实存在**两种可区分的排列**，区别只在**打两下的那只手第二下往哪边挪**。
- **详情**：

  1. **手级定义**：三角组在手级上是 **XYX** —— 一只手打第 1、3 个音，另一只手夹中间。占 2 键时打两下的那只手**原地按两次**，占 3 键时要在两个键之间**挪一格**。这与 020「它是**摆位**上的划分，与实际节奏无关」是同一个方向：**"三角"是键位摆位上的分组，不是手上的分组。**
  2. **起手手没有偏好**：全库左起与右起**基本各占一半**。这和知识 067（段首先出手 = 离上一段结束近的那只手）一致——**三角组用哪只手起手只由上一个音的位置决定**。
  3. **两种排列**（**agent 的说法，存疑**）：

     | | 一种 | 另一种 |
     |---|---|---|
     | 三个音的位置次序 | **中间键 → 一端 → 另一端** | **一端 → 另一端 → 中间** |
     | 第 3 个音落在哪 | 第 1 个音的**外侧** | **夹回前两个音之间** |
     | 打两下的那只手 | 第二下**背离**另一只手挪 | 第二下**朝着**另一只手挪 |
     | 两手的走势 | 从中间往两边**撑开** | 往中间**收拢** |

     占 2 键时打两下的手原地按两次，**不分这两型**。
  4. **★ 段级基本"一段只用一种"，谱级多数混用**：一个段落里几乎总是清一色的同一种排列，中间地带极少；但整张谱通常两种都用。**所以这两种排列不是把官谱分成两族的分界线。**
  5. **手感没有验证**：020 记的「正三角打起来顺、反三角别扭/卡/更累」是**用户体感**，本条**完全没有取证**（也无法取证）。只能记下一个结构对应：收拢型的第 3 个音夹回前两个音之间。

  **证据注脚**：388 谱 **1 524 个三角组 / 213 张谱**；占 2 键 721 / 占 3 键 803（对半开）；起手手 **L 765 / R 759**（无偏好）；手序 XYX 占 2 键 95%、占 3 键 90%（其余是段落边界被切断的残片）。803 个三键组里**背离 410 / 朝向 393**（组级对半开）；含 ≥3 个三键组的 37 段里 **22 段是纯的**（全朝向 6 段、全背离 16 段），中间地带（0.4–0.6）**只有 2 段**；含 ≥4 个三键组的 88 张谱里两种混用 57 张。官谱例：`148-Beat of getting entangled-remas` m000–m003（24 组 100% 背离）、`655-閃鋼のブリューナク-mas` m047（4 组全朝向）、`547-HERA-mas` m057/m059/m061/m063、`666-Revive The Rave-mas`（朝向占比最高）、`141-カゲロウデイズ-remas` m084、`673-拝啓ドッペルゲンガー-mas` m066–m067。

- **理由**：020 把正/反的区分挂在"只有手感"上，文末另挂了一条 agent 观察（正＝中间键起手 / 反＝端键起手）标着"用户尚未确认"。本条给出一个**可在手级检验**的等价说法，并把它在 388 谱上数清楚——**但不认领"正三角/反三角"这两个名字**。

- **置信度**：**经验（agent 观察，n=388 谱计数，未经用户确认）**（XYX、起手无偏好、两种排列在段级可区分）/ **存疑**（① **"背离 / 朝向"与用户口中的"正 / 反"是否同一件事未经确认**——用户明确说过这个区分"只有手感、还没认真思考"，**不得据此改写 020**；② 手感（顺 / 卡 / 累）完全没有取证；③ **切组的相位有歧义**——一串匀速单点切成三个一组有三种切法，检测器选的是"能切出更多合法三角组"的那种，**凡是跨过用户引文边界的计数都不可靠**（AGENT.md 准则 9）；④ 要求手序 XYX，所以"三个音被分成 1+2 或 3+0"的变体不在统计内）。
