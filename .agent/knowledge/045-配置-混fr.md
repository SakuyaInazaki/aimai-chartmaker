# 045 — 配置：混 fr（两手各踩一条不同节奏的音轨）

- **日期**：2026-09-19
- **要点**：混 fr = **两个音轨采的是不同节奏的音，落到舞萌里就是两只手要处理不同的节奏**；难点在协调而不在速度。
- **详情**：

  ### 教程说明（转述）
  - `[08:41]`「**混fr：两个轨道采的不同节奏的音，放到舞萌里就是两只手要处理不同的节奏，非常的吃协调能力**」；并自嘲「目前 UP 的金鱼记忆力只能想到一个示例」。
  - 同屏给了写法示意（OCR 原文，有残缺）：
    ```
    一手{4}X,X,X,X,X,X,X
    一手{8}X,x,x,x,x,x,
    ```
    即**一只手走 4 分、另一只手走 8 分**。
  - 教程谱例：**Cthugha**（14.3 / Jack / ver.舞萌DX2023 / BPM 213）→ manifest 核对为 **DX MASTER 14.2**。
  - `[09:02]` 另附一段「**不知道算不算混fr姑且先放上来**」：**Credits**（13.3 / Jack / ver.MiLK / BPM 179）→ manifest 核对为 **EXPERT 13（13.3）**，并把该段的 simai **整段打在屏幕上**。

  ### 谱例
  - 两首都**未能定位**（DX / EXPERT，本地谱库没有）。
  - 不过 **Credits 那段的谱面本身就写在屏幕上**，照录其中三行（`{16}`@179BPM，OCR 原文已按屏幕重排，句读可能有出入）：
    ```
    {16}1,,8,1,,1,,8,1,,8,1,,1,,8,
    {16}1,,8,1,,1,,8,1,,1,,1,,1,,
    {16}1,,8,1,,1,,8,1,,1,,2<7[1:8],,,,
    ```
    只用 1、8 两个键（顶部两侧，左右各一只手），但**两只手的落点在 16 分格上是不规则错开的**——这正是"两手节奏不同"的最小实现。

  ### agent 理解
  - **它是"踩音层"的配置，不是"摆位层"的配置**：003 的四因素讲的是同一条踩音下怎么把配置写难；混 fr 反过来——**踩音本身就是两条**，一手一条。按 002，官方谱的常态是"鼓当骨架 + 非鼓填充"，两条线通常落在同一批时间点上；混 fr 是**故意让两条线的网格不同**（4 分 vs 8 分、直拍 vs 三连）。
  - **和 027 定拍的区别（重要）**：定拍里固定手只是**节拍器/伴奏**，不承担独立的踩音线；混 fr 的两只手**各自都在踩一条真实存在的音轨**。形状上可能长得很像（一手密一手疏），但**设计意图与踩音归属不同**——定拍是"把节奏交给一只手"，混 fr 是"把两条音轨分给两只手"。（agent 推断，存疑）
  - **为什么吃协调**：两手的周期不可约（4 分 vs 8 分还好，真正难的是 3:2、3:4 这种），大脑没法把两手合并成一条脉冲来数，必须分开维持。这与 038 绕手"手的分配要不停重算"是不同的难度来源。
  - **写谱时的红线**：混 fr 段里两手各自的密度都不高，但**合并后的瞬时密度会出现不规则尖峰**——核对 015 的速度红线时必须按**合并后的时间轴**算，不能按单手算。另外两条线一旦在同一 slot 撞上就成了双押，**撞点的落位要主动设计**（对照 030 的侧边双押铁律）。
  - **词源未知**：「fr」出自哪里教程没说，社区也没有统一写法（`corrections.md` 确认"混fr"是 UP 主原文、不是错字）。**不猜**。
