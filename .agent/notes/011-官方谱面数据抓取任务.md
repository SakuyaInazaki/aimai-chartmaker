## 用户追加的两条规则（重要）

1. **只要 ST 谱**：用户指出"有一些ST谱后续会追加DX谱，还有一些是先出的DX谱后续追加的ST谱。但是无论如何我只要ST谱"。最终过滤条件 = `song.type == "standard"` **且** chart.touch ∈ {None, 0}（双保险，排除含 touch 的 DX 谱）。已验证：432 个候选全部满足双条件，无 DX 混入。
2. **截断谱面补 E**：用户指示"不完整的没E的那你加个E不就好了"。22 个站点数据截断（原文无 E、以逗号结尾）的谱面已补 `E` 收下，清单见 `resource/official-chart/_patched_E.log`（本机）。⚠️ 注意：这些谱面的站点原文在**内容上也可能不完整**（如 火炎地獄 MAS 原文止于 1b/8b,），补 E 只保证语法可解析，不保证谱面内容完整——后续用作训练/参考数据时需知悉。

## 技术要点备忘

1. **数据源机制**：站点为 SPA；`/data/manifest.json` 含全量歌曲+谱面元数据（1563 歌 / 6390 谱），谱面数据在 `/data/charts/{chart_uuid}.txt`（纯 simai 正文，无 `&` meta 头）。
2. **谱面タイプ ST** = 站点 JS 中 `song.type == "standard"`（standard→"ST"、deluxe→"DX"）；同一首歌可能同时存在 standard 与 deluxe 两个条目（如 火炎地獄 999/1000），ST 谱记录 touch 字段为 None/0。
3. **`has_chart_data=false` 的谱面**：请求返回 SPA HTML 兜底页（200）而非数据——该标记可靠，脚本据此跳过并记录。
4. **文件名 id**：采用站点 manifest 自带的 `simai_id`（数字编号，全部候选非空）；曲名做文件系统非法字符清洗（`/ \ : * ? " < > |` → ＿、空白折叠为半角空格；manifest 中全角空格 U+3000 已折叠）。
5. **踩坑记录**：日志行分隔符 "  <- "（两空格）导致一次重试脚本解析失败（已修复）；manifest 曲名全角空格导致预览镜像 2 个文件失配（已修复）；`_verify.py`/`run.py` 曾把非 MASTER 难度误当 remas 后缀（已修复为显式三分支）。
