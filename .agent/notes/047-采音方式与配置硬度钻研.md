# 047 — 采音方式与配置硬度钻研（难配置落在曲子哪里、那里怎么采音）

- **日期**：2026-09-19
- **来源**：**用户原话**——「针对曲子对应的采音进行钻研，主要是哪里的配置比较难对应的曲子的强度如何，
  它们都是怎么采的音，是采全音、空音还是半采音等等，我希望你去探索。」
  即三问：① 难的配置出现在曲子的哪里（硬度 × 强度 / 段落 / 曲内位置）；
  ② 难配置段落是怎么采音的（全采 / 半采 / 空音 / 加花）；
  ③ 产出"段落类型 × 强度档 → 采音模式 + 配置硬度档"的可引用规律与知识条目草案。
- **关联**：note **032**（388 谱配置扫描，脚本当时未入库——本轮在 `tools/chart_analysis/` 重新实现并入库）、
  note **044**（配对标定 n=160，本轮复用其全部对齐口径与 160 首语料）、
  知识 **003 / 008 / 015 / 017–030**（配置定义与硬度因素，本轮的判据全部以它们为准）、
  知识 **002 / 005 / 031 / 032**（踩音归因、采音要简、密度曲线）；
  报告 `docs/research/sampling-mode-study.md`；数据 `docs/research/data/sampling-mode-summary.csv`。

## 理由

n=160 标定回答的是「**踩哪条轨**」（recall / precision / lift），没有回答「**在那条轨上怎么采**」。
用户这次要的正是后者，并且把它和"配置难度落在哪里"绑在一起问。这两件事之前都没有工具：

- 配置识别只有 note 032 那次的一次性脚本（未入库、判据自认"过宽"）；
- 采音形态（全采/半采/空音）连度量都没有。

所以本轮先补两个模块，再在 160 首上做分析。

## 变更

### 新增文件

- **`tools/chart_analysis/configs.py`**（约 1 000 行）：按知识 017–030 的定义实现逐片段配置识别，
  覆盖 17 类（含 `双押纵` / `侧边双押` 两个 030 的子型）；每个片段给
  `{bar_start, bar_end, config, evidence, n_notes, detail}`，一个片段可命中多个配置。
  另含无理代理检测（知识 009/010/011 的阈值）与**逐小节配置硬度分** `bar_hardness()`：
  `raw = 0.22·K(种类) + 0.22·M(位移) + 0.26·V(速度) + 0.10·U(无理) + 0.20·C(配置)`，
  曲内 min-max 归一 + 曲内三分位分档。
  ⚠️ 所有阈值/权重集中在 `PARAMS` / `CONFIG_WEIGHT`，**明确标注为 agent 的操作化**，不是知识条目原文。
- **`tools/calibration/sampling.py`**：采音模式度量。逐小节相对骨架轨算
  `coverage`（骨架轨的音被踩了多少）/ `extra_ratio`（落不到任何 stem 的音）/
  `alt_pattern`（隔一个 / 只踩强拍 / 分音减半）/ `rest_beats` / `density_ratio`，
  再按阈值落成 `全采 / 半采 / 稀采(空音) / 加花 / 静默 / 混合` 六类；
  含随机平移对照 `shuffled_control()` 与轻量装载 `load_pair()`（不解码混音、不重算强度，
  160 首全量 7 秒）；CLI 子命令 `python -m tools.calibration.sampling song|corpus`。
  ⚠️ 六类的**术语与阈值同样是 agent 的操作化**，报告里已列谱例请用户校正。
- **`tests/test_configs.py`**（57 项）、**`tests/test_sampling.py`**（24 项）：
  全部用自写合成 simai 片段与合成时间序列，每个配置/模式至少一正一负例；
  负例多数就是第一轮实测里抓到的假阳性类型。全库 **339 项全绿**。
- **`docs/research/sampling-mode-study.md`**：中文报告（方法与操作化定义 → 识别精度核对 →
  硬度 vs 强度/段落/位置 → 采音模式分布与交叉表 → 各配置的典型采音与典型段落 →
  8 首个案 → 对照与敏感性 → 可引用规律清单 → **知识条目草案 033/034/035** → 14 条局限）。
- **`docs/research/data/sampling-mode-summary.csv`**（193 行 / 50 KB）：
  逐曲 160 行 + 逐段落 9 行 + 段落×硬度档 24 行，含模式占比、coverage/extra、
  硬度与强度均值、逐曲 ρ(强度,硬度)、17 类配置的小节占比。

### 主要结论（全部写进报告，**未经用户确认**）

1. **配置识别器在知识条目点名的官谱上复现了全部引文**（695 大宇宙 3/3、633 方向盘、
   648 三角 3/3、547 HERA 长纵连、1212 Halcyon 轴交互 2/2）；
   三首人工核对（SPICY SWINGY STYLE / Death Scythe / 幻想のサテライト）抽检 96 段全对，
   但这是**修掉 7 类假阳性之后**的数字（三角把单向音阶/星星链当三角、错位把双手同刻双押当错位、
   散点把星星链当散点、子弹把星星头+同键 tap 当子弹、跳拍把密度变化当跳拍、
   普通交互/纵连把星星串算进去），7 类全部写成了单测负例。
2. **硬度 × 强度**：逐小节 ρ = 0.291（和密度的 0.328 一个量级），**逐段落均值 ρ = 0.641**
   → 强度曲线只配定段落档位，不配定每小节写多难。硬度沿曲内位置**单调爬升**
   （0.424→0.581）而强度 40% 处见顶回落；**最难配置不在音频高潮小节上**（±8 小节内差 0.06）。
3. **★ 难配置段落"踩得更省"**：去掉硬度分里的配置项（破循环论证）后，硬度低→高时
   `半采` 9.6%→18.8%、`稀采/空音` 5.8%→9.0%、`全采` 36.6%→**30.2%**，coverage 0.702→0.673。
   进副歌同样是"配置升级 + 采音变挑"（硬度 +15%、半采 +3.9 pt，coverage 只 +0.011）。
4. **配置的段落分区**：几何配置（方向盘 3.51 / 大宇宙 2.71 / 楼梯 2.58 / 散点 1.96 /
   三角 1.88 / 轴 1.84）属 **ドロップ** 与 **間奏**；双押系（侧边双押 1.51 / 单双双单 1.38 /
   连续双押 1.21 / 错位 1.17）属 **サビ**，而普通交互在サビ被压到 0.60；
   纵连尤其长纵连属 **イントロ**（1.92 / 3.16）。
5. **一手被占住的配置天然半采**（定拍 22.8% / 双押纵 21.6% / 连续双押 15.9%），
   **手型预定的几何配置天然全采或加花**（三角 53.1% 全采、散点 15.5% 加花，半采≈0）。
6. **对照通过**：随机平移各 stem 的 onset 后，`全采` 33.4%→7.2%、`加花` 6.5%→45.8%、
   coverage 0.687→0.422 —— 模式分布不是密度伪影。
7. **最大的盲区**：硬度分量不到"读谱与手型"。散点（知识 025 明说难度来自读谱预判）、
   大宇宙、方向盘去环后都落在中低档，与谱师直觉相反。
