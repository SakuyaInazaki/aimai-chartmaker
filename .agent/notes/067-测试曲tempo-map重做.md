## 结论

1. **BPM = 205.000，全曲恒定，无变速 / 无漂移 / 无拍号切换 / 无 ritardando / 无半倍速段**（置信 高）。
   - **滑窗扫描**（2 与 4 小节窗、步长 1 小节、BPM **100–260 步长 0.05**、与相位无关）：
     4 小节窗 drums 102 个窗，**101 个**最佳 BPM 落在 205±0.3，std **0.085**，全域范围 204.60–205.15；
     2 小节窗 96 个窗全部落在 205±1.0。
   - **主体高精度拟合**（bars 21–124，122 s，步长 0.002）：**205.000，95% 峰宽 204.984–205.016**；
     前半 bars 21–72 与后半 bars 73–124 **独立**拟合给 205.000 / 204.992。
   - **逐小节 8 分相位**（量程 ±73 ms）：中位 +10.0 ms（= 包络峰检测器的固有滞后）、std 4.4 ms、
     **全曲无跳变**；回归斜率 4.71e−6 s/s → BPM_true 204.999。
   - **三路跟踪器**瞬时 BPM 中位：beat-this 205.11 / librosa beat_track 205.09–205.11 / plp 窄先验 204.69。
     无一路出现 ≥1.5 BPM 的持续偏移。
   - `(bpm)` 序列只需开头 `(205)` 一条。

2. **`&first` 维持 1.349 s，半拍备选 1.2027 被否定**（置信 高，比 064 的「中高」升一档）。
   判据是 064 没做的那一步：**只看鼓最干净的段**（build 41–48、最终 drop 起手 105–112），
   用分带 flux 把 kick/hat 与 bass 分开——
   **kick 正拍 6.59 dB vs 反拍 3.08 dB（比 2.14）、hat 4.91 vs 2.85（比 1.73）**，
   kick 是标准的四分四拍（4-on-the-floor）；bass 反过来（2.44 vs 7.45）是本曲的 **offbeat bass**
   曲风特征（106 小节：kick 在 16 分格 0/4/8/12，bass 在 2/6/10/14，严格交错）。
   选 1.2027 会让 kick 与 hat 全落反拍、bass 全落正拍，音乐上是反的。
   旁证：包络自相关在 A 段与最终 drop 给出 1.002 / 1.998 / 3.000 / 4.001 小节的重复周期；
   主体网格外推回第 1 小节线 = 1.349 s，正落在乐曲硬切入点 1.3478 s。

3. **205 是四分音符（拍），不是 8 分线**。倍/半速得分表（410 > 205 > 102.5）只是「格子多命中多」的平凡效应，
   不能定拍速；定拍速的是 kick 每 292.7 ms 一下。102.5 是同一张网格的半速读法，
   **note 时刻完全相同**，只影响记谱；本曲写 205 正确（102.5 下同内容要写 `{32}`，撞 `docs/audio-analysis.md` §2.5 红线）。

4. **「全都没对齐，歪得特别奇怪」与 BPM / `&first` 无关，是 Visual Maimai 的分音指令解析**。
   桌面包里的 `chart.json` **是 VM 自己的存档**（VM 导入 maidata.txt 后写的，含 VM 私有字段与 GUID），
   等于拿到了「VM 眼里的我们这份谱」。实测规律：
   > **VM 丢弃「紧跟在 `||` 注释行之后那一行、写在行首」的 `{x}`；行中的 `{x}` 正常生效。**

   **触发条件是 `||`，不是「行首」本身**——主会话核过：官方谱 **414 份里 405 份有行首 `{x}`、
   0 份含 `||`**，用户在 VM 里读官方谱从不出事。我们这份谱**每行都带 `||`**，
   所以两种解释在本文件数据上无法区分，按官方谱的反证成立的是前者。
   - 假设检验：H0「正常解析」与 VM 的 128 个注释位置只吻合 **3/128**；
     H1「`||` 之后那行的行首 `{x}` 被吞」吻合 **128/128**，模拟总长 108.500 小节 = VM 实测值；
     note 位置 636 个也完全重合。
   - 后果：m004–m058 我们写 `{8}` 被按 `{16}` 走（**每小节只占半小节**）；m059 行中那个 `{8}` 被认下，
     于是 m060 起我们写的 `{16}` 被按 `{8}` 走（**长度翻倍**）；128 小节被读成 **108.5** 小节。
     第 4 小节之后每个 note 都错，且**错法忽大忽小**——正是「歪得特别奇怪」。
   - **谱面自身没有问题**：只读解析 maidata 的 128 个小节，分音累计**每个都精确等于 1.0**，
     小节起点与 205 理论值逐条相差 0.00 ms。
   - **修法**：**交付版去掉全部 `||` 注释，保持官方格式，行首 `{x}` 照写**（官方谱 405/414 就是这个写法）。
     注释可以留在工作副本里，只是导出给 VM / 玩家的那一份不能带。
     复验办法：让 VM 重新导入保存，看 `chart.json` 的 note 位置与总长是否 = 128.0 小节。

5. **对 064 §2.3 的两处修正**（本轮的主要方法论收获）：
   - (a) **「8 小节块 + 32 分网格（搜索半径 ±17 ms）相位回归」有两个盲点**：
     ① 对**离散整格错位**完全不敏感——半拍 146 ms、16 分 73 ms、32 分 36.6 ms 在 32 分格里都混叠成 0；
     ② 测不出 >0.4% 的 BPM 误差——一块（9.37 s）之内相位就绕过一整格了。
     064 里「bars 73–80 +13.8 ms / bars 105–112 +15.0 ms 偏大」正是绕圈的痕迹；
     本轮把量程换成 8 分（±73 ms）后，这两块的相位是 +8.6…+10.3 / +9.9…+12.9 ms，**平的**。
     → **漂移检测应以「无相位的滑窗 BPM 扫描」为主，相位回归只作辅助，且量程不得小于 8 分。**
   - (b) **064「无鼓段单独验证 → 全曲同一个网格」这条结论作废**。它用的是全混 onset 列表，
     而本轮实测该列表在混响 pad / 低通渐弱段上**比随机还差**（到最近 16 分线 |中位| 19.1 ms，
     随机基线 9.1 ms；落 ±12 ms 只有 33%，随机 65.6%）——一个音符会触发 5–10 次包络涟漪。
     用带内 flux 重测，**前奏 1.3–24 s 只有 27 个真 attack，尾奏更少**，
     onset-fit 曲线是平的（前五名峰差不到 8%）。
     → **前奏与尾奏的速度「测不了」，只能靠结构外推**（主体网格外推回去正落在硬切入点）。
     尾奏逐 2 小节窗的 204.8→190→220 序列是**先降后升**，不是 ritardando 的形状，是检测失效。

6. **顺带核查（都不是问题）**：桌面包 `track.mp3` 与仓库里**逐字节相同**（MD5 1aca253c…）；
   该 mp3 带 Xing/Info 帧、容器 `start_time = 25.06 ms`，但 **ffmpeg 与 afconvert（CoreAudio）两套独立解码器
   结果逐样本一致**（长度 7 141 376、首个非零样本 10 491、互相关 lag = 0），`&first = 1.349` 通用。
   残余风险：若 VM 的解码器不读 Xing 帧，音乐会整体晚 25.06 ms（≈1/3 个 16 分）——那是**均匀**偏移，
   与本次「忽大忽小」的症状不符，排在第 4 条之后。

## ⛔ 第三次更正：下拍相位（整体早一拍）

起因：参考谱（DX Master 抄谱）的内部网格与我们逐拍相同，但它折到我们音频上的 `&first`
在 0.14–0.16 s，我们是 0.4279 s——**差一拍**。

⚠️ **口径（用户当场修正）**：参考谱的背景音乐与我们的并没有对齐，
**那份抄谱相对它自己的 ogg 未必对准，`&first=0` 不可信**。
所以它的「切入 = bar 2 第 1 拍」**只是候选假设，不作证据、不作兜底**。
下面的裁定**完全建立在我们自己音频的证据上**。

**裁定：改为早一拍。新 `&first = 0.1352 s`，205 段起点 24.4709 s，总小节 131 不变。**
整张 map 刚性前移一个 **205 拍**（0.29263 s，不是 195 拍的 0.30769 s——
因为 205 段的拍网格实测到 ±10 ms 且覆盖 104/131 小节，精度远高于采参考谱值的前奏；
两种锚法差 15 ms）。各段 BPM 与小节数一个没动。

### 支持（五路，全部来自我们自己的音频）

1. **beat_this 下拍**：mix n=74 到 P1 小节线中位 **124 ms / ±40ms 32%**（P0 367 ms / 4%）；

### 反方两路，都被判为不可信

### 我这次又错在哪

**在「有 4-on-the-floor kick」的段落上数 backbeat，然后因为比值 ≈1.00 就判「分不开」，
转而去信两条分辨率不够的间接判据。** 正确姿势是先找一段**只有军鼓/拍手**的音乐
