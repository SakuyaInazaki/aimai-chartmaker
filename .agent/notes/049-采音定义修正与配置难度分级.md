# 049 — 采音定义修正（纯音乐事件）与配置难度分级 × 强度对应表

- **日期**：2026-09-19
- **来源**：**用户原话（两条，对 note 047 那一轮的批评）**——
  ① 「采音肯定是根据音乐来踩的啊，不能光根据 bpm 来。」
  ② 「你就不能稍微确定一下什么样的配置比较密比较难，适合放在强度高的地方；什么样的配置比较简单适合放在强度低的地方吗？」

  `configs.py` 之后以它为基础重写）——本轮照做的部分是**把配置检测器做成可替换的注入点**，
  配置分级表仍用现有键位版 `configs.py` 跑，报告里逐处标注"待手序版重跑"。
- **关联**：note **047**（第一轮采音钻研，本轮修订其判据）、note **044**（n=160 配对标定，复用全部对齐口径与语料）、
  note **043**（分轨细化，`melody`/basic-pitch 灌水的教训，本轮据此把有音高 note 默认关闭）；
  知识 **003 / 015 / 017–030**（配置定义与难度因素）、**002 / 005 / 031 / 032**（踩音归因与密度曲线）；
  报告 `docs/research/config-difficulty-intensity.md`、`docs/research/sampling-mode-study.md`（顶部已加修订说明，只增不删）；

## 理由

note 047 那一轮把「半采」判成了三条判据的或：①被踩中的 pool 下标等差为 2（"隔一个"）、
②官方槽全落在 0.5 拍整数倍上（"只踩强拍"）、③谱面最细分音 = 音频量化分音的一半（"分音减半"）。
**这三条全是拍网格/分音判据，与"音乐里哪个音更重"无关**——用户的第一条批评正中要害。
同时那一轮只给了"硬度 × 采音"的交叉表，没有回答"哪些配置密/难、该放哪里"这个可直接用于创作的问题
（用户第二条批评）。

## 变更

### 修改 `tools/calibration/sampling.py`（536 → 696 行）

- **删除** `_alt_check()` 与 `alt_pattern` / `alt_reason` 字段，`bar_metrics()` / `song_sampling()` /
  `load_pair()` 的 `chart_div` / `audio_div` 参数一并去掉——**整条采音判定链上不再存在任何分音 / BPM / 网格量**
  （`sec_per_beat` 只剩把 `rest_beats` 换算成拍这一个单位用途）。
- **新增** `accent_pick()`：唯一的新半采判据「挑重音」。两条任一成立——
  ①**重音优先**：命中事件的平均 onset 强度 − 未命中事件的平均 onset 强度 **严格大于** `accent_margin`（默认 0，打平不算）；
  ②**分位单调**：pool 按强度切 3 个等频桶，各桶命中率不下降且最高桶严格高于最低桶。
  两侧有效事件各少于 2 个 → `证据不足`。返回 `(是否挑重音, 理由, 均强差)`，均强差进 `BarSampling.accent_delta`。
- **新增** `_unique_with_strength()`：pool 去重时**簇内取强度最大的那个事件**（60 ms 内的一串 onset 谱面上只对应一个音）。
- **模式从六类改八类**：`全采 / 近全采 / 半采 / 随机半采 / 稀采·空音 / 加花 / 静默 / 混合`（`MODE_ORDER`）。
  新增阈值 `near_full_lo=0.65`（近全采下界）、`sparse_min_pool=4`（稀采要求音乐真的在响）、
  `accent_margin` / `accent_bins` / `accent_min_side`。
- **目标音轨三口径**：`skeleton_mode` 新增 `melodic`（只在 `MELODIC_STEMS = other/piano/vocals` 里按 lift 选），
  `load_pair()` 相应多返回 `melodic_default`（段落级 melodic 骨架）。
- **强度进管线**：`load_pair()` 读 onset 缓存里的 `<轨>__str`；无缓存时现场算（`detect_onsets().strengths`）；
  `shuffled_control()` 平移时**强度跟着 onset 一起搬**（否则对照不可比）。
- **新增可选开关** `load_pair(..., pitch_conf=0.6)`：把 `stems_htdemucs_6s/pitch_notes.json` 里置信度 ≥ 阈值的
  basic-pitch note 并进对应 melodic 轨。**默认关闭**——40 首实测并池后 melodic 口径 coverage 0.619→0.567、
  稀采 9.4%→15.1%、挑重音通过率 65.0%→59.5%，正是 note 043 说的候选池灌水。

### 新增 `tools/chart_analysis/config_profiles.py`（701 行）+ CLI

配置难度分级与强度对应表。**检测器可替换**是首要设计约束（为 `hands.py` 手序版留口）：
`bar_config_table()` 接受 `bar_configs`（一张 `{小节: {配置名}}` 表）/ `hits`（任何带 `config`/`bar_start`/`bar_end`
的对象或字典）/ `detector`（`fn(res, slots) -> hits`）三种注入，**都不传才回落 `configs.detect_all`**；
`chart_profile()` / `aggregate_by_config()` / `lift_table()` / `recommend_matrix()` / `placement_by_config()`
全部只吃这张表，不碰 `configs.py` 内部函数。

内容：逐小节**内在难度画像**（note/小节、时间槽、NPS、最细分音与分音占比、each/slide/hold/break/touch 占比、
相邻槽键位位移均值、等效速度、无理代理计数、**去掉配置项重新归一的硬度**）；
`intrinsic_score()` 给复合分 `(D+H)/2`（D = NPS ÷ 22.2 知识 015 红线，H = 去环硬度）；
`placement_by_config()` 给外在放置（强度分位/lift/位置/coverage/各采音模式占比）；
`cooccurrence()` 给同 ±1 小节共现前 3；`recommend_matrix()` 给「事件密度 × 强度档」矩阵（lift 榜 + 出现率榜两份）。

CLI：`python -m tools.chart_analysis.config_profiles --bars-json <逐小节配对 JSON> --csv ... --json ...`。

## 主要结论（详见报告）

1. 新判据下模式分布：`全采 33.4% / 近全采 19.3% / 半采 15.3% / 随机半采 7.8% / 稀采 5.9% / 加花 6.5% / 静默 5.4% / 混合 6.4%`。
   第一轮 33.7% 的 `混合` 被拆开——19.3 pt 其实是 `近全采`。
2. **「挑重音」是真的但幅度小**：半采区通过率 66.1% vs 随机平移对照 58.3%（曲内配对 t=6.40，96/130 曲为正）。
3. **硬度 × 模式核心表在新判据下完全复现**（去环硬度低→高：全采 36.6%→30.3%、半采 11.9%→18.9%、coverage 0.702→0.673）；
   **但新增一条否定结论**：半采里"挑重音"的比例不随硬度上升（65.4% → 66.3%），
   所以不能说"难的地方谱师更讲究踩重音"。
4. **「密」与「难」是两个正交旋钮**（本轮最有用的一条）：密 D（NPS）预测"出现在多高定数的谱里"（ρ=+0.80），
   难 H（note 种类/位移/无理）预测"放在曲内多强的位置"（与高强度富集 ρ=+0.58）；交叉项分别只有 −0.15 与 −0.03。
5. 矩阵里最有用的三格：**密 × 高强度 → 方向盘 4.52× / 散点 2.98× / 三角 2.91×，采音 `半采` 24%**；
   **稀 × 高强度 → 侧边双押 1.50×，coverage 0.760 全矩阵最高**；**中 × 低强度 → 长纵连 2.43×**。
6. 矛盾案例六条，最突出的是**散点**（内在难度第 5 却被放在低强度，低强度 lift 1.14）与
   **侧边双押**（内在倒数第 4、平均定数全表最低 13.61，却是副歌 lift 最高的配置 1.51）。
