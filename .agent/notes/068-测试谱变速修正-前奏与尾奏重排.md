### 1.2 🔧 修掉的真 bug：`play.py::_measure_locator` 在小节中途换速时算错小节线

原写法用 `note.time − beat_in_measure × 60/note.bpm` 反推小节起点——
**这假设一小节内 BPM 恒定**。实测同一小节内不同 note 反推出的起点最大分歧：

```
1789-咲キ誇レ常世ノ華 m013   619.5 ms      1212-Halcyon m008   300.1 ms
235-天ノ弱 m051              22.0 ms      243-sweet little sister m079   6.2 ms
```

**改法**：`simai_parser` 解析时就把小节线记下来——新增
`ParseResult.measure_starts: dict[小节号, 秒]`，逐槽推进时**在槽内线性插值**出小节线
（`(bpm)` 只能出现在逗号之间 ⇒ 一个槽内 BPM 恒定 ⇒ 插值是精确的）。
`play.py` 优先用它，旧写法只留作兜底。
验证：四首里**所有落在小节第 0 拍上的 note，时间与 `measure_starts` 完全相等**（0 处不符）。

⚠️ **这条对本轮特别要紧**：重排后的前奏每小节（甚至每半小节）都换速，
不修的话手序层报的小节号会整段指错。

### 1.3 两条只记不修

1. **`(bpm)` 不重启小节相位**。`docs/simai-error-checking.md` §8.3 记 MiaCode「任何 `(BPM)`
   指令即使数值不变也重启小节相位」，而我们的 `simai_parser` 按累计拍位定小节
   （`measure = beat // 4`）。但官方谱**大量在小节中途写 `(bpm)`**
   （咲キ誇レ m013 一小节换四次），如果真按"重启"算，那一小节会被切成四个 1 拍小节——
   显然不是这个意思。**存疑，不动**；本轮的做法是**能放在小节线上就放在小节线上**，
   半小节换速时另行确认。
2. **`calibration/sampling.py:620` 的 `t0 + 4×60/bpm`** 假设一小节内 BPM 恒定。
   标定链不在交付路径上，本轮不动。

## 3. 新工具：`tools/chart_analysis/tempo_remap.py`（变速重排的写与校验）

人手摆 `(bpm)` 摆错一格，听感上就是整段偏。所以把两件事做成可复跑的：

```bash
# ① 把 tempo map 的 (bpm) 序列插进正文（正文一行一小节、不带 (bpm)）
python3 -m tools.chart_analysis.tempo_remap emit \
    --tempo out/test-01/tempo_map.json --body body.txt --out body_with_bpm.txt

# ② 校验：逐小节起点秒 vs tempo map 的秒表，**误差必须为 0**
python3 -m tools.chart_analysis.tempo_remap verify \
    --tempo out/test-01/tempo_map.json --maidata samples/test-01/maidata.txt
```

- **两种 tempo map 写法都收**：`bars[{bar, bpm, start_sec}]` 或
  `segments[{start_bar, end_bar, bpm}]`；`bar` 一律 **1 起**；
  **半小节换速**写成 `{"bar": 12, "beat": 2.0, "bpm": 165}`。
  `start_sec` 有就当**校验基准**，没有就按 BPM 自己累。
- **`emit` 的锚点取"上一个逗号之后"**，所以 `(bpm)` 落在 `{x}` **前面** → `(bpm){x}`
  （`docs/simai-syntax.md` §6 禁 `{x}(bpm)`）；正文里原有的 `(bpm)` 先剥干净、不叠加；
  tempo map 要在一个**正文里不存在的格**上换速时**直接报错**，不静默取近似。
- **`verify` 用 §1.2 新加的 `measure_starts`**（精确小节线），加上 `&first` 换成音频绝对秒，
  逐小节比对；同时查 `&first` 与小节总数。小节数按**有 note 的最大小节号**算，
  不把"最后一小节之后的那条小节线"算成一小节。
- 冒烟（含小节中途换速）：`(120)` 一小节 → `(240)` 半小节 → `(60)` 半小节 → `(120)` 一小节，
  emit → verify 回路 **误差 0.000000 ms**；现役定速谱 verify 也是 **0**。
- 单测 `tests/test_tempo_remap.py` **10 条**：含「写错 BPM 必须被抓」「`&first` 不一致必须被抓」
  「换速点没有对应格必须报错」三条**反例**。

## 5. tempo map 拿到手之后：工具侧又补了三处

1. **`load_tempo_map` 认了真实 schema**（`tempo_map v1`）：`first_sec` / `bpm_at_bar_start` /
   `start_beat_in_bar` 三个键名；**换速点只从 `segments[]` 取**（半小节换速只写在那里），
   `bars[]` 只提供 `start_sec`（校验基准）与小节数。
2. **`emit` 的插入锚点要跳过 `||` 注释**。原来只跳空白，结果 `(bpm)` 卡在**上一行的注释前面**
   （`…,2,1,,      (185)||m009`）——时间上没错（仍在下一小节第一个 note 之前），
   但落在了错误的行上，去注释之后更难看。改成连 `||…` 整段一起跳，
   于是稳定落在**下一行行首**、`{x}` 之前 → 官方写法 `(bpm){x}`。
3. **`verify` 分成两个口径**：
   - 对 **按 BPM 累算**的值（与谱面同一套 BPM）→ **必须精确为 0**；
   - 对 tempo map 的**秒表**（`bars[].start_sec`，只写到小数点后 4 位）→ 容差 0.2 ms，
     只覆盖那一列的四舍五入。本轮实测：累算 **0.000000 ms**、秒表 **0.0615 ms**。
   另外「谱面比 tempo map **短**」改成提示不是错误——尾奏留白、`E` 提前收是正常的；
   只有「谱面比 map 长」才报错。

**还修了一处会误导的**：`chart_check` 采音层新增**网格漂移检测**——
谱面小节线与 `song_analysis.json` 的 `bars[].start_sec` 差超过 50 ms 就**跳过本层并说明原因**。
本轮正中：analysis 还是旧网格（`first=1.349` / 恒定 205），与新谱差 >1 s，
不跳的话会报出一串假的「该有音却整段留白」。
