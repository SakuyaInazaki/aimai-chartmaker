## 理由

note 050 建的手序模型，其代价项有相当一部分**没有用户侧依据**，只能靠社区教程（知识 006/007）
和 388 官谱的间接校准撑着——`docs/hand-sequencing.md` §7-9 自己也写明「除 `t_hit_min` / `t_hard_*`
有官谱数据锚点外，其余权重全是 agent 设定」。本轮用户一次性把其中六个关键口径讲清楚了，
**必须先入库再改模型**（AGENT.md 准则 8：稳定认知立即沉淀，不得留在对话里）。

入库按 AGENT.md **准则 9「引文即边界」**执行：每条目的「详情」先放原话对应句子的**逐字引文**，
再分开写「主会话解读」与「对手序模型的含义」；凡超出原话的形式化、阈值、机检规则，
一律标 `agent 解读/操作化，待用户确认`，并在 `hand-alignment-user-2026-09-19.md` §4 汇总成疑问清单。

## 变更

### 新增知识条目（四条，置信度均为**确信（用户谱师讲授）**）

- **064 — 手序：舒适区与出张**：左手 = 左半屏 8765 + 上方 1 + 下方 4；右手 = 右半屏 1234 + 8 + 5；
  **共享区 {1,4,5,8}**，**只有右手拍 6/7、左手拍 2/3 才算出张**；轻易不要写出张，写了要判断
  「容易游玩 / 故意难点」，**就算是难点也要做好引导**。→ 分页先验从「二分」改「带共享区的三分」。
- **065 — 手序：星星头与星星条可分属两手**：A 拍头可 A 划条也可 B 划条，**没有严格规定**，且用户未给偏好。
  → 知识 007 的「末尾半边」与一笔画「一手拍一手划」降级为社区经验/打分项。
- **066 — 写谱不以特殊处理的手法为导向**：同时处理/狗刨是**手法**，使用手法更好打 ≠ 可以据此塞难配置。
  → `docs/hand-sequencing.md` §7-1「一手吃两个对象默认不开」由用户背书，理由从「实测前不得放宽红线」升级为规划期口径。
- **067 — 手序：段首先出手 = 离上一段结束近的手**：上一个配置把手带到了这里；新配置起始键放在
  上一配置结尾键**附近**也可以。→ 段边界不重置手状态，起手由上一段末状态决定。

### 既有条目追加补充（原文一字未改）

- **019 纵连**：新增「补充（用户讲授：短纵连可单手）」——**长度 ≤3 个 tap 的纵连即使稍快也可单手处理**，
  拆手判据**长度优先于速度**；记录疑问「稍快的上界未给」。
- **030 连续双押**：新增「补充（用户讲授：「突然」与「引导」的定义）」——
  **突然** = ① 与谱面临近位置位移较大 ② 与上一个配置间隔过小；
  **引导** = A 双押带过来 / B `18/87/76/65/54` / C `18/23/45/67`；
  铁律据此读作「**禁止突然的**侧边双押」而非「禁止侧边双押」（B 含 7/6、C 含 2/3 与 6/7，用户明说可以写）。
- **006 分页**：补用户的舒适区版本（共享 1/4/5/8，取消 023 的「深度 1」档），指向 064；原二分保留为粗粒度版本。
- **007 末尾半边 / 一笔画**：标注为**社区经验/打分项、不是硬规则**，被 065 覆盖；
  并作废其下游口径「出张 = 与末尾半边冲突的根数」，改用 064 的键位定义。
- **042 狗刨 / 060 同起点拍滑（同时处理）**：按 066 标明手法不得作为「可以写更难配置」的依据。
- **043 出张**：边界改以 064 的用户定义为准（教程「左手打右边」只是按中线二分的粗口径）。
- **054 换手 / 062 鼓动段**：「拍头手＝划轨手」只是常见打法而非硬规则（065）；
  验证报告 §9 里「062 与 007 冲突需用户裁定」一项在用户口径下解决（两条都不是硬规则）。
- `.agent/knowledge/README.md` 索引：新增 064–067 四行，并在 006/007/019/030/042/043/054/060/062 行内标注本次修订。
