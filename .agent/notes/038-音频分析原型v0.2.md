### 重写的模块

- **`quantize.py`（整体重写）**：拍同步 1/48 拍重采样 → **每小节只选一个 div**（四轨共用）
  → 容差 `τ(d)=clamp(0.25·slot_ms(d),12,30)` → 三连判别（`rms12≤τ(12) ∧ rms12≤0.7·rms16`）

## 实跑结果（三首曲子，复用 v0.1 的 stems 缓存，`--level 13.5`）

| 曲目 | 段数 | 高潮小节（v0.1 → v0.2） | 分音分布（v0.2） | unquantized |
|------|------|------------------------|-----------------|-------------|
| TransientTears | 12 | 78 → **55** | `{8}`7% / `{16}`93%（真被解释 20/92） | 13.1% |
| チモシー健康ジャズ | 9 | 53 → **24** | `{16}`100%（真被解释 27/74） | 6.9% |
| 金魚鉢からの脱走 | 9 | 38 → **50** | `{4}`5% / `{8}`4% / `{16}`92%（真被解释 11/85） | 18.6% |

热跑总耗时 20.5–22.5 s，RTF 0.15–0.16（all-in-one 推理占 86%）。

**A 项（量化）**：`{32}` 与 `{24}` 从输出里彻底消失（v0.1 里 bass/other/vocals 各有
24–44 个小节被判 `{32}`，全是噪声）；红线分别拦下 21 / 9 / 16 个小节；三连门一次都没开
（符合"音游曲以二分为主"的先验）。v0.1 报的 `unresolved_bars = 0` 被证实是**容差过宽
造成的假象**（25 ms > `{32}` 格距的一半 19.5 ms，任何 onset 都能被"解释"），
v0.2 把它换成了可检验的 7–19% 未落格率。代价是 `{16}` 变成压倒性多数——
div 由四条 stem 的 onset 并集决定（每小节中位 15–22 个 onset），非鼓轨的 onset 定位误差
15–33 ms，一个离群点就把整小节顶到上限。

**C 项根因（已定位并实证）**：**不是平滑改变了电平，而是做了两次不同的归一。**
v0.1 的 `bar_raw` 未归一，`bar_intensity` 是"平滑后再做一次 min-max"的值；画图时
raw 画成 `bar_raw/max`（下界留在 `min/max`），smoothed 画成拉满 `[0,1]` 的那条，
偏离量恰好是 `min/max`，在低强度段最大。用 v0.1 的代码路径原样复算，
チモシー健康ジャズ **34–48 小节 mean(raw_plot − smoothed_plot) = +0.256**（逐条 0.17–0.51），
与主会话报的 0.2–0.3 精确吻合；TransientTears 全曲均值只有 +0.001（曲线本来贴顶，
`min/max` 小）——这解释了为什么只有一首曲子暴露该 bug。
修法：归一只做一次（先鲁棒 min-max 到 `[0,1]`，再平滑，平滑后不再归一）。修完三首的
`mean(smoothed − raw)` 是 −0.0005 / −0.0018 / +0.0030，チモシー 34–48 变成 −0.016。
已加回归测试 `test_smoothing_does_not_shift_level`（同时把 v0.1 的错误做法写成反例断言）。

**D 项（结构标签）**：TransientTears 的 `chorus 13–16（4 小节）` 与
`pre_chorus/build 17–40（24 小节）` 双双消失——该曲 vocals stem 只占 1.4% 能量，
被正确判为**器乐向**，改用 `ドロップ(drop)` 能量票，得到
`イントロ 1–4 / 間奏 5–16 / Aメロ 17–56 / ドロップ 57–68 / … / アウトロ 99–100`。
チモシー健康ジャズ 新派生出 `Bメロ(pre_chorus) 45–48`（位于 ドロップ 前 4 小节、
强度单调上升、kick 密度下降）与两次 ドロップ（第二次 `upgrade`）。
金魚鉢からの脱走（唯一人声曲，voiced 0.64）得到完整的
`サビ #1 / ラスサビ #2（upgrade，repeat_of 33–44）/ 落ちサビ×2（rest）`。

**E 项（切轨）**：三首都有多次切轨、均未触发"整曲单轨"警告；金魚鉢 上是
`hook(intro) → drum(Aメロ) → vocal(サビ/ラスサビ) → drum(間奏) → vocal(落ちサビ)`，
与 MMFC 5.4「副歌全踩人声」一致。

## 理由

1. **主会话验收 v0.1 时列出的五项问题**（A 量化 / B song sheet 表示 / C 强度 bug /
   D 结构标签 / E 切轨建议）是本次返工的直接触发条件，逐条对应上面的改动。
2. **口径统一到调研 v2**：v0.1 实现时依据的是 `docs/audio-analysis.md` v1.0，
   而 v2 已在量化容差、融合权重、标签词表、切轨判据四处修订了 v1 的结论
   （尤其 §2.1 指出 all-in-one 根本没有 `pre_chorus`/`build` 标签，必须由规则派生）。
3. **密度地板来自官方谱实测**：`docs/research/official-chart-density-curves.md` §4.3 实测
   归一密度 p10=0.264、段落尺度最弱段≈0.62，说明"音频强度可以逼近 0，谱面密度不能"，
   §7 建议 4 明确要求把这条非线性补进映射——所以 v0.2 的建议密度是
   `floor + (1−floor)·I` 而不是线性。绝对量级取 §2.4 的 note/小节均值、
   总数区间取知识 004，保证"难度校准来自官方谱、情绪起伏来自音频"。
4. **轨数压到 4 是为了执行知识 005**：v2 §5.2(d) 明确"轨数上限 4，不要把 8 条轨全铺出来
   ——那会诱导 LLM 采密"。v0.1 的 6 轨（含 kick/snare/hat 三条几乎相同的串）正是反面。
5. **所有启发式都带证据与出处**：段落的 `evidence`、切轨的规则编号（MMFC 5.4-N）、
   量化的 `reason` 都写进 JSON 与 md，宁可标"这条只有 1 路证据"，不可让下游把启发式当事实。
