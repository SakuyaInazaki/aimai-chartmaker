## 理由

n=160 那一轮把话说死了：**加曲子这条路走到头了**——从 40 首到 160 首，
密度侧的默认值一个都没再改，人声侧一条都没解决（人声曲 ρ 0.28 vs 器乐 0.42）。
note 043 又证明"人声活动"这个**标量**救不了人声曲，需要的是**乐句/句读边界这一层结构**。
公网 LRC 的逐行时间戳是唯一能低成本拿到"真实乐句边界"的来源，所以先试它。

## 结论（详见报告）

1. **LRC 不是瓶颈，对齐才是。** 109 首人声曲里 **97 首（89.0%）**找到带时间轴歌词
   （lrclib 51 / netease 46）；VOCALOID 曲 100% 命中，POPS＆アニメ / ゲーム＆バラエティ 最差（0.73）。
2. **对齐被跨曲阴性对照判死。** 把别的曲子的 LRC 喂给同一个对齐器，得分几乎一样：
   真 LRC 二项 z 中位 **5.74** / 外来 **5.15**，真>外来只占 **56.7%**；
   250 对随机配对 **36.8% 过门槛**；奇偶折半一致率真 **0.05** / 假 0.01。
   四种口径（VAD 互相关 / onset 命中 z / RMS 对比度 / 小节格点受限扫描）**全都分不开**。
   根因：游戏版 `track.mp3` 是剪辑版（**LRC 末行比游戏版结尾晚 70.1 s，59/97 判为有剪接**），
   而音频侧唯一的锚 Demucs `vocals` 轨太脏（VAD 活动占比中位 0.674）。
   ⚠️ **"对齐成功 67/97"是假数字，不得引用。**
3. **唯一能区分真假 LRC 的是"节拍一致性"**（行首落在小节格的 `n·R²`，真 7.51 / 外来 0.52，
   真>外来 86.6%）——它只能证明"这份 LRC 属于这首歌"，**不含偏移在哪里的信息**。
4. **LRC 口径的 T1–T4 在配对外来 LRC 对照下全线归零**：T1 句头 lift 配对差
   **+0.017 ± 0.021（t = 0.80）**；T3 音节密度 ρ 真 0.023 / 外来 0.023；T4 同。
   唯一"显著"的 T2b（句前留白，t = −3.73）**被分层检查证伪为伪影**
   （对齐置信度最低那档最强 t = −3.00，最高那档消失 t = −1.25）。
5. **免对齐口径（纯音频句读 × 160 首官方谱）给出真正的答案**：
   - **note 级别没有句头效应**：句头 ±半拍 lift 中位 **1.021**（人声曲），显著率只有 **10%**；
   - **换气留白也没有**：留白内 lift 中位 **0.992**；
   - **小节级别有一个小而真的增量**：句读特征相对**同自由度的环形平移假特征**，
     人声曲 R² **+0.036 ± 0.008（t = 4.60、Wilcoxon p = 4.7e-4、符号检验 66/109）**，
     **器乐曲无（t = 1.87、p = 0.61）**——阴性对照通过；
     ⚠️ **中位增量只有 +0.005，收益集中在少数曲子**；
   - **句读不是第二条强度曲线**：ρ(句首数, 密度) 中位 **−0.045**、ρ(留白, 密度) −0.056，
     对比 ρ(强度, 密度) **0.278**。
6. **探测器的 F1 没有分母**：对真 LRC 边界 F1(±1拍) 0.217、对外来 LRC 0.196 ——
   两者差距在噪声内，只说明 GT 不可用。探测器的有效性**只有**第 5 条的小节级证据支持。
7. **知识 002 不动**：本轮验的是句读，不是踩音；"副歌全踩人声待人工听审"维持原状。
