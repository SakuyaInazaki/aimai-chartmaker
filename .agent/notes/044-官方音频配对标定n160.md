## 理由

n=40 那一轮留下三类问题，都只能靠扩样回答：

1. **n=40 的结论本身是不是又一次小样本运气？** n=8 → n=40 时逐小节 ρ 从 0.454 掉到 0.226，
   有过一次"掉一半"的前科；n=40 换掉了默认权重、改了三个阈值，这些决定值不值得信，
   需要四倍样本复核。
2. **n=40 的分层结论全部建立在音频侧代理上**（人声/器乐用 `share_vocals`，曲风只是顺带一提）。
   新 120 首是按官方曲风分层选的，**`&genre` 是硬标签**，第一次有条件做真正的曲风分层。
3. **n=40 自己给出的判断是"下一轮最该补的不是更多曲子，是更好的人声 ground truth"**
   —— 这个判断需要被证实或证伪：如果加 120 首之后密度侧数字全都不动、人声侧一条都没解决，
   那它就是对的。

## 结论要点

### 一、**这一轮一个默认值都没改** —— 这是最重要的结论

| 项 | n=160 的裁定 |
|---|---|
| 强度融合权重 `[0,0.19,0.07,0,0.74]` | **不再换**：LOSO 160 折对照现役默认 **−0.0015 / 82 折胜（51.3%）/ p = 0.81**，三条判据全不过。对照 v0.3 初值仍全过（+0.0617 / 124 折 / p ≈ 0）→ **n=40 那次替换被四倍样本确认正确** |
| `share_vocals ≥ 0.14` | **不动**：1401 段扫出的 Youden 最优是 **0.1424**，与 n=40 的 0.142 撞在小数点后三位 |
| `INTRO_OUTRO_CAP_RATIO = 0.75` | **确认**：155 个 intro 段的实际密度比中位 0.784 |
| `BAR_DENSITY_FLOOR = 0.25` | **确认**：池化最优 0.340，默认只差 0.53% SSE |
| `SECTION_DENSITY_FLOOR = 0.60` | **不动**（388 谱大样本优先），但 SSE 代价从 3.7% 涨到 **9.5%**，记录用常数改 0.330 |

### 二、被 n=160 下修 / 推翻的 n=40 结论

1. **「器乐曲 ρ 是人声曲 2.7 倍」下修为 1.49 倍**（器乐 0.4196 / 人声 0.2823，51 vs 109 首）。
   报告 §2.2 做了 2×2 分解：n=40 的 2.73× 被"平滑口径"与"v0.3 权重"双重放大
   （同 40 首、同 v0.3 权重、不平滑口径就只剩 1.81×）。
   → **「强度管线对人声曲几乎不管用」这句话要撤回**，正确说法是"差三成"。
2. **R7「锚点应按 BPM 选」撤回**：NPS 锚在 160 首上于**每一个** BPM 档与定数档持平或占优
   （全样本 MAPE 12.46% vs 15.52%）。n=40 那条建立在 180–199 档只有 8 首的 5.1% 上。
3. **三条"全表最高"措辞被推翻**：`other` 最强的是 `intro`(0.359) 不是 `pre_chorus`(0.318)；
   `interlude` 的 vocals precision(0.561) 不再是第一；`quiet_chorus` 的 drums recall(0.682)
   略低于 `chorus`(0.692)。
4. **R12（`outro` 规则 8）从"存疑"升级为"确认的缺陷"**：32 段上仍输常数基线 9.4 pt。
5. **「整条融合式仍低于 flux 单项」推翻**：n=160 上已追平（0.3665 vs 0.3686，中位反而更高）。
6. 结尾形态 57.5/2.5/40.0 是小样本偏差：**n=160 是 65.6/1.9/32.5，与 387 谱的 65.1/1.0/33.9
   逐档误差 < 1 个百分点**（全部指标里互证最强的一条）。

### 三、被 n=160 证实的

- 同权重口径逐小节 ρ **0.2959（n=40）→ 0.2999（n=160）**，四倍样本纹丝不动；
- 切轨归因第三次全部复现（drums recall 0.650 / 不落鼓 33.7% / 什么都不落 16.0% /
  候选池 0.840 / 0.549 / 骨架模型 84.7% vs 常数 84.1%）；
- **C3（intro 判据换成 onset 匹配倾向）赢常数基线 +7.7 pt，与 n=40 完全一致**；
- **「副歌全踩人声」第三次被否**（14.3% → 4.5% → **2.7%**），
  但**「人声作为重音点缀」的信号变强**（28% → **36.4%**）；
- **`piano` 是六路分离里唯一确认的净增益轨**：160 首 recall **0.289**（高于 `other` 与 `vocals`）、
  precision 0.606、lift **2.44**（与 40 首那轮完全一致）；
- 峰位误差中位 18 小节（与 n=40 一模一样）、边界命中 ±1 0.50 / ±2 0.67（三轮同量级）。

### 四、n=40 那条"下一轮该补人声 ground truth"被完全证实

加 120 首之后，**密度侧的数字（ρ、权重、地板、锚点、归因、结尾）全部稳住、一个默认值都没改**；
**人声侧一条都没解决**，而且代理判据的失败模式更严重了 ——
器乐曲《疾走あんさんぶる》的 vocals 轨拿到 **recall 0.579（160 首最高）**，
比 n=40 的《超絶！Superlative》(0.339) 还离谱；160 首里 vocals 天花板 ≥ 0.7 的 12 首中
**4 首是器乐曲**。**「再加曲子」这条路已经走到头。**

### 五、本轮踩到的两个坑（n=40 时没暴露）

1. **`&wholebpm` 不等于谱面正文的 `(BPM)`**（3/160 首）。《ウッーウッーウマウマ(ﾟ∀ﾟ)》的
   `&wholebpm=164` 而正文是 `164.73`，按 164 跑会让 66 个小节只有 6 个对得上（对齐误差 434 ms）。
   → **前处理一律改取谱面正文的 `(BPM)`。**
2. **候选池有效率的 φ 补偿口径错了**：候选池是锚在用户 `&first` 上的网格，与官方 note
   本来同一个时钟，不该再叠 φ\* 解码延迟补偿。n=40 时最大 |φ\*| 只有 25 ms、被 30 ms 容差盖住；
   n=160 里《L4TS2018》（φ\* = −37.5 ms）的候选池 recall 被压到 0.003 才暴露。
   → **已修 + 加单测**；修正后 pool recall 0.8328 → 0.8396。
