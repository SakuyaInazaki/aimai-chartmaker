# 052 — 谱面级「定数 × BPM × 配置」对照（撤回 (D+H)/2 内在难度排序）

- **日期**：2026-09-19
- **来源**：**用户裁定（原话）**——上一轮（note 049）`docs/research/config-difficulty-intensity.md` §2.2
  给每类配置算了一个合成的「内在难度分 (D+H)/2」并排出 1–17 名，用户质问「谁让你这么排的？」，随后给出判据：

  > 「大体上肯定是按照每张谱的定数和它对应的 bpm 和它的配置这样对照着来看的啊，
  > 没有说一定要有什么什么配置，一个谱也不可能把所有的配置都放进去。」

  即：难度只能从**「每张谱的定数 × BPM × 它实际用了哪些配置、怎么组合」对照着看**；
  不给配置打合成分、不预设某类配置必须出现——配置是谱师按曲子挑着用的。
- **关联**：note **049**（本轮撤回其 §2.2/§3，复用其 `config_profiles.bar_config_table()` 注入接口）、
  note **047**（第一轮采音/硬度钻研）、note **032**（官方谱踩音归因）；
  知识 **003**（BPM 是放大器 / 低 BPM ≠ 简单）、**004**（定数 note 总数分布）、**015**（速度与密度红线）、
  **017–030**（本轮进统计的 14 条配置定义）、**031**（官方谱密度曲线）；
  报告 `docs/research/chart-config-matrix.md`，数据 `docs/research/data/chart-config-matrix.csv`，
  代码 `tools/chart_analysis/chart_matrix.py`，单测 `tests/test_chart_matrix.py`。

## 理由

note 049 那一轮的错在**口径层**，不在算术层：它把「密 D」（NPS ÷ 22.2 红线）与「难 H」（去环硬度）
平均成一个标量，再拿这个标量给 17 类配置排座次，等于默认
「配置本身有一个脱离具体谱面的难度值，且可以线性合成」。
用户的裁定否掉了这个前提——**难度是"这张谱的定数 + 这首曲的 BPM + 它实际怎么用配置"三者对照出来的**，
配置只是被挑着用的素材，不是打分对象；而且**一张谱本来就只会用到全部配置里的一小撮**，
按配置排座次会诱导出"缺了某某配置"这种伪问题。

所以本轮的交付换成**谱面级对照**：每张谱摊成一行，按定数档 × BPM 档分格，
只报"这一格的谱长什么样、换一格又变成什么样"，全程不合成任何难度分。

### 新增 `tools/chart_analysis/chart_matrix.py`（约 900 行）+ CLI

**一谱一行**（`ChartRow` / `chart_row()`）：定数与定数档、主 BPM 与 BPM 档、变速多段、
有 note 小节数与时长、note 总数 / 时间槽数 / NPS、each/slide/hold/break/touch 占比、分音占比与主分音、
**每类配置的小节占比与片段数**、配置词汇量与主料集。

口径上的三个要点：

1. **主 BPM = 占时最长的那一段**（按 `(BPM)` 事件切段、按占时合并同值段）；变速谱在 CSV 里记全部段。
   388 谱里 26 张变速，其中 `916-ってゐ！`（184 段）、`917-東方妖々夢`（311 段）是渐变速谱、最长段只占 3–4%，
   为此另算**占时加权中位 BPM**（`weighted_median_bpm()`）交叉验证——**388/388 两种口径同档**。
2. **出现率与小节占比分开报**：出现率 = 这一格里多少比例的谱**用过**它；
   小节占比中位 = **只在用了它的谱里**取中位。这正是为了落实用户那句"没有说一定要有什么什么配置"——
   "没用某配置"不是缺陷，不能被平均成 0 拉低占比。
3. **另加「每分钟片段数」**（`seg_per_min`）：小节占比会被小节粒度放大
   （<140 档每小节 1.89 秒 vs ≥200 档 1.14 秒），跨 BPM 档比较时**两个口径同向才当结论**。

分析函数：`grid()`（定数档 × BPM 档分格 + 行列边际）、`heatmap()`、
`trend_by_level()` / `trend_by_bpm()`（控另一维的加权 Spearman，支持 `rate` / `share` / `seg_per_min` 三口径）、
`vocab_stats()`（词汇量分布与偏相关）、`pair_stats()`（共存/互斥的 lift 与 φ，`min_share` 可切到主料口径）、
`habitat()`（每类配置的住址格与主料/点缀角色）、`config_sequence()`（个案的逐小节配置序列，折叠连续同配置段）。

**检测器可替换**（沿用 note 049 建的接口，是本模块的首要约束）：
"这一小节命中了哪些配置"一律经 `config_profiles.bar_config_table()` 取得，
本模块**不直接调用 `configs.py` 的任何检测函数**。因为命中只经"小节表"这一层，
**片段数被重新定义为"连续小节段数"**而不是检测器内部的 `ConfigHit` 条数，换检测器时这个口径也不变。
等 `hands.py` 手序版落地、`configs.py` 按手重写后，整份报告换一条命令即可原样重跑。

CLI：`python -m tools.chart_analysis.chart_matrix --csv ... --json ... [--case <谱名> ...]`。

## 主要结论（详见报告）

分格样本量：定数档 51 / 127 / 98 / 61 / 51，BPM 档 61 / 128 / 125 / 74；20 格里 18 格 n≥8
（薄格 13.9–14.1 × <140 = 3、14.2–14.5 × <140 = 7，不据其下结论）。定数与主 BPM 基本独立（ρ=+0.159）。

1. **定数升档 = 加种类 + 加时长，不换配方**。词汇量中位 8→9→10→12→12（ρ=+0.46，控 BPM 后 +0.45）；
   17 类里 15 类出现率随定数上升，**只有侧边双押真正反着走**（ρ=−0.090，4 个 BPM 档一致为负）。
   多出来的主要是几何配置：轴交互 14%→61%、大宇宙 16%→67%、散点 10%→53%、三角 39%→86%、楼梯 33%→75%。
   **重要否定**：each 占比 59%→49%、slide 占比 15%→11% 都随定数**下降**——升定数靠密度（NPS 5.26→7.79）
   与细分音（{16} 占比 9%→52%），不是多押多星星。
2. **BPM 不是配置种类的旋钮，是分音与块长的旋钮**。控定数后词汇量 ρ 只剩 +0.07；
   17 类里没有一类出现率 |ρ|>0.21。变的是 {8} 占比 19%→61% / {16} 占比 32%→5%（全表随 BPM 变化最大的量），
   以及片段切得更勤（子弹 +70%、连续双押 +63%、普通交互 +70% 段/分钟，5 个定数档全正）而每段更短。
   **"高 BPM 应避开几何配置"这条不成立**（三角 41%→68%、楼梯 41%→57%、大宇宙 31%→41%，方向都是升）。
3. **低 BPM 谱靠错位撑密度**（知识 003 第 4 条的谱面侧证据）：错位在 <140 档占 **38.5% 时长**、
   ≥200 档只剩 **12.2%**（ρ=−0.413，5 个定数档全负，全表最强的 BPM 趋势）；跳拍同向（22.4%→7.7%）。
   机制 = 星星启动按拍计时（知识 014），低 BPM 窗口长、塞得进错位音。
4. **一张谱 = 六件套当底色 + 5 类主料 + 5 类点缀**。词汇量中位 10（四分位 8–12，全距 2–15），
   主料（占 ≥10% 小节）中位只有 5；**没有一张谱用满全部配置**——数据侧印证用户「一个谱也不可能把所有的配置都放进去」。
   底色六件套（子弹/连续双押/错位/普通交互/跳拍/单双双单）在 18 个有效格里**全部**出现率 ≥50%；
   几何配置即使在峰值格也只占 2–6% 小节，**方向盘的主料率是全表唯一的 0%**。
5. **互斥只在主料口径下成立**：按"整张谱出现过"的松口径，17 类里没有任何一对互斥（最小 lift 0.88）；
   换成主料口径后最接近互斥的是 **三角交互 × 侧边双押 lift 0.28**（63 vs 65 张里只有 3 张同为主料），
   次之侧边双押 × 散点 0.37。最强共存是几何四人组内部（大宇宙 × 楼梯 3.43、三角 × 楼梯 3.23、三角 × 散点 3.08）。
6. **个案十张**（每个定数档一高一低 BPM）：`1701-しねばいいのに` / `851-フキゲンワルツ` /
   `454-FestivaLight` / `825-セハガガガンバッちゃう！！` / `1482-スリップフリップ` / `432-Doll Judgment` /
   `69-Nerverakes` / `1048-初音ミクの消失` / `204-System “Z”` / `379-Contrapasso -paradiso-`。
   最有说服力的一对是 `454-FestivaLight`（13.4 / BPM 125，错位占 47% 小节）与
   `825-セハガガガンバッちゃう！！`（13.3 / BPM 202，错位只占 14%、slide 占比却是前者两倍）。
