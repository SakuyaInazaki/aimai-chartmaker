## 主要决策与理由

1. **目标定数 13.6（显示 `13+`）**。205 BPM 下 `{16}` = 13.67 键/秒，成段 16 分等同 14.3 级谱的量级，
   所以骨架定在 8 分、16 分只做六处 ≤1 小节的爆发（知识 072：BPM 是分音与块长的旋钮）。
   密度按 **NPS 锚**走（知识 031 §7：`note/小节` 锚在 BPM ≥ 200 上系统性高估）——
   终稿 918 note / **NPS 6.13**，与 13.5 档官谱均值 6.13 重合。
2. **段落按人工复核表写，不用管线标签**：前奏是 1–19（不是 1–4 + 5–20 間奏）、
   69–76 与 77–84 必须拆开（后者鼓全退）、61–64 的 `chorus#2 upgrade` 是假切点、
   125 起是アウトロ不是間奏、137–138 是片尾 logo 音效**一个 note 不写**。
3. **ドロップ2 的升级走配置不走密度**（知识 002 / 031 §8）：
   ドロップ1 用连续拍滑（两手交替），ドロップ2 换成**双压连续拍滑**（两手同相位）+
   **错位半小节版** + **整小节 16 分二连扫** + 单双双单满档；密度只 +30%。
4. **205 BPM 写不了完整的海底谭错位**：滑完穿心后同一只手要在 146 ms 内飞回 4 格（≈27 键/秒），
   越过知识 015 的红线；与知识 072 实测一致（≥200 BPM 档错位只剩 12.2% 时长）。
   故主力改用**连续拍滑**（头与启动拍隔一个四分 = 293 ms，两手相位差一拍）。
5. **出张只用知识 091 的两招**（长条钉专属键 2 处 + C 型侧边双押 12 处），
   写完按知识 079 回头量了一次：**22.75 ‰ / 出张·slide 0.2323**，与官谱（21.1 ‰ / 0.232）同量级，
   没有重演 `e2e-trial-02` 第 3 轮写到 43.2 ‰ 的过头（缺口 G14）。

## 本轮暴露的两个工具缺口（记录，未动 `tools/`）

- **G16（新）：`&first ≠ 0` 时采音层整体错位。**
  `tools/chart_analysis/simai_parser` 不施加 `&first`，谱面 note 的时间从 0 起算；
  而 `song_analysis.json` 的 `bars[].start_sec` 是绝对秒（本曲从 1.349 起）。
  两套时钟差一个 offset ⇒ `tools/chart_check` 采音层的 coverage 全曲判 0，
  报出 12 条 `SMP-EMPTY-SECTION` 警告。`e2e-trial-01/02` 那首 `&first = 0`，所以此前没暴露。
  本轮用「把 `start_sec` 统一减去 `&first`」的诊断副本（scratchpad，不入库）重跑，
  采音层才有意义：**0 错误 / 0 警告**。
- **G17（新）：`hands.py` CLI 直接吃 `maidata.txt` 会把 meta 头当谱面。**
  `&title=` / `&lv_5=13＋` 等行里的数字被解析成 `m0000 0.000s` 的 note，
  报出 11 次"同刻 13 个需处理对象"的假多押。只喂 `&inote_5=` 之后的正文即正常（0 无理）。
  `tools.chart_check` 走的是正确路径，不受影响。

两条都**只记录、不修**（本轮任务明令不改 `tools/`）。

## 最没把握的三处（写在 writeup §8，这里只列标题）

1. **`&first` 的半拍归属**——两簇相位差恰好半拍，鼓点本身分不开；
   若整体错半拍改 `&first = 1.2027`，谱面正文不用动。
2. **本曲该有多密**——没有官方谱可比，全靠跨谱分布；
   「NPS 锚在 205 BPM 上准不准」本身没被单独验证过。
3. **前奏 19 小节的写法**——完全无鼓，只能踩 pad 与琶音，而 `melody` 是候选池里最脏的一条；
   写成 4.63 note/小节（官谱 イントロ 中位 6.82），**没有听感支撑**。

另有一条明显的词汇缺口：**12 种 slide 形状只用了 `-` 与 `^` 两种**，
`v V q p qq pp s z w` 与同头星星 `*` 一个没写（见 writeup §8-4/§8-5）。
