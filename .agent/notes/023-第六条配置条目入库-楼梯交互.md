# 023 — 制谱经验记录：第六条配置条目（楼梯交互）

- **日期**：2026-09-10
- **变更**：
  1. 新增知识条目 **022（配置：楼梯交互）**。
  2. 知识库索引更新（022 入库）。
  3. 记录本次 agent 分析方法被纠正之处（见下）。
- **理由**：用户讲授楼梯交互（沿同一方向、每次只移相邻键位；按"走向"分组；走向之间靠另一只手飞过去衔接）后指示记录。

## 记录中的纠正

1. **不拆手分析**：agent 一开始把引文按奇偶位拆成两只手的序列来看，用户指出"首先这是交互，你分手来看感觉怪怪的"——正确做法是**按"走向"分组**（如 ERINNNNNN 的 `1b,8,1,8,...,4,5,4,5,` 是一组走向，`3b,4,...,8,7,8,7` 是另一组）。
2. **接缝处的小跳不是异常**：agent 曾把走向接缝处的非相邻位移（如 LAMIA 5→8 跳 3 格）当作疑似问题去问——实际上**那正是走向之间的正常衔接**（由正常交互顺序下轮到的那只手飞向下一组走向的起始位置）；该疑问已撤回。

## 条目要点备忘

- 定义：沿同一方向、每次只移到相邻键位的交互。
- 结构：走向内成对推进（**成对=交互基本结构，对内的键不要求相邻；"相邻"限制的是位移**）；走向内两种一般写法——**重复两次（较简单）**、**不重复直接走（要求更高）**。
- 衔接：靠轮到的那只手飞向下一走向的起点。
- 走向之间方向自由：同向、反向都可以（无强制反向）。
- 实例：ERINNNNNN!!（185BPM，3 组走向，各 16 音）、LAMIA（199BPM，走向各 8 音）。
- 待补：与之区分的下一配置（用户预告）。

## 入库后的追加纠正（同日）

用户纠正了 agent 在记录中的两处误解，条目已修订（见条目"修订记录"）：

1. **成对不必相邻**：agent 以为"成对"要求两个键相邻（读到 LAMIA 的 `{3,8}`、`{4,7}` 时产生疑问）——错，**对内的键可以不相邻**，"相邻"限制的是**位移**。
2. **成对与重复无关**：agent 把"成对推进"当成"重复的走法"——错，成对是交互的基本结构；重复与否是走向内的写法差异（**重复两次较简单、不重复直接走要求更高**）。
3. 补记：**走向之间没有必须反向的要求**（同向、反向都行）。
