# 062 — 写谱工作流 v0.1：谱面检查器 + song sheet 写谱提示层 + 端到端试写一首

- **日期**：2026-09-20

- **理由**：用户 2026-09-20「**继续去实现与完善认识，别问我**」。此前项目三大组成
  （分析工具 / 制谱经验 / 手序模型）各自都跑得通，但**从来没有被串起来实际写过一张谱**——
  `AGENT.md` 的待办里「工作流指引：拿到 mp3 后的完整操作 SOP」一直空着，验收标准四条
  也没有可执行的核对清单。本轮把三者串成**写谱工作流 v0.1**，并**端到端试写一首**，
  目的是**暴露认识缺口**（不是为了写出好谱）。
  **全程不向用户提问、不设阈值当规则、不造术语、不改知识库条目。**

## 变更

### 一、新增 `tools/chart_check/` — 谱面检查器（验收工具）

一份 `maidata.txt` 进，中文 Markdown 报告 + JSON 出；退出码非零表示有错误。

```
python3 -m tools.chart_check <maidata.txt> [--level 13.5]
    [--analysis song_analysis.json] [--json out.json] [--inote 5] [--quiet]
```

模块：`model.py`（Issue / LayerResult）、`maidata.py`（meta 与正文切分，**保留行号**）、
`syntax.py`、`play.py`、`configlayer.py`、`densitylayer.py`、`samplinglayer.py`、
`excerpt.py`（逐小节原文片段）、`report.py`、`core.py`、`__main__.py`、`_deps.py`、`README.md`。

五层与依据（**一条规则不自造**）：

**两条边界写进报告正文**：① **外部三检待接**——本机没有 SimaiSharp / MajdataEdit / MiaCode，
语法层只是按三方规则交集实现的**内部校验**，不能代替真机跑谱；
② 无理计数依赖 `hands.py` 选出的**一套**手序（知识 065），「绝对无理 0」读作
「**存在一套合法手序**」。

**分级取舍（记一笔）**：**硬级无理记「警告」不记「错误」**。
`hand-sequencing.md` §6.2 要求 `budget.muri`（含硬级）为 0，但知识 077 的 388 谱实测里
硬级不是 0（Hold 尾多押 74 / 超速 24 / 外键 13 / 撞尾 7），本轮官方谱基线也在
ジングルベル 上报出 10 次——**把硬级记成错误等于宣布官谱不合格**。

**官方谱基线（5 首，`tools/chart_check/README.md` 有表）**：
ぽっぴっぽー 13.3 / ダンスロボットダンス 13.3 / コトバ・カラフル 13.7 / 緋色のDance 13.7 /
ジングルベル 14.2 —— **语法 0 错、不可行 0、绝对无理 0 全部成立**；硬级只有
ジングルベル 10 次；出张 12–29 ‰（知识 079 官谱中位 21.1 ‰）；
侧边双押 0–10 次且**八型引导全部判得出**（与知识 082 一致）。

> 跑基线时修掉了两处**自己制造的误报**（官谱一开始被判 14–88 条错误）：
> ① 「连续两个分音标记」原来只看 token 序列，把 `{8}…,{16}` 这种每首官谱都在写的写法全报了
> → 改成**只在文本上真正紧挨着**时才报；
> ② `3<3` / `7>7`（绕一整圈）被当成几何违规 → 官方对 `<`/`>` 无硬限制、官谱写过，**降为提示**。
> 这两条都写进了单测的**负例**。

## 主要发现（详见 `docs/research/e2e-trial-01.md` §3/§4）

1. **最大的差距在 note 种类构成，不在 note 总数**：试写 761 vs 官谱 946，差额 185 个里
   **slide 差 116、hold 差 46、tap 只差 29**。官谱 slide 占 note 的 17.1%、hold 5.3%，
   试写 6.0% / 0.5%。**检查器五层一层都没报出这个维度。**
2. **出张写不出来，只能逼出来**：分配器按代价最小选手序，两只手都够得着时绝不主动跨界。
   把知识 087 §5 的对称模板 `45,,45,,2,3,2` 原样写进去，出张 **0 次**；
   把长条从共享键 `1h`/`8h` 换到**专属键** `3h`/`6h`，出张立刻出现。
3. **段落 lift（知识 074）是分布不是处方**：这一首的 イントロ 与 間奏 官谱写的都是**星星族**，
   与 074 的「纵连族 / 几何集中地」整段相反。管线的 `rest ✅` 字段更危险——
   43–68 被标成「落ちサビ + rest」，官谱那里写到 **11.1 note/小节**（跟副歌一样密）。
4. **「采音」在写谱端没有抓手**：试写 79% 的小节被判成「全踩」（官谱 44%），
   副歌 coverage 0.90 vs 官谱 0.48 —— 我实际在做的是**按分音铺匀拍**。
   知识 068 第 8 条自己写着「真正要设计的是舍音时舍哪一半」，本轮把它变成了可复现的失败。
5. **检查器拦不住「写得太浅」**：终稿 0 错误 0 警告，手序难度只有官谱的 41%、
   软级蹭 0 次（官谱 22 次：撞尾 20 + 外键 2 —— 官谱是**故意**把 tap 摆在星星尾上的）。

## 边界与局限

- **n=1**：一首曲、一次试写。报告里所有比例性的结论都只能当个案；三条知识草案全部标
  `存疑`、**不入库**。
- **没有真机、没有听审**：终稿没在 SimaiSharp / MajdataEdit / MiaCode 里跑过（本机没装）；
  「0 绝对无理」只说明分配器能找到一套合法手序（知识 065）。
- **没有改任何知识条目**：G1–G8 的修订建议只写在报告 §5，`.agent/knowledge/` 一字未动。
- **采音层是网格候选池口径**（`song_analysis.json` 的 `patterns`），与
  `tools/calibration/sampling.py` 的原始 onset 口径**不可混用**。
