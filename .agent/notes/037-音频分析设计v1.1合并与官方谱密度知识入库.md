## 理由

- 音频分析线在三条支路上各自产出了成果（第二轮调研 / 官方谱密度实测 / 原型实跑），但三者都停在
  "报告"形态：调研报告的 R1–R24 是**建议清单**、密度报告的 §7 是**只提建议不改条目**、
  原型报告的实测结论散在 notes 与 tools README 里。设计文档 `docs/audio-analysis.md` 仍是 v1.0，
  含已被证伪的事实（all-in-one 10 类标签 / ISMIR 2023 / 手写模板 T）。按 AGENT.md 准则 2
  「调研结论必须先落到 docs 再进入实现」与准则 8「稳定认知必须沉淀到 knowledge」，
  需要一次收敛式合并。
- **以实测为准**：调研是推测、实跑是证据。natten 编译坑、madmom NC 权重风险、basic-pitch 可装性、
  包络法 offset 打分这四处，调研预期与实测结论都不一致，文档一律采实测并注明，避免后续
  开发按过时预期做设计。
- **密度实测必须入 knowledge 而不只是留在 docs**：`T_density`、密度地板、"末段最强"这些是
  **谱面设计的稳定认知**（生成谱面时必读），按准则 8 属 knowledge 而非 docs。
- **知识 001 的"渐弱"不擅自改写**：该句是用户讲授内容（MMFC 5.2），准则 9 规定引文即边界，
  即使有 388 谱的反证也只能标存疑、待用户裁决，不能代替用户改写。
