# 016 — 事故记录：子代理中间产物误入库，已重写历史修复

- **日期**：2026-09-10
- **变更**：
  1. 发现音频调研子代理把中间抓取产物（约 600 个文件，含 68MB 二进制权重 `audiosep_ckpt.bin` 与 spleeter/audio-separator 等第三方源码包）留在了工作区根目录的 `.research/` 下，被 `git add -A` 误提交并推送到公开仓库。
  2. 修复：`git reset --soft` 撤销该提交 → 移除 `.research/` 暂存 → 补 `.gitignore`（`.research/` 不入库）→ 重新提交（仅 5 个预期文件）→ `git push --force-with-lease` 重写历史。远程历史中已无大文件。
  3. `.research/` 目录保留在本机磁盘（未删除，如不需要可手动 `rm -rf .research`）。
- **理由**：公开仓库混入 68MB 二进制与大量第三方源码包，违反"仓库轻量+许可证边界"原则（第三方源码虽为 MIT 但不应作为本项目文件入库；权重文件许可不明更不能入库）。
- **来源**：agent 自主发现并修复（事故由 agent 的 `git add -A` 疏漏触发）。
- **关联**：`.gitignore`；笔记 015（同批调研）。

## 教训（供后续 agent 遵守）

1. **子代理任务必须约定产物位置**：只允许把最终报告作为返回值/消息，中间抓取文件一律写 `/tmp` 或工作区外的临时目录；确需落盘的需显式指定路径并自行清理。
2. **提交前核对 `git status`**：`git add -A` 前先看变更清单，异常大文件/未知目录（如 `.research/`）必须先确认再提交。
3. 大文件（>10MB）默认不入库；确需版本化的走 Git LFS 或外部存储。
