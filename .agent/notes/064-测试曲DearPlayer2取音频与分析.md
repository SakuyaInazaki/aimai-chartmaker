## 取材途径

全程**匿名公开接口**，没有读浏览器 cookie、没有绕验证码，与 note 046 同一套：
`x/frontend/finger/spi` 拿 `buvid3/buvid4` → `x/web-interface/view` 取元数据 →
`x/player/playurl`（`fnval=4048&fourk=1`）取 dash → `curl` 只下**音频流**。
UA + `Referer` 齐全，请求间隔 >= 1 s，四步全部 `code: 0`。
匿名档位只有 64K / 132K / 192K 三档 AAC，无 flac / dolby；取了 id 最大的 192K 档。

## 结论

1. **BPM = 205.000，恒定，全曲无变速无漂移**（置信 高）。
   onset-fit 网格扫描在 100–250 区间给 205.00 得分 0.3847，第二名（非谐波）只有 0.196；
   细扫步长 0.01 时峰**恰好落在 205.000**。半速 102.5 明显更差（0.233），
   加倍 410 是平凡加倍（8 分线被当拍线）。all-in-one 独立报 102 BPM，是同一族的半速读法。
   **漂移**：8 小节一块、32 分网格的相位回归给斜率 **+3.87e-5 s/s**（门槛 2e-4），
   反推 BPM_true 204.992；13 块里 11 块相位落在 +-7 ms。无鼓的前奏 / breakdown / 尾段
   单独测相位也只有 +3.0 / -3.6 / +8.4 ms。

2. **`&first` = 1.349 s**（置信：拍相位 高；半拍归属 中高）。
   乐曲本体在 **1.3478 s** 硬切入（之前是数字静音，是剪辑点），all-in-one 的第一个 downbeat
   报 1.35 s，细分辨率鼓击对格的中位残差 kick +3.6 ms / snare -2.2 ms，
   项目自己的 `check_offset` 报 phi* = -9.9 ms（判「一致」、z=3.11、单峰无反拍歧义）。
   **半拍歧义如实写出**：拍内相位直方图有两簇、间隔恰好半拍（0.1463 s），
   本轮按「强度更高 + 乐曲切入点 + all-in-one downbeat」三条判给 1.349；
   **备选 1.2027**（写谱时若发现整体错半拍就换）。

3. **首尾各有一段非乐曲的片头 / 片尾音效，且是同一个动机**。
   0.238–1.25 s 与 160.364–161.82 s 两段：谱心 1268 vs 1343 Hz、谱峰集合几乎重合、
   chroma 首位都是 A#，而乐曲本体开头的 chroma 是 E/F#/G#/A —— 调性无关。
   **按要求没有裁剪**，但写谱时这两段不能踩。
   另外 ~146.5 s 起是**低通 + 渐弱**的尾巴（谱心 4500 -> 900 Hz），到 157 s 后基本听不见。

4. **`track.mp3` 与 `track.wav` 逐样本对齐**（互相关最佳 lag = 0 样本，长度相同），
   所以 `&first` 对两者通用；m4a 与 wav 差 33 ms 是 AAC priming 的处理差异，
   **时间轴基准一律取 `track.wav` / `track.mp3`**。

5. **管线段落表在本曲上有 9 处可疑标签**（详见 `out/test-01/analysis-notes.md` §4），
   其中三处会直接误导写谱：
   - **尾奏被标成「間奏」×3**（第 125 小节起鼓已全退、低通渐弱），
     导致 **intro/outro 结构封顶一小节都没生效**（Header 自报「已封顶 0 小节」），
     第 125 小节还在建议 4.3 note；而 §1.5 给間奏的提示是「最敢采空音、几何配置集中地」；
   - **最后两小节（137–138）标成「アウトロ」，其实是片尾 logo 音效**，分析单还给了它 onset 与建议 note；
   - **前奏被腰斩成「イントロ 1–4 + 間奏 5–20」**（1–19 小节 drums stem 低频 -89 dB，完全无鼓；
     all-in-one 自己也判 intro 到 24.46 s），两段拿到的配置族建议互相冲突（纵连族 vs 几何族）。
   其余六处：69–84 把「有鼓减压段」和「真 breakdown」糊成一段；85–104 的连续 build 被切成三段平行「間奏」；
   97–104 的骨架被段内留白拉成 `bass`（实际仍是鼓）；61–64 的 `chorus#2 + upgrade` 切点在一条连续平台中间；
   29–40 被标成 21–28 的重复而实际是「弱底鼓 + hat/bass」段；
   前奏骨架被降级成 `vocal`（全曲 `share_vocals` 只有 0.0146，那是 demucs 泄漏，
   规则 5「間奏有人声采样」在 5–20 与 125–132 也是同一个误报）。

6. **这是一条对既有认识的检验**：段落标签与 `rest` 未经听审这件事 SOP §2 已经写过，
   本曲把它坐实成**三类系统性失效**——(a) 渐弱尾奏被当間奏（结构封顶因此失效）；
   (b) 网格铺到音频末尾，把非乐曲的片头片尾音效也纳入段落；
   (c) 器乐曲的 vocals 轨泄漏会同时触发「骨架降级到 vocal」与「規則 5 人声采样优先踩」两条。
   **本轮不改代码、不改知识库**——只如实记录，是否落实由主会话裁定。

7. **管线量化能力的边界在本曲很突出**：205 BPM 下 `{16}` 槽长 73 ms、`{32}` 36.6 ms，
   实测 **25.9% 的 onset 未落格**、**59 个小节被 `{32}` 红线拦下**、只有 31/132 小节是"真的选中"了分音。
   与 `docs/audio-analysis.md` §2.5.1 的信息论推论一致：**高 BPM 曲的网格串只能当节奏轮廓**。
